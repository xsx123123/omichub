# CygnusX 项目空间测试与验收方案

> 日期：2026-10-24  
> 依据：修订后的 `CygnusX_project_workspace_architecture.md`  
> 类型：待执行测试方案，本文不代表测试已运行或通过。  
> 核心范围：F01 项目身份、F02 默认项目、F03 删除保留；补充相邻功能回归与后续工作包验收。

## 1. 测试目标

本轮重点验证：

1. 项目改名不改变 UUID、稳定 slug 和后续运行归属。
2. 默认项目创建不能绕过 tombstone，删除后的新默认项目能够稳定复用。
3. 科研引用阻止项目删除，返回可解释的业务冲突。
4. 并发请求与异常不会导致部分提交、身份复活或悬空引用。
5. 项目管理修改不破坏文件、目录、权限与归档功能。

测试分为三个层级：

| 层级 | 范围 | 验收含义 |
|---|---|---|
| A：本轮修复 | F01–F03、异常身份、真实 PG/HTTP | 验证身份和删除保留 |
| B：相邻回归 | 文件、目录、上传、ACL、归档 | 验证修改未破坏已有功能 |
| C：后续目标 | F04–F10、持久打包、分页与运行视图 | 后续工作包验收，不视为当前已实现 |

**单元测试通过不能替代真实 PostgreSQL、HTTP 或 Worker 验证。**

## 4. F01：项目身份与运行落盘

### ID-01：改名后的四类生产入口

**前置条件**

用户 A 拥有 P1，已有历史运行及产物。记录项目 UUID、slug、历史路径和文件 SHA-256。

**步骤**

1. 修改项目显示名为 `Renamed`。
2. 分别执行：
   - AgentTeams Case；
   - Studio 产物登记；
   - 普通会话归档；
   - Overdrive 归档。
3. 查询项目、运行来源、目录索引和 overview。

**预期结果**

- UUID 和 slug 不变。
- 新产物仍位于 `projects/original/runs/`。
- 不因改名生成 `projects/renamed/`。
- 执行记录仍关联 P1。
- 历史产物路径与内容不变。
- overview 能看到新增运行目录。

**要求：** 四个入口分别验证，不能仅测试路径工厂。

### ID-02：携带 project_id，但项目不存在

分别使用：

- 不存在的项目 UUID。
- 已删除项目的 UUID。

重点调用 Overdrive 归档路径。

**预期结果**

- 停止项目归档写入，返回明确不可用结果。
- 不按显示名重新推导项目 slug。
- 不创建新 Project。
- 不复活已删除项目目录身份。

如果当前代码仍有名称兜底，记录为缺陷；如果只是文档残留，更新文档并保留回归测试。

### ID-03：跨用户项目

用户 B 使用用户 A 的 P1 UUID 发起运行或归档。

**预期结果**

- 按现有契约拒绝访问。
- 不产生新目录或文件。
- 不返回 A 的项目或产物信息。

### ID-04：历史产物可读性

改名后通过会话、文件和报告入口读取历史产物。

**预期结果**

原有授权下仍可访问，历史 Manifest 和文件内容不被重写。

### ID-05：未绑定名称入口

单独测试 TaskService、生信工具的旧名称参数。

**预期结果**

- 保持明确的兼容行为。
- 不把未绑定入口计入“全部已绑定项目入口已统一”。
- 如果入口实际携带项目身份却仍按名称落盘，记录缺陷。

### ID-06：路径边界

覆盖中文、空格等合法名称，以及已有路径校验中的非法输入。

**预期结果**

显示名与存储身份分离；绝对路径、目录穿越或不安全符号链接不导致越界写入。

## 5. F02：默认项目与身份预留

| ID | 场景 | 预期结果 |
|---|---|---|
| DEF-01 | 首次创建未指定项目的会话 | 创建有效默认身份及目录投影 |
| DEF-02 | 连续创建多个会话 | 复用同一默认项目 |
| DEF-03 | 删除默认项目后创建会话 | 新 UUID、新可用 slug；旧 tombstone 保留 |
| DEF-04 | 替代默认项目建立后再创建 5 次会话 | 复用替代身份，不持续产生 `-3/-4` |
| DEF-05 | 替代默认项目再次删除 | 不复用任何被保留的旧 slug |
| DEF-06 | 两个 PG 事务同时获取默认项目 | 收敛至同一有效身份，无未处理唯一冲突 |
| DEF-07 | 显式创建与默认创建竞争 | owner 锁和唯一约束行为一致 |
| DEF-08 | 两用户并发创建同名项目 | 项目、会话与目录不串用户 |
| DEF-09 | 预留身份后外层会话事务失败 | 不被 helper 提前 commit |
| DEF-10 | 后缀 slug 已被占用或 tombstone 保留 | 跳过占用值，后续复用稳定 |

另需核对：

**默认项目被改名后，系统如何识别默认身份？**

应先明确当前契约，再验证是继续复用还是创建新默认项目。不能在测试中暗自假定存在专用默认标志。

对于数据库回滚后残留的物理目录，应验证其符合明确的补偿或对账规则，不能宣称数据库与文件系统共同原子提交。

**共同预期**

- DELETE 返回 409。

### 6.2 其他删除场景

| ID | 场景 | 预期结果 |
|---|---|---|
| DEL-01 | 删除无阻断引用的项目 | 204；删除项目和根索引；保留 tombstone 与物理文件 |
| DEL-02 | 多类引用同时存在 | 完整返回对应阻断信息 |
| DEL-03 | 用户 B 删除 A 项目 | 拒绝且无副作用，不泄露引用计数 |
| DEL-04 | 重复删除 | 符合既有 API 语义，不产生重复身份或 500 |
| DEL-05 | 删除后执行磁盘同步 | 不重新导入 tombstone slug |
| DEL-06 | 非保留引用类数据库异常 | 不误转换为科研引用冲突 |
| DEL-07 | 删除过程注入失败 | Project、tombstone、根索引无部分提交 |
| DEL-08 | 存在会话等字符串引用 | 记录当前行为及 F08 缺口 |
| DEL-09 | 子目录和 FileRecord 保留 | 不误删文件，侧入口行为可解释 |

### 6.3 PostgreSQL 并发验证

使用独立连接与事务，通过 barrier 或明确同步点控制调度。不要通过随意 `sleep` 猜测竞争窗口。

#### PG-DEL-01：预检查后新增引用

1. T1 完成无引用预检查，在删除前暂停。
2. T2 尝试新增合法科研引用。
3. 根据实际锁行为安排两个事务继续执行。
4. 验证提交结果。

允许的正确结果：

- 引用先提交，项目删除被阻止。
- 项目先删除，后续引用插入被外键拒绝。

禁止的结果：

- 项目已删除，却存在指向该项目的已提交引用。
- 只提交 tombstone 或目录删除等部分状态。

#### PG-DEL-02：FK 兜底与冲突转换

在可控调度下验证：

- 数据库约束确实拦截竞争。
- 异常后先完整回滚。
- 能识别的引用冲突转换成稳定业务错误。
- 无法识别的异常保持正确分类。

如果现有锁机制使某个竞争窗口不可达，应报告实际锁行为，不能伪称已经触发 FK 竞争路径。

#### PG-DEL-03：异常后的连接状态

删除冲突后，在正常新事务执行查询和合法写入。

**预期结果：** 会话不处于失效事务状态。

#### PG-DEL-04：两个请求同时删除

验证重复删除结果符合既有契约，tombstone 唯一，不产生未处理数据库异常。

## 7. 真实 HTTP 验证

必须通过实际 API、认证和中间件执行：

- 创建 → 读取 → 改名 → overview → 删除。
- 空项目删除返回 204。
- 科研引用删除返回 409 和正确错误结构。
- 空 PATCH 按当前文档返回 422。
- 跨用户读取、更新和删除被拒绝。
- list/count 不隐式导入磁盘目录。
- sync-from-disk 跳过 tombstone 和符号链接。
- 默认项目通过真实会话创建入口触发。
- 功能关闭不解除科研引用保留。
- JWT/API Key 按当前权限契约分别验证。
- sync-from-disk 的 JWT 限制得到保留。

服务函数调用成功不能替代这些 HTTP 结论。

## 12. 放行标准

以下任一情况阻断本轮身份与删除修复放行：

- 改名后仍写到新名称目录。
- 有 project_id 但项目缺失时继续按名称写入。
- 默认项目复用 tombstone slug。
- 每个新会话都创建新的替代默认项目。
- 跨用户访问或写入。
- 科研引用存在时删除成功。
- 删除产生部分提交或悬空引用。
- 关闭开关后历史证据失去保护。
- 已识别的引用冲突表现为未处理异常。

真实 PG/HTTP 未完成时，只能声明：

> 代码及隔离回归完成，运行验收待完成。

F04–F10 单独记录实施状态，不因其未完成而否定所有已完成修复，也不能把它们隐藏在“全部通过”中。
