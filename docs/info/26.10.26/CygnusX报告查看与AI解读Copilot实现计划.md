## 一、背景与目标

平台「结果报告中心」当前列表展示的 137 份报告为 **mock 演示数据，非真实报告**（2026-10-26 用户确认）。真实报告由分析流程生成独立的自渲染 HTML 网页报告（BioReport，含项目概述/样本信息/分析概述/质量控制/分析结果/溯源信息/关于等页签），盘面实际存在的真实报告数量远少于 137。因此本计划同时承担一个隐含任务：**报告中心从 mock 数据源切换到真实注册制数据源**（见 Part 3）。

目标能力三层：

1. **P1 报告嵌入查看**：在平台内直接打开网页报告（iframe 嵌入 + 平台外壳 + 鉴权），不从浏览器新标签裸开。
2. **P2 AI 解读对话面板**：看报告时右侧可展开 AI 对话栏，AI 绑定当前报告上下文，可通过只读工具查询该项目的结果数据、解读报告章节。
3. **P3 沙箱高级分析**：AI 可调用平台沙箱执行代码，基于报告结果数据做追问式高级分析（重新绘图、统计检验、自定义筛选），产出注册回项目产物列表，接入平台积分计费。

设计锚点（2026 年业界事实）：

- Power BI Copilot 模式：AI 面板绑定当前报告上下文 + 底层语义模型，是报表消费层的标准形态；
- E2B 类 Firecracker microVM 沙箱：模型执行代码的默认方案，冷启动 150–300ms，会话内状态持续，图表直接返回；
- Agent 沙箱安全硬共识：隔离由执行环境强制，不靠提示词；最小权限、只读挂载、默认禁出网、资源限额是标配。

## 三、总体架构

```javascript
分析流程交付 ──▶ {报告根目录(配置项)}/{reportId}/   ← reportId = <project_id>_<yyyymmdd-hhmmss>
                    │  内含 report.html + report.paths.json(schema 2.1.0) + data/
                    ▼
            交付注册器：解析 JSON 一次（project/platform/files/stats/enrichment）
                    → 写报告注册表（含 user_id 归属）→ 报告中心列表读库
                                                      ↓
报告中心列表 ──预览──▶ 报告查看页（平台路由，如 /reports/:reportId/view）
                          ├─ 顶栏/侧栏：CygnusX 平台外壳（不变）
                          ├─ 主体：iframe ──▶ BioReport 静态 HTML（签名 token 鉴权）
                          └─ 右侧抽屉：AI Copilot 面板
                                │  context: reportId → 注册表元数据 + JSON 摘要注入
                                ├─ 只读工具（P2）：query_project_results / read_report_section
                                │     / list_artifacts（数据源 = JSON 2.1.0 的 files 索引，
                                │     相对路径解析须防 ../ 穿越）
                                └─ 执行工具（P3）：run_sandbox_code
                                      ├─ 只读挂载：{报告根目录}/{reportId} → 容器内 /data（ro）
                                      ├─ 工作区：会话级 /workspace（rw），产出落盘后注册回项目产物
                                      ├─ 限制：禁出网（白名单 PyPI 等）、CPU/内存/wall-clock/输出大小限额
                                      └─ 计费：积分预扣 → 执行 → 实结
```

数据契约已定稿：**report.paths.json schema 2.1.0**（project 区块含 user_id 绑定、
platform 区块含绑定键、files 索引含逐文件 role/description），字段规范以独立文档
《BioReport JSON Schema 2.1.0 更新计划.md》为准。

关键数据前提（P0 施工前核实，见 P0 调查提示词）：

- 报告 HTML 的生成/存储位置现状与访问方式（静态目录？对象存储？现有下载接口怎么走？）；
- 流程交付端生成 report.paths.json 的代码位置（2.1.0 升级落点，见 JSON 更新计划）；
- 现有沙箱的调用入口（已有任务中心/生信工具箱在用？调用契约是什么）、隔离配置（网络/挂载/限额现状）；
- 平台工具集的 MCP 化现状与命名规范（新工具须遵从既有命名）。

## 四、写死的边界（不做的事）

1. AI **不给跨项目数据权限**——所有工具的作用域参数（projectId）由后端从会话上下文注入，禁止模型自行指定其他项目。
2. 沙箱代码**默认只产出到会话工作区**；写入项目正式产物目录需用户在对话中显式确认（前端确认卡片），不允许 AI 静默落盘。
3. **不做 AI 自动修改报告正文**——报告是可溯源产物，AI 只能「追加附录」（追加也走用户确认）。
4. 报告 HTML 不重渲染、不拆进平台组件库——iframe 嵌入是刻意的交付形态，不是技术债。
5. P2 阶段不接沙箱执行——只读问答先跑通上下文注入与工具调用链路，避免两个阶段的问题搅在一起。

## 七、P2：AI 解读对话面板（只读工具，不接沙箱）

目标：查看页右侧抽屉式 AI 面板，绑定当前报告上下文；三个只读工具让 AI 能查项目结果、
读报告章节、列产物文件。本阶段不接代码执行。

前置依赖：交付注册器（Part 3）已上线且 JSON 2.1.0 契约已定稿——注册表元数据 +
report.paths.json 的 files 索引即为 P2 上下文注入与工具的数据源，不再另设落库任务。

### P2 提示词（粘给编码 Agent）

```text
你是一名资深全栈工程师。在 P1 已完成的报告查看页基础上添加 AI 解读对话面板。
先阅读现有代码（[AI 助手模块路径]、[工具注册机制路径]、[P1 查看页组件路径]），
工具注册与命名遵从平台既有规范，禁止另起一套工具机制。

## 功能需求

1. 面板形态：查看页右侧抽屉，默认收起为一个悬浮按钮（位置与风格同平台既有浮层）；
   展开宽度约 400px 可调，展开时 iframe 区域自适应压缩；对话历史按 reportId 持久化。
2. 上下文锚定：打开面板时前端将当前 reportId 传入会话；后端从报告注册表读取元数据
   （project/platform 区块：项目、用户归属、流程类型、样本数、分组、核心指标），
   注入 system context。禁止让模型去读 HTML 原文当主上下文；章节级正文由工具按需提取。
3. 新增只读工具（作用域由后端从会话注入，模型不可指定其他项目/报告）：
   - query_project_results：按 role 从 report.paths.json 2.1.0 的 files 索引定位结果文件
     （如 role=deg_table / enrichment_table），读取并支持 top-N 与按列筛选；
     返回时携带该文件的 description 作为口径说明；
   - read_report_section：按章节名提取报告正文文本（项目概述/样本信息/质量控制/…）；
   - list_artifacts：直接返回 files 索引（path/role/description/format），
     不遍历目录——JSON 索引是唯一数据源。
   三个工具全部只读，返回体积设上限（如单条结果截断并说明截断）；
   **所有从 JSON 读出的相对路径，解析后必须校验仍在该报告目录内，拒绝 ../ 逃逸**。
4. 快捷提问：面板顶部给 3–4 个预置问题（如「这份报告的核心结论是什么」
   「质控有没有异常样本」「按调整 p 值列出 top 20 差异基因」），点击即发送。
5. 回答引用：AI 引用具体章节时，消息内渲染可点击的章节锚点标签；点击后通过
   postMessage 通知 iframe 滚动到对应章节（报告 HTML 需注入一个轻量 listener 脚本，
   注入点在报告模板公共头部，存量报告重新生成或由查看页代理注入）。
6. 空/错态：元数据缺失（老报告未回填）时面板可正常打开，但提示「该报告暂不支持完整
   AI 解读，可回答通用问题」；工具报错向用户展示友好文案，不暴露堆栈。

## 验收标准

- [ ] 打开任一报告查看页 → 展开面板 → 问「这个项目用了几个样本、什么分组」，AI 回答
      与报告页实际内容一致（抽查 3 份不同流程的报告）
- [ ] 「列出 top 20 差异基因」返回真实数据表内容，非编造（与差异分析产物文件核对）
- [ ] 点击回答中的章节锚点，iframe 滚动定位到对应章节
- [ ] 尝试诱导 AI 访问其他项目数据 → 后端拒绝（工具作用域注入生效）
- [ ] 对话历史刷新页面后保留；切换报告后面板上下文随之切换
```

### P2 人工验收（用户手测）

| --- | --- | --- |
| 打开报告 → 问样本/分组/质控 | 与报告内容一致 | 查上下文注入日志，确认元数据落库字段 |

| 老报告（未回填元数据）打开面板 | 降级提示 + 通用问答可用 | 补回填脚本 |

## 八、P3：沙箱高级分析（执行工具）

目标：AI 可在对话中调用平台沙箱执行代码，基于当前项目结果做高级分析；产出注册回项目；

前置确认（P0 第 4 项已给出事实）：若现有沙箱缺以下任一条，先补再开工具——
只读挂载支持、出网限制（默认禁，白名单放行 PyPI/CRAN 等）、CPU/内存/wall-clock 限额、
单会话隔离与销毁。

## Part 3：报告挂载与 JSON 绑定方案（2026-10-26 晚确认，修订 P1/P2 假设）

### 已确认决策

0. **框架先行，目录后定**（2026-10-26 深夜确认）：报告根目录的具体落点是配置项，
不是架构决策。注册器/查看页/AI 工具一律面向「报告根目录（配置项）+ reportId」抽象
开发，根目录位置后续由用户决定，改配置不改代码，P0–P2 可立即开工。
1. **统一挂载与目录命名**：所有报告以 `{报告根目录}/{reportId}/` 挂载，
reportId = `<project_id>_<yyyymmdd-hhmmss>`（时间格式写死，禁冒号）。目录名仅为
人类可读标识；**project_id/task_id 的权威来源是 JSON platform 区块**，目录名只做
一致性校验（不一致告警，不静默猜测）。目录内含 report.html + report.paths.json +
data/ 产物；平台静态服务统一出口 + 签名 token 鉴权。
2. **复用渲染 JSON**：分析流程交付给报告渲染的 `report.paths.json`
（schema_version 2.0.0，已含 stats / input_files / enrichment 逐 contrast 状态与
term_count）作为报告的事实源与绑定载体，**不另起一套元数据格式**。
3. **JSON 追加 platform/project/files 区块**：渲染器忽略未知字段，向后兼容。
**已确认缺口：现有 JSON 无 projectId/taskId/userId，必须补，这是绑定键。**
字段规范已拆出独立文档《BioReport JSON Schema 2.1.0 更新计划.md》，
以该文档为准，本节不再重复定义。
4. **注册制，非扫描制**（对用户原始方案的修正）：平台不扫描目录解析 JSON 渲染列表。
交付瞬间平台解析一次 JSON → 提取绑定键与元数据 → 写数据库报告记录；
报告中心列表读库（筛选/搜索/排序走 SQL），JSON 只在交付注册与 AI 深读时被解析。
理由：IO 线性增长、半成品 JSON 竞态、列表筛选不可行。
5. **JSON = 报告的相对路径索引与 AI 地图**（2026-10-26 深夜确认）：report.paths.json
以 `path_base: "."` + 相对路径索引报告目录内全部结果文件，既是渲染输入，也是 P2
`list_artifacts` / `query_project_results` 工具的数据源——AI 不遍历目录，只读索引。
两条安全/演进规范：
a. **路径穿越防护**：所有从 JSON 读出的相对路径，解析后必须校验仍在该报告目录内，
拒绝 `../` 逃逸（P2 工具与查看页文件服务共同遵守）；
b. **schema 2.1.0 演进（可选增强）**：索引文件条目追加 `role`（如 deg_table /
enrichment_table / qc_stats）与一句话摘要，AI 按语义角色挑文件，省 token 且更准；
渲染器忽略未知字段，向后兼容。
