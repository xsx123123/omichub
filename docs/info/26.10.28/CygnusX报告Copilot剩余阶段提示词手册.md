## R1：迁移预演 + 存量回填执行（运维包，授权环境执行）

```text
你是一名资深后端/运维工程师。reportpaths01 迁移与回填脚本
scripts/backfill_report_paths_registry.py 已实现但未在真实环境执行。
本任务在获得明确授权的目标环境执行，纪律：先备份、先审计、后写库。

## 执行步骤

1. 迁移预演：备份目标数据库；在与生产版本一致的测试 PostgreSQL 上执行
   make check-migrations && make migrate；记录执行耗时、锁等待、新旧报告行数、
   owner 字段与 JSON 列完整性、唯一 head；给出回滚步骤并实测一次 downgrade/upgrade。
2. 存量审计（只读）：用只读数据库连接运行回填脚本审计模式（不带 --apply），
   --reports-root 用真实报告根目录；产出 success/failed/manual 三份清单，
   逐项核对报告 ID、owner、Task 匹配与文件路径；manual/failed 项逐条定位原因，
   禁止将不确定归属自动写入。
3. 正式回填：审计清单经我确认后，在维护窗口带 --apply 执行；执行前后各做一次
   报告行数与关键字段快照对比；留存全部命令、输出与清单到验收证据目录。

## 交付

- 迁移预演报告（耗时/锁/回滚实测证据）；
- 审计三清单 + manual/failed 原因分析；
- 回填前后快照对比；
- 任何一步异常即停止并报告，不自行修复数据。
```

**用户人工把关**：`--apply` 前亲自过目 success/failed/manual 三清单；重点抽查 manual
清单里 owner/Task 反查依据是否可信。

## R2：P1/P2 + 注册链路真实验收（只测不改任务书）

```text
你是一名资深测试工程师。对 CygnusX 报告查看页、Copilot 与 2.1 注册链路做真实环境验收。
T0 纪律：只测不改——只允许新增 tests/ 文件、验证脚本与验收报告；不修改任何业务代码；
发现问题记录证据并分级，不现场修复。

## 环境准入（Step 0，任一项不满足整体标「受阻」并停止，禁止降级绕过）

- 目标环境 HTTPS/反代已就绪；存在至少一份真实 RNA-seq、一份 ATAC-seq 报告
  （R1 回填后）；真实 LLM 模型可用（先报预估调用量与成本，经我批准后用真实模型，
  未批准则在报告标注「未经真实模型验证」）。

## 验收项（每项留证：报告 ID + 操作步骤 + 截图/日志）

1. 注册一致性：报告 HTML 的项目/样本/分组/QC/富集/差异结果 vs 2.1 sidecar 与
   数据库快照逐项比对；文件索引的 role/description/format/路径 vs 真实文件内容。
2. P1 查看页：真实报告完整渲染；未登录/他用户访问预览 URL → 403；构造 ../ 路径 →
   拒绝；退出登录后旧预览会话失效；报告过期/删除后的访问行为；生产代理/HTTPS 下
   iframe CSP 行为。
3. P2 Copilot（真实模型）：样本数/分组/QC/top 20 差异基因回答与文件逐项核对；
   跨项目诱导拒绝；list_artifacts 与 files 索引一致；章节锚点跳转；刷新恢复会话；
   2.0 老报告显示 legacy_degraded 降级标注。
4. 报告中心：列表数量 = 盘面真实注册数；四个统计卡片对账；筛选/搜索/收藏/下载
   在真实数据上正常；生产源码 mock 引用为零（给出扫描命令与输出）。

## 交付

验收报告：通过/失败/受阻三态分类，失败按严重度分级，每条带证据；
不接受「应该没问题」式结论。
```

**用户人工把关**：R2 报告拿回后逐条对证据，未通过项修复后复测，全部通过前不进 R4。

## R3：P3 前置——沙箱能力核实（只查不改）

```text
你是一名资深平台工程师。本任务只做代码级调研，禁止修改任何代码；结论必须标注
文件路径与关键代码位置。目标：为「Copilot 沙箱高级分析工具」开工前核实平台现有
沙箱能力边界。

## 核查清单（逐项给「已具备/部分具备/缺失」+ 证据位置）

1. 调用入口与契约：沙箱现有调用方（任务中心/生信工具箱/AI 助手）、接口签名、
   会话生命周期管理；
2. 挂载能力：能否将「单个报告目录」以只读挂载进容器 /data，挂载根可否限定到
   reportId 粒度而非整盘；
3. 网络策略：默认出网状态？是否支持白名单（仅 PyPI/CRAN）？
4. 资源限额：CPU/内存/wall-clock/输出体积上限是否可配，超限行为；
5. 隔离与销毁：会话间隔离粒度、会话结束后的容器销毁与残留清理；
6. 产物回注册通道：沙箱内生成的文件有无登记回 FileRegistry/项目产物的现成路径；
7. 计费接口：现有积分体系有无「预扣-实结」接口可复用；
8. 确认门：平台有无现成的人工确认卡片/审批交互组件可复用。

## 交付格式

能力矩阵表（核查项 × 现状 × 代码位置）；缺口按「阻断 P3 / 需补齐 / 可延后」分级；
若某项实际已有现成实现，明确指出实现位置，禁止把已有能力报成缺口。
```

**用户人工把关**：R3 报告拿回后发到本对话核对；核对后把 P3 提示词的「前置确认」段
替换为实测结果再投喂 R4——已具备项直接引用代码位置，缺失项作为 P3 阶段 0 先补。

## R4：P3 实现（沙箱高级分析）

使用《CygnusX报告查看与AI解读Copilot实现计划.md》**第八节 P3 提示词**全文，
投喂前完成两处修订：

1. 「前置确认」段落替换为 R3 实测结论（逐项标代码位置）；
2. 若 R3 发现沙箱缺只读挂载/网络策略/限额/隔离中任一项，在提示词开头追加
   「阶段 0：先补齐以下隔离能力并测试强制边界：【按 R3 缺口填写】，完成并验证前
   禁止注册执行工具」。

P3 提示词的核心内容（不变）：权限边界五条（reportId 粒度只读挂载、禁出网白名单、
资源限额、产出保存须用户确认卡片、积分预扣实结）；run_sandbox_code 工具；
e2e 用例含三个越权测试（越路径/出网/写项目目录均被阻断且有后端审计记录）；
产物回注册来源记「AI 沙箱分析」+ 关联对话 ID。
