## 0. 总览

### 0.1 目标

1. 平台获得本地客户端（Tauri 桌面端），经 **mTLS 独立 8443 监听**加密接入后端，
   复用现有 `/api/v1` 全部能力；浏览器 Web 端全程零回归。
2. 平台新增**集群状态页面**：一台服务器一个卡片，展示负载与运行情况
   （Web 端先行，客户端复用同一 API）。
3. 身份体系：**mTLS = 设备准入，JWT = 用户身份**，双层叠加，审计双维度。

### 0.2 已定决策（不再讨论）

- 客户端形态：Tauri（复用现有 Vue 前端构建产物打进壳内）
- 分发范围：小范围分发（自助 enroll + 管理员吊销，更新需签名）
- phylo/searxng 跨服务器在用：端口不回收，改认证 + 白名单
- 浏览器长期共存 → mTLS 走独立 8443，443 不动
- 客户端鉴权：token-in-header（系统钥匙串存 JWT），不复用 Cookie
- 报告预览改造：优先客户端本地代理同源化，后端不加新通道

浏览器 443 口零改动零回归。仓库已有参考范式：
`infrastructure/download/supervisor_server.py:344-395`（CERT_REQUIRED + 证书

### 阶段 2 提示词（paste-ready）

```text
你是资深后端/安全工程师，实施"mTLS 设备准入层"。约束：443 浏览器口与现有

feat(mtls): 阶段2。安全改动必须 e2e 证据（命令 + 现象）。

【任务 1：私有 CA】
新增 deploy/pki/（脚本 + README，私钥不入库，.gitignore 兜底）：
1. 离线根 CA（4096 RSA，10 年）+ 在线中间 CA（5 年，仅可签客户端证书）。
2. 设备证书模板：90 天有效期，Subject CN=<device_id>，SAN 可选；
   吊销走 CRL 文件 + devices 表 status 双通道。
3. README 写清：根私钥离线保管流程、中间 CA 部署位置、轮换操作手册。
验收：从零跑一遍脚本得到可用 CA 链；openssl verify 链验证通过；
根私钥文件权限 600 且不在 compose 挂载面内。

【任务 2：nginx 8443 监听】
deploy/docker/nginx/nginx.prod.conf 新增 server 块（不改现有 443 server）：
1. listen 8443 ssl；ssl_client_certificate=<中间CA>；ssl_verify_client on；
   ssl_crl 挂载；TLS1.2/1.3 与现有对齐。
2. location /api/ 透传：X-Client-Verify=$ssl_client_verify、
   X-Client-Fingerprint=$ssl_client_fingerprint、X-Client-Subject=$ssl_client_s_dn；
   proxy_pass 与 443 同一 upstream。
3. compose 暴露 8443（生产 0.0.0.0；如叠加组网可后续再收窄）。
验收：无证书 curl https://<host>:8443/api/v1/health 握手失败；
持有效设备证书同请求 200；443 口行为不变。

【任务 3：ClientCert 中间件】
新增 src/cygnusx/middleware/client_cert.py：
1. 只对经 8443 进入的请求生效（按 X-Client-Verify 头存在性 + 可信来源判定，
   注意该头只允许 nginx 注入——直接访问后端 8000 必须忽略这些头）。
2. 指纹查 devices 表：status != active → 403 DEVICE_REVOKED；
   cert_not_after 过期 → 403 DEVICE_CERT_EXPIRED；
   未注册指纹 → 403 DEVICE_UNKNOWN。
3. 通过则注入 request.state.device_id；更新 devices.last_seen_at（节流，每分钟最多一次）。
4. 中间件顺序：ClientCert 在 Auth(Bearer) 之前；两层各自独立拒绝。
验收：注册设备 + JWT → 通；吊销后 5s 内 → 403；未挂 Authorization 但证书有效 →
仍被 Auth 层拒（双身份缺一不可）；伪造 X-Client-* 头直连后端 → 被拒或忽略。

【任务 4：enroll / renew / revoke API】
扩展阶段 1 的 devices API：
1. POST /api/v1/devices/enroll（JWT 必需，可选 2FA 挑战）：入参 CSR + 设备名 +
   platform；服务端用中间 CA 签发，返回证书 PEM + 链 + not_after；
   私钥仅客户端持有，服务端永不接触。
2. POST /api/v1/devices/{id}/renew：到期前 30 天内可续（JWT + 当前设备证书双证明）。
3. DELETE /api/v1/devices/{id}：吊销 → status=revoked + 写 CRL；管理员可吊销任意设备。
4. bootstrap 端点（阶段 1 任务 4）填入真实 mtls_host/port/ca_pem/ca_fingerprint。
验收：完整生命周期 e2e（enroll → 连 8443 成功 → revoke → 5s 内 403 →
重新 enroll 新证书 → 恢复）；renew 后旧指纹失效。

【任务 5：审计扩展】
audit_logs 增加 device_id、cert_fingerprint、client_version 三列（Alembic 迁移）；
middleware/audit.py 从 request.state 写入。
验收：8443 发起的写操作审计记录含设备维度；443 发起的记录三列为 NULL 不报错。

【任务 6：443 回归 + 全量回归】
Web 全功能冒烟一遍 + make lint && make type-check && pytest tests/unit
-m "not quarantine" 全绿。
```

## 6. 阶段 3　Tauri 客户端 MVP（1–2 月，比赛季后）

**目标**：Tauri 桌面壳打包现有 Vue 前端，钥匙串存令牌、mTLS 8443 接入、
报告预览本地代理同源化、统一流式重连、首次引导与自动更新。
前置：阶段 1（基址收口/流式鉴权）与阶段 2（mTLS 引导）均已验收。

### 架构决策（已拍板）

- **复用现有 Vue 前端**：frontend 构建产物打进 Tauri；vite `base:'./'` +
  路由改 hash（`createWebHashHistory`，原 history 路由在 Web 构建中保留——
  通过构建模式区分：web build 用 history，client build 用 hash + base './'）。
- **同源方案**：客户端内置 Rust 侧 loopback 代理（127.0.0.1:端口随机），
  前端仍访问"同源"地址，代理统一注入 Authorization 并转发到真实服务器 8443
  （mTLS 在代理出口完成，证书存系统钥匙串）。报告预览 Cookie 问题由此化解——
  预览 iframe 也走同一代理，Cookie 由代理按 token 换取并注入。
- **令牌存储**：系统钥匙串（keyring crate / tauri-plugin-stronghold），
  前端 localStorage 仅存"已登录"标记，不存 token 本体。
