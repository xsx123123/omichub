# 验收证据与S6/S7交接模板

本文保留为后续运行可复用的逐断言填写模板。本轮已经形成实际交接记录：[IAT-R3 / G3-E2 / S6-S7 Handoff](../../../evidence/iat-r3-20261018/handoff.md)，并由 [2026-10-18 验收矩阵](CygnusX_Integration_Test_Matrix_2026-10-18.csv) 汇总。当前有隔离级测试结论，但没有新增真实部署运行或浏览器业务 E2E 通过结论；不得把本模板空字段视为已执行。

## 1. 每次运行基线

- run_id / 时间与时区 / 操作者 / 授权范围：待填
- HEAD / dirty diff hash / 子仓SHA / 依赖锁hash：待填
- environment_id / OS与kernel / 镜像digest / migrations：待填
- 服务拓扑 / 队列及DB身份 / Provider模式 / 初始门禁：待填
- 资源上限、受控源与端口、清理及证据保留计划：待填

## 3. 证据包建议结构

```text
evidence/<run_id>/
  baseline/        # 授权脱敏、版本、配置hash、门禁、拓扑
  runtime/         # 两引擎、Node、Provider脚本摘要、工具与SSE
  browser/         # trace、截图、console、断流/迟到响应
  reliability/     # Broker/ACK/事务/恢复注入时间线
  trusted-http/   # 内核能力、网络计量、quota、cgroup、receipts
  database/        # 隔离DB前后差异与审计
  matrix.jsonl     # 原78项及子断言，实际schema可复用仓库
  report.md        # 由矩阵生成汇总，再补人工结论
  manifest.json    # 路径、大小、hash，原始与脱敏衍生物分开
```

日志及查询脱敏；Token、密码、完整Authorization头不得进入共享证据。原始敏感证据受限保存，脱敏副本记录与原始hash的关系。hash证明文件一致性，不能单独证明证据真实；需关联可信来源和时间线。

S6 当前为 `NOT_READY`，S7 为 `NOT_STARTED`。所有条件满足后，须由独立责任人按明确授权执行S6准入操作。本包不授予该操作，不得手改全局常量放行。具体已完成范围、运行限制、证据路径和清理边界以本轮交接记录为准。

## 5. S6/S7必须交付的同一条执行证据

- 来源发现及证据 → 不可变Prepare摘要 → 人类确认记录。
- task/attempt/execution关联 → policy与范围化认证 → 受信完成/停止证明。
- 实际文件hash与校验 → FileRecord与DatasetVersion → 项目资产。
- 冻结分析manifest → FlowFrame代码/容器/参数/seed与真实产物。
- BioReport引用实际产物 → 结论/图表/数据/运行记录可追溯。
- 跨项目拒绝、重复确认、超期撤销、失败恢复、重复投递与晚到回写反例。

S7失败时记录具体中断点，不能用已生成报告页面替代分析实际成功。需要尚未认证的HTTPS或SRA输入时，新增协议认证为前置条件，不能把HTTP实验认证外推。
