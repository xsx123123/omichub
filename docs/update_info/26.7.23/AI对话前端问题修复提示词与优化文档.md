# AI 对话前端问题修复提示词与优化文档

> 涉及问题：① LLM 已回复但前端不显示正文（空气泡 Bug）；② AI 回复加载动画单一，需要丰富。
> 适用对象：可直接投喂给 AI 编程助手（如 Cursor / Copilot / Claude Code 等）执行，也可作为人工开发的需求文档。

---

# 第一部分：提示词（Prompt）

## 提示词一：修复「已回复但消息正文不显示」Bug

```text
你是一名资深前端工程师。我们的 AI 聊天应用存在一个严重的渲染 Bug，请帮我定位并修复。

【现象描述】
- 用户发送消息后，AI 回复的「消息头」正常渲染（模型名、角色标签、Token 统计如
  "Tokens: 4724 ↑4287 ↓437"、时间戳均正常显示）。
- 「思考过程」折叠面板也正常渲染。
- 但消息的「正文气泡区域」完全空白：LLM 确认已经返回了内容（有 Token 消耗统计），
  页面上却没有任何正文展示。
- 对比正常情况：正常时正文气泡会以 Markdown 渲染标题、段落、表格等内容。

【初步判断】
后端/LLM 链路已确认返回了内容，问题大概率出在前端。请重点排查以下方向：

1. 流式数据接收与拼接
   - SSE / WebSocket 流式响应的 delta 累积逻辑是否有遗漏（如只在流结束后才写入
     content，而 done 事件未触发写入）。
   - 字段名是否匹配：后端返回 content / delta / text / answer 等字段，前端取值
     的字段是否一致；流式与全量两种响应结构的字段路径是否不同。

2. 消息状态机流转
   - 消息 status 从 streaming → done / error 的流转是否正确；
     正文渲染是否被 status 条件（如 v-if="status === 'streaming'"）错误地隐藏。
   - 是否只渲染了 reasoning_content（思考过程）而漏渲染 content（正文）。

3. 渲染层异常吞错
   - Markdown 渲染器 / 代码高亮 / KaTeX 等插件是否在特定内容上抛错，导致整个
     气泡渲染失败且被 try-catch 静默吞掉。请为渲染器加错误边界（Error Boundary），
     渲染失败时降级为纯文本展示，绝不能空白。
   - 内容为空字符串、仅空白字符或 null 时的兜底展示逻辑。

4. 响应式更新失效（如使用 Vue/React）
   - 检查是否直接给响应式对象的嵌套属性赋值导致视图不更新；
     消息列表是否用 index 作为 key 导致复用错乱；
     异步写入后是否缺少强制刷新。

【修复要求】
1. 定位根因并修复，保证「只要后端返回了正文内容，前端就一定展示」。
2. 增加防御性兜底：
   - 正文为空但有 Token 消耗时，显示「回复内容加载异常，点击重试」并提供重试按钮；
   - Markdown 渲染失败时自动降级为纯文本；
   - 增加前端日志上报（消息 id、原始响应、渲染错误堆栈），便于线上排查。
3. 不要破坏现有的思考过程面板、Token 统计、消息操作按钮等功能。
4. 修复后请给出：根因说明、改动点清单、自测验证步骤。

请先阅读相关代码（消息列表组件、气泡组件、流式请求模块、Markdown 渲染组件），
再输出诊断结论和修复代码。
```

## 提示词二：丰富 AI 回复加载动画

```text
你是一名注重体验的前端工程师。我们 AI 聊天应用的「AI 回复中」加载态目前比较单一
（只有骨架屏 + 一句固定文案「星尘正在穿越神经网络…」），请为它设计并实现一套更
丰富的加载动画体系。

【现状】
- AI 气泡内展示：若干条紫色渐变的骨架条 + 底部一个图标和固定文案。
- 场景：用户发送消息后，等待 LLM 首 Token 返回的 loading 阶段。

【优化需求】
请在保持现有视觉风格（浅紫色调、圆角气泡）的前提下，实现以下能力：

1. 多种加载动画组件（至少 3 种，可随机或按场景切换）：
   - 三点呼吸/跳跃动画（typing dots）；
   - 渐变流光骨架屏（shimmer 扫光效果）；
   - 脉冲光环/粒子扩散动画；
   - 打字机光标闪烁效果（配合首 Token 到达前的占位）。

2. 阶段性状态文案轮播：根据等待时长或后端事件动态切换文案，例如：
   - 0~2s：「星尘正在穿越神经网络…」
   - 2~5s：「正在理解你的问题…」
   - 5~10s：「正在检索工作区数据…」
   - >10s：「内容较多，正在努力生成…」
   文案淡入淡出切换，避免生硬跳变。

3. 工程要求：
   - 动画统一封装为组件（如 <AiLoading />），通过 props 控制类型与文案；
   - 使用 CSS 动画优先，注意 will-change / transform 性能，避免引起重排；
   - 尊重 prefers-reduced-motion 设置，用户开启减弱动态时降级为静态提示；
   - 首 Token 到达后 loading 平滑过渡到正文（淡出/高度过渡），不能闪跳；
   - 提供简单的配置项（动画类型、文案列表、切换间隔），方便后续调整。

4. 交付：动画组件代码 + 使用示例 + 各动画的效果说明。

请阅读现有加载态相关代码后给出实现方案与完整代码。
```

# 第二部分：详细优化文档

## 一、问题背景

| 项目 | 说明 |
| --- | --- |
| 产品 | 星尘 AI 对话助手（qwen3.7-max，含代码助手/可视化助手等角色路由） |
| 问题一 | LLM 已生成回复（有 Token 统计与思考过程），但消息正文气泡空白不显示 |
| 问题二 | AI 回复等待阶段的加载动画单一，用户等待感知差 |
| 影响范围 | 所有对话场景；问题一属于阻断性 Bug（用户拿不到回复），问题二属于体验优化 |

## 二、问题一：空正文 Bug 分析

### 2.1 现象复盘

- 消息头正常：模型名 `qwen3.7-max`、角色标签「代码助手」、Token 统计
  `Tokens: 4724 ↑4287 ↓437`、时间戳均渲染成功。
- 「思考过程」折叠面板渲染成功。
- 正文气泡区域完全空白，无任何正文内容、无报错提示。
- 对比正常截图：正常时正文会渲染 Markdown 标题、段落、表格等。

**结论：后端已返回内容（有 output Token 消耗 ↓437），属于纯前端展示链路故障。**

### 2.2 疑似根因清单（按概率排序）

| # | 疑似根因 | 典型特征 | 验证方式 |
| --- | --- | --- | --- |
| 1 | 正文渲染条件错误：只渲染了 `reasoning_content` 或 status 判断有误 | 思考过程能显示、正文空白 | 检查气泡组件的渲染条件与取值字段 |
| 2 | 流式响应字段不匹配：`content` / `delta` / `answer` 路径取错，或流式与全量结构混用 | 偶发、与特定模型/角色（代码助手）相关 | 打印原始响应，比对取值路径 |
| 3 | Markdown/高亮渲染器抛错被静默吞掉，整棵气泡渲染失败 | 特定内容（含代码块/表格/公式）必现 | 控制台报错、给渲染器加 Error Boundary 复现 |
| 4 | 响应式更新失效：嵌套属性直接赋值 / 列表 key 用 index / 异步写入未触发更新 | 切换会话或强制刷新后内容出现 | Vue DevTools / React DevTools 观察状态与视图差异 |
| 5 | 空内容无兜底：正文为空字符串/null 时渲染为空且无任何提示 | 少数请求出现 | 构造空响应测试 |

### 2.3 修复方案

**P0（必须）**

1. 修正正文取值与渲染条件：明确 `content` 与 `reasoning_content` 的取值路径与渲染分支，保证正文一旦存在必然渲染。
2. 渲染器加错误边界：Markdown 渲染失败时降级为 `<pre>` 纯文本展示，并上报错误日志。
3. 空内容兜底：当「有 output Token 消耗但正文为空」时，展示「回复内容加载异常」+「重试」按钮，点击后重新拉取该消息内容。

**P1（健壮性）**

4. 统一流式/全量响应的解析层，收敛为一个 `normalizeMessage()` 函数，杜绝字段路径分叉。
5. 消息状态机显式化：`pending → streaming → done / error`，渲染只依赖状态与归一化后的数据。
6. 前端日志上报：消息 id、原始响应摘要、渲染错误堆栈，接入现有监控。

**P2（防回归）**

7. 补充用例：空正文、超长正文、含代码块/表格/公式的正文、流式中断等场景的单测与 E2E 用例。

### 2.4 验收标准

- 任意回复场景下，只要后端返回正文，前端 100% 展示；
- 渲染异常时展示降级内容或错误提示，**永不空白**；
- 思考过程、Token 统计、操作按钮等既有功能无回归；
- 空内容场景出现可操作的「重试」入口。

## 三、问题二：加载动画优化方案

### 3.1 现状

加载态 = 紫色渐变骨架条 ×3 + 固定文案「星尘正在穿越神经网络…」。动画单一、无进度感知，等待超过几秒后用户无反馈。

### 3.2 设计目标

- 丰富等待期的视觉反馈，降低感知等待时长；
- 通过阶段文案让用户知道「进行到哪一步」；
- 保持现有浅紫色调与圆角气泡的视觉语言。

### 3.3 动画方案（封装为统一组件 `<AiLoading />`）

| 动画 | 说明 | 适用阶段 |
| --- | --- | --- |
| 三点呼吸 Typing Dots | 三个圆点依次缩放/透明度脉动 | 通用，首 Token 前 |
| 流光骨架 Shimmer | 现有骨架条叠加扫光渐变动画 | 默认骨架态增强 |
| 脉冲光环 Pulse Ring | 图标外圈光环扩散，呼应「星尘」主题 | 与文案区图标结合 |
| 打字机光标 | 竖线光标闪烁，模拟即将输出 | 首 Token 到达前的过渡 |

### 3.4 阶段文案轮播

| 等待时长 / 事件 | 文案 |
| --- | --- |
| 0 ~ 2s | 星尘正在穿越神经网络… |
| 2 ~ 5s | 正在理解你的问题… |
| 5 ~ 10s | 正在检索工作区数据… |
| > 10s | 内容较多，正在努力生成… |

文案以 300ms 淡入淡出切换；若后端支持阶段事件（如工具调用），优先按事件切换。

### 3.5 工程要求

- CSS 动画优先，仅使用 `transform` / `opacity`，避免重排；
- 尊重 `prefers-reduced-motion`，开启时降级为静态骨架 + 文案；
- 首 Token 到达后 loading → 正文 200ms 淡入淡出过渡，高度平滑变化，不闪跳；
- 组件 props：`type`（动画类型）、`phrases`（文案列表）、`interval`（切换间隔），默认值内置。

### 3.6 验收标准

- 至少 3 种动画可用，视觉风格统一；
- 文案按时间/事件正确轮播，切换自然；
- loading 到正文的过渡平滑无跳动；
- 低端设备动画帧率稳定（无明显掉帧）；
- `prefers-reduced-motion` 下正确降级。
