## 改动包 A：会话管理智能化

### A1. 需求描述

- 现状问题：会话保存到本地后以一串随机 ID 作为标识，用户无法从历史记录中辨认任何会话。
- 目标：
  1. 每个会话用「首条消息」自动生成一句简短描述作为标题（8~15 字）；
  2. 历史会话通过**抽屉/浮层**入口访问（不占固定布局宽度）；
  3. 抽屉顶部提供**搜索框**，支持按标题和消息全文检索。

### A2. 功能规格

#### A2.1 会话历史抽屉

- 入口：助手页左侧窄栏顶部新增「🕘 历史」图标按钮；工作台页「工作台会话」面板头部新增同款图标（两页交互一致）。
- 交互：
  - 点击后从左侧滑出抽屉（宽度约 300px），覆盖式浮层，带半透明遮罩，点击遮罩或按 `Esc` 关闭；
  - 抽屉内会话按最近活跃时间倒序排列，虚拟滚动（会话数 >100 时保证性能）；
  - 每条会话项显示：标题（一行省略）+ 最后活跃时间（如「昨天 23:27」）；
  - 悬停显示操作：重命名、删除（删除需二次确认）。
- 空状态：显示星尘风格插画 + 「还没有历史会话，开始你的第一次分析吧」。

#### A2.2 自动标题生成

- **触发时机**：该会话首轮问答完成（AI 首条回复流式结束）后，异步触发一次标题生成，不阻塞对话。
- **生成方式**：调用一次轻量 LLM（可用当前会话同款模型的低档位，或平台已有的小模型），输入用户首条消息 + AI 首条回复的前 500 字，输出 8~15 字概括标题。运行时提示词见 **附录 1**。
- **兜底逻辑**（按优先级）：
  1. LLM 返回为空 / 超时（5s）/ 报错 → 截取用户首条消息前 20 个字符，超出加「…」；
  2. 首条消息为纯文件/图片（无文本）→ 使用默认标题「新会话 + 日期」，如「新会话 07-23」。
- **标题清洗**：去除引号、书名号、首尾空格、换行；强制截断至 30 字。
- **手动重命名**：抽屉内会话项悬停 → 重命名，原地变为输入框，回车保存 / Esc 取消。手动命名后设置 `title_locked = true`，此后不再被自动生成覆盖。
- **持久化**：标题存数据库字段，文件/目录命名仍用会话 ID（避免重名、特殊字符、路径注入问题），**界面展示层一律显示标题，ID 仅作内部主键**。

#### A2.3 会话搜索

- 入口：抽屉顶部固定搜索框，占位文案「搜索会话标题或内容…」。
- 搜索范围：
  - 一级匹配：会话标题（模糊匹配，不区分大小写）；
  - 二级匹配：会话内消息全文（数据库 `LIKE` 或全文索引，视消息量级定）。
- 交互：
  - 输入防抖 300ms 后发起请求；
  - 结果分组展示：「标题匹配」组在前，「内容匹配」组在后；
  - 关键词在结果中**高亮**（`<mark>` 或等价样式，用主题强调色）；
  - 点击「内容匹配」结果 → 跳转会话并滚动定位到该条消息，消息短暂高亮闪烁提示；
  - 无结果时显示「未找到相关会话」。

### A3. 接口设计（建议）

| 方法 | 路径 | 说明 | 请求体 / 参数 | 响应 |
|---|---|---|---|---|
| GET | `/api/chat/sessions` | 会话列表（抽屉） | `?limit=50&offset=0` | `[{id, title, title_locked, last_active_at, message_count}]` |
| GET | `/api/chat/sessions/search` | 搜索会话 | `?keyword=xxx` | `{title_matches: [...], content_matches: [{session_id, title, message_id, snippet}]}` |
| POST | `/api/chat/sessions/{id}/generate-title` | 生成/重新生成标题 | 空 | `{title}` |
| PATCH | `/api/chat/sessions/{id}` | 重命名 | `{title}` → 同时置 `title_locked=true` | `{id, title}` |
| DELETE | `/api/chat/sessions/{id}` | 删除会话 | 空 | `204` |

> 说明：`generate-title` 在首轮问答完成后由**前端自动调用一次**；若该会话已有 `title_locked=true` 的标题则跳过。

### A4. 数据结构变更

会话表（session）新增字段：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `title` | VARCHAR(64) | NULL | 展示标题，NULL 表示尚未生成 |
| `title_locked` | BOOLEAN | false | 手动重命名后锁定 |
| `last_active_at` | DATETIME | 创建时间 | 排序依据，每次新消息更新 |

### A5. 边界与异常处理

- 标题生成失败不影响主流程，静默降级到兜底逻辑；
- 生成中的会话在抽屉里显示骨架占位标题「生成中…」；
- 删除当前正在进行的会话 → 先跳转回新会话页再执行删除；
- 搜索接口需转义 `%`、`_` 等通配符，防止 LIKE 注入；
- 重名标题允许存在（不强制唯一），靠时间区分。

### A6. 验收标准

1. 新建会话发送第一条消息并收到回复后，10 秒内抽屉中出现概括性标题（非 ID）；
2. 断网 / 模型超时场景下，标题降级为消息截断形式，无报错弹窗；
3. 手动重命名后，重新进入页面标题保持为手动值；
4. 搜索「差异表达」能命中标题含该词的会话，且关键词高亮；
5. 抽屉打开/关闭动画流畅（≤300ms），打开时不挤压主对话区布局。

### A7. 编码提示词（投喂 AI 编码助手）

```text
【背景】
这是 OmicHub 生信分析平台，前端为【填写：如 React + TypeScript + Tailwind】，后端为【填写：如 FastAPI / Node】，会话数据存储在【填写：数据库类型】。当前 AI 助手页的会话以随机 ID 作为标题保存，用户无法辨认历史会话。

【任务】实现「会话管理智能化」，包含三个功能，请分步实现并说明每一步改动的文件：

1. 抽屉式会话历史
   - 在 AI 助手页左侧窄栏顶部加一个历史图标按钮，点击从左侧滑出覆盖式抽屉（宽约 300px，带遮罩，Esc/点遮罩关闭）；
   - 抽屉内按 last_active_at 倒序展示会话：标题（单行省略）+ 相对时间；列表项悬停出现「重命名」「删除」操作，删除需确认；

   - 在会话表新增字段：title (VARCHAR(64), 可空)、title_locked (BOOLEAN, 默认 false)、last_active_at (DATETIME)；

   - 若 title_locked=true 则接口直接返回现有标题；
   - 失败兜底：截取首条消息前 20 字加「…」；无文本消息则用「新会话 MM-DD」；

【约束】
- 不改变助手页主布局，抽屉为覆盖式浮层，不挤压对话区；
- 文件/目录存储仍用会话 ID，标题仅用于展示；
- 所有新接口需有错误处理，失败静默降级，不弹报错打断用户；
- 标题生成用的 LLM 系统提示词：「你是会话标题生成器。根据用户的首条消息和助手的回复，用 8 到 15 个汉字概括这段对话的主题。只输出标题本身，不要标点结尾，不要引号，不要解释。」

请先给出改动文件清单和实现顺序，确认后再逐文件给出完整代码。
```

## 改动包 B：视觉风格统一（对齐首页「星尘」主题）

### B1. 现状问题

| 维度 | 首页 | AI 助手 / AI 工作台 | 问题 |
|---|---|---|---|
| 品牌色 | 蓝紫渐变 Banner | 几乎纯白+浅灰 | 品牌色缺席 |
| 图标 | 彩色图标 + 浅色圆角底（蓝/紫/青/绿/橙） | 全部线性灰图标 | 无色彩体系 |
| 卡片 | 大圆角 + 柔和阴影 | 平铺分区、无阴影 | 层次扁平 |
| 选中态 | 蓝色竖条 + 浅蓝底 | 助手页紫色药丸 / 工作台页另一种蓝 | 三处不统一 |
| 人格化 | 星尘工作站、问问星尘AI | 自称「智能助手」 | 命名割裂 |

### B2. 设计规范（Design Tokens，从首页提取）

> 以下色值需从首页实际代码中提取校准，此处为目测参考值，以代码为准。

```text
主渐变：linear-gradient(135deg, #6366F1 → #8B5CF6 → #A855F7)  （蓝→紫）
主色 Primary：#6366F1（按钮、链接、强调）
强调色 Accent：#8B5CF6
图标底色板（浅色圆角块）：蓝 #EEF2FF / 紫 #F3E8FF / 青 #ECFEFF / 绿 #ECFDF5 / 橙 #FFF7ED
```

### B3. 页面级改动清单

#### B3.1 全局侧边栏（三页统一）

- 所有页面菜单选中态统一为「主色竖条 + 浅蓝底」样式（与首页一致），替换助手页的紫色药丸样式。

#### B3.2 AI 助手页

1. 欢迎卡片：背景改为**淡渐变**（主渐变 10% 透明度版本）+ 大圆角 + 卡片阴影；
2. 发送按钮：改为主渐变实心圆角按钮，悬停加深；
3. 输入框工具栏图标（灯泡/附件/联网/图片/深度思考）：套用首页「彩色图标 + 浅色圆角底」样式，每个功能一个色板色；
4. 模型选择器标签：加主色描边或渐变描边；
5. 空状态：增加星尘风格插画（与首页 Banner 视觉同源），下方放 2~4 张快捷指令卡片（白底圆角卡片 + 彩色图标），点击直接发送预设问题，例如：
   - 「帮我看看工作区里有哪些数据文件」
   - 「RNA-seq 差异表达分析怎么开始」
   - 「画一个样本间相关性热图」
   - 「生成一份可复现的分析报告模板」
6. 助手命名统一为「星尘 AI」（与首页「问问星尘AI」呼应），头像使用星尘视觉元素。

#### B3.3 AI 工作台页

1. 顶部标签（对话 / 分屏 / 代码 / 跟随 AI）：选中态用主色 + 浅蓝底，图标彩色化；
2. 右侧面板（结果产物 / 待办计划 / 沙盒状态）：统一为白底圆角卡片 + 柔和阴影，面板标题前加彩色小图标；
3. 沙盒状态区：休眠/运行状态用彩色徽标（休眠灰紫、运行绿色脉冲点），资源条用主渐变填充；
4. AI 消息气泡内的标题与重点：用主色渲染，代码块头部加浅色渐变底。

### B4. 验收标准

1. 三页（首页 / 助手 / 工作台）侧边栏选中态完全一致；
2. 助手页与工作台页能识别出与首页同源的渐变主色与彩色图标体系；
3. 聊天长文本区域仍以浅色为底，对比度满足可读性（正文对比度 ≥ 4.5:1）；
4. 无样式回归：暗色/窄屏（1280px）下布局不破损。
