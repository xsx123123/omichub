# 任务：为 Agent 增加工作区文件浏览的原生能力（文件工具集）

## 背景与现状
- 平台为 OmicHub，对话中用户问"帮我看看工作区里有哪些数据文件"，
  Agent 回复"我目前没有可以浏览或列出工作区文件的工具"，只能引导用户
  去文件管理页面手动查看、或手动提供 file_id。
- 已有能力：Agent 支持根据用户提供的 file_id 读取文件并做后续分析
  （读取链路已存在，可复用）。
- 缺失能力：列举文件、搜索文件。Agent 无法自主发现用户工作区里有什么。

## 目标
为 Agent 注册一组只读的工作区文件工具，让它在对话中能自主列出、
搜索、（基于已有链路）读取当前用户工作区的文件。

## 实现 Spec

### 1. 新增工具（注册到 Agent 的 function calling 工具集）
1. `list_workspace_files(path?: string, pattern?: string)`
   - 列出指定目录内容，默认 path = 当前用户工作区根目录；
   - 返回每项的 file_id、文件名、类型（文件/文件夹）、大小、修改时间；
   - 支持 pattern 过滤（如 `*.csv`）。
2. `search_workspace_files(query: string, limit?: number)`
   - 按文件名模糊搜索，从用户工作区根目录递归；
   - limit 默认 50；默认排除 `.git`、`node_modules` 等目录；
   - 返回 file_id、文件名、相对路径、修改时间。
3. 读取不新增：工具结果中的 file_id 直接对接已有的文件读取/分析链路。

### 2. 权限与安全（必须遵守）
- 工具作用域 = **当前会话所属用户的工作区根目录**，禁止访问其他用户目录；
- 路径校验：拒绝任何通过 `..`、绝对路径逃逸出工作区根目录的请求，
  返回明确错误信息；
- 只读：不提供写入、删除、移动能力。

### 3. Agent 行为更新（系统提示词层）
- 在 Agent 的 system prompt 工具说明中注册上述工具，并明确使用时机：
  用户问"工作区里有什么文件 / 帮我找某个数据文件"时，**必须调用工具
  获取真实结果**，禁止再回复"我没有浏览文件的工具"；
- 找到文件后，Agent 应主动用列表形式展示（名称 + 类型 + 修改时间），
  并询问用户要对哪个文件做什么操作。

### 4. 与前端 @ 弹窗的关系
- 若前端 @ 弹窗的文件搜索接口（/api/files/search）已存在或正在开发，
  本工具集与其**复用同一个后端文件索引/搜索服务**，不要造第二套。

## 验收 Checklist
- [ ] 对话中问"工作区里有哪些数据文件"，Agent 调用 list_workspace_files
      并返回当前用户工作区的真实文件列表（含 file_id、大小、修改时间）
- [ ] 对话中问"帮我找一下 xx 表达表"，Agent 调用 search_workspace_files
      返回匹配文件，并能继续用 file_id 发起分析
- [ ] 构造 `../` 越权路径，工具拒绝并返回明确错误
- [ ] Agent 回复中不再出现"我没有浏览文件的工具"类话术
- [ ] 工具结果仅包含当前用户工作区内容，无其他用户数据
