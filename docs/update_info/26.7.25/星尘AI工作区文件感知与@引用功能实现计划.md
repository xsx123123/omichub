# 星尘 AI「工作区文件感知 + @ 引用」功能实现计划

## 背景与目标

**现状痛点**：星尘 AI 助手与平台数据割裂——用户问"工作区里有哪些数据文件"，助手没有文件目录访问能力，只能让用户自己去「工作区/文件管理」面板翻查；引用文件需要手动复制 `file_id`（形如 `upload://xxx`），体验断裂；后续不同智能体安装不同 Skill 后，用户也无法显式指定"用哪个专家/哪个能力"。

**目标**：

1. 助手可通过 MCP 工具直接读取用户工作区文件（列目录、读内容、查元数据）；
2. 对话输入框支持 `@路径` 引用文件，带自动补全（对标 Claude Code 的 `@` 交互）；
3. `@` 同时支持引用 Agent / Skill，实现显式指定专家与能力挂载。

**平台上下文**：OmicHub 生信分析平台，已有工作区文件管理模块（目录树：根目录 / enrichment / raw_data / results / temp / workspace，文件带 `file_id`）、星尘 AI 对话页（工作台模式、多智能体体系）。整体为星空/宇宙视觉风格。

---

## 现状问题 / 需求清单

| # | 问题 | 需求 |
|---|------|------|
| 1 | AI 看不见用户工作区文件，无法主动分析数据 | 封装 Workspace MCP Server，暴露只读文件工具 |
| 2 | 引用文件要手动复制 file_id，操作断裂 | 输入框 `@` 引用文件 + 自动补全 + chip 插入 |
| 3 | 无法显式指定智能体 / Skill | `@` 补全扩展支持 Agent / Skill 分组引用 |
| 4（可选） | 引用的文件在对话中无跳转闭环 | 对话气泡中的文件 chip 可点击跳转文件面板 |
| 5（可选） | Agent 文件操作无安全边界 | MCP 默认只读，写操作需二次确认 |

## 分阶段实现

### 阶段 1：工作区文件 MCP 工具（后端优先）

**改动点**：
- 新增 Workspace MCP Server（或等效工具层），向 Agent 暴露三个只读工具：
  - `list_files(path?)`：返回指定目录下的文件/文件夹列表（名称、类型、大小、修改时间、file_id）；
  - `read_file(file_id, max_bytes?)`：文本类文件返回内容预览，超过 100KB 截断并标注；二进制文件（BAM/CRAM 等）只返回元数据，不读内容；
  - `get_file_info(file_id)`：返回文件元数据。
- 权限范围硬限定为当前登录用户的工作区根目录，拒绝路径逃逸（`../` 等）。
- 助手系统提示词中登记三个工具，使"看看工作区里有哪些数据文件"可直接回答。

**对应提示词**：

```text
你是一名资深全栈工程师。本项目为 OmicHub 生信分析平台，后端已有工作区文件管理模块
（目录树：根目录/enrichment/raw_data/results/temp/workspace，文件有 file_id，
形如 upload://xxx）。先阅读现有文件管理与助手对话相关代码，禁止重构无关代码。

任务：新增 Workspace MCP Server（或等效工具层），向星尘 AI Agent 暴露三个只读工具：
1. list_files(path?)：返回指定目录下的文件/文件夹列表（名称、类型、大小、修改时间、file_id）
2. read_file(file_id, max_bytes?)：文本类文件返回内容预览，超过 100KB 截断并标注；
   二进制文件（BAM/CRAM 等）只返回元数据，不读内容
3. get_file_info(file_id)：返回文件元数据

要求：
- 权限范围硬限定为当前登录用户的工作区根目录，拒绝路径逃逸（../ 等）
- 工具默认只读，不暴露任何写/删除能力
- 在助手系统提示词中登记这三个工具，使"看看工作区里有哪些数据文件"可直接回答

验收：
- [ ] 问"工作区里有哪些文件"，助手直接列出真实目录内容
- [ ] 路径逃逸与越权访问被拒绝
- [ ] 大文件读取被截断并明确标注
```

### 阶段 2：输入框 `@` 文件引用 + 自动补全（前端为主）

**改动点**：
- 对话输入框监听 `@` 字符，弹出补全面板：数据源为当前用户工作区文件树，`@` 后字符实时模糊匹配（防抖 300ms）；面板项展示文件图标、文件名、所在路径；支持键盘上下选择、Enter 确认、Esc 关闭。
- 选中后在输入框插入不可编辑的 chip（显示文件名），chip 可整体删除。
- 发送消息时，把 chip 对应的 file_id/path 结构化注入消息上下文，Agent 侧可直接调用 `read_file` 读取被引用文件。
- 三态处理：加载中显示 loading；空目录显示"暂无可引用文件"；接口失败显示重试入口。

**对应提示词**：

```text
你是一名资深前端工程师。本项目前端为 Vue/React + 现有组件库，平台为深色星空视觉风格。
先阅读星尘 AI 对话页输入框组件与工作区文件树接口代码，复用现有 Popover/Dropdown
组件与设计 token，禁止修改路由与无关组件。

任务：为对话输入框添加 @ 文件引用与自动补全：
1. 输入 @ 弹出补全面板，数据源为当前用户工作区文件树，
   @ 后的字符实时模糊匹配（防抖 300ms）
2. 面板项展示：文件图标、文件名、所在路径；键盘上下选择、Enter 确认、Esc 关闭
3. 选中后在输入框插入不可编辑的 chip（显示文件名），chip 可整体删除
4. 发送消息时把 chip 对应的 file_id/path 结构化注入消息上下文，
   供 Agent 调用 read_file 读取
5. 三态：加载中 loading；空目录显示"暂无可引用文件"；接口失败显示重试入口
6. chip 样式与输入框现有附件/引用样式统一

验收：
- [ ] 输入 @ 弹出补全，模糊匹配、键盘操作、chip 插入/删除均正常
- [ ] 引用文件发送后，Agent 能正确读取该文件内容并用于分析
- [ ] 空目录/加载中/接口失败三态展示正常
- [ ] 不影响现有对话功能
```

---

### 阶段 3：`@` 引用 Agent / Skill

**改动点**：
- 补全面板扩展为两个分组（参考 Claude Code 的 `@` 交互）：
  - 文件组：`+` 图标 + 文件名/路径；
  - 智能体/技能组：`*` 图标 + 名称 + 一句话能力描述（如 `claude-code-guide (agent) — Use this agent when...`）。
- `@agent名`：将对话显式转接/指定给该智能体；`@skill名`：把该 Skill 挂载到当前对话上下文。
- Agent/Skill 列表来自平台已有的智能体注册数据，不新增数据源。

**对应提示词**：

```text
你是一名资深前端工程师。在阶段 2 已实现的 @ 补全面板基础上扩展（先读现有补全组件代码）：

任务：
1. 补全面板分为两个分组展示（参考 Claude Code 的 @ 交互）：
   - 文件组：+ 图标 + 文件名/路径
   - 智能体/技能组：* 图标 + 名称 + 一句话能力描述
2. @agent名：将对话显式转接/指定给该智能体
3. @skill名：把该 Skill 挂载到当前对话上下文
4. Agent/Skill 列表来自平台已有的智能体注册接口，不新增数据源

验收：
- [ ] @ 补全中文件与 Agent/Skill 分组展示正确
- [ ] 选中 Agent 后对话转接生效，选中 Skill 后能力挂载生效
- [ ] 阶段 2 的文件引用功能不受影响
```

---

### 阶段 4（可选增强）：引用闭环与安全加固

- 对话气泡中的文件引用渲染为可点击 chip，点击跳转文件管理面板对应文件位置；
- MCP 工具保持默认只读；若后续开放写操作（移动/删除/重命名），必须前端二次确认 + 操作日志记录。

## 风险与回退

| 风险 | 应对 |
|------|------|
| 大文件（BAM/CRAM/FASTQ）读入撑爆上下文 | `read_file` 强制截断 + 二进制只回元数据；引导 Agent 走分析流程而非直接读原始数据 |
| 越权/路径逃逸 | 后端在 MCP 层硬校验工作区根目录，前端不做安全假设 |
| 文件树过大导致补全卡顿 | 补全接口分页/按需加载子目录，前端防抖 + 虚拟滚动 |
| Agent/Skill 注册数据变动导致引用失效 | 发送时校验引用有效性，失效 chip 标灰提示 |
| 阶段间耦合导致返工 | 三个阶段独立交付、独立验收；每阶段完成后再进入下一阶段 |

---

## 执行建议

按 **阶段 1（后端/MCP）→ 阶段 2（前端补全）→ 阶段 3（Agent/Skill 引用）** 顺序执行，每阶段提示词单独粘贴给编码 Agent。验收时重点回归最初场景：同样问"工作区里有哪些数据文件"，助手应直接列出 enrichment、raw_data 等真实目录，而不是让用户自己去面板里找。
