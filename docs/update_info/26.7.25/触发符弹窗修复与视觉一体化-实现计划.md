- 先读现有代码再动手：输入框组件、弹窗组件、触发符监听逻辑、文件搜索相关接口。
- 不改输入框其他功能（发送、附件、深度思考等按钮）。

## 失败史（上一轮已尝试但未达标，禁止重复同样的实现）

- 样式：上一轮已要求弹窗"left:0; right:0; bottom:calc(100%+4px)、与输入框同背景同描边"，但当前实现仍是一个**独立的白色卡片**：自带独立搜索框、圆角和大阴影与输入框不一致、与输入框之间有明显间距和遮挡，视觉上"飘"在输入框上方。本轮必须按下文 spec 重构。
- 文件搜索：上一轮已要求"默认根目录=用户根目录"，但 @ 弹窗文件类结果仍为空。本轮必须先定位根因（见 Bug 排查要求），不允许只改前端文案。

## 样式重构：弹窗从输入框"长出来"，而不是飘在上面

### 交互结构改动（关键）

1. **移除弹窗内独立的搜索输入框**。弹窗不再有自己的搜索框；搜索词 = 输入框中触发符（@ 或 /）之后的文本，用户继续输入即实时过滤列表，与 Codex CLI 的 @ 行为一致。退格删到触发符时弹窗关闭。
2. 弹窗与输入框合并为**一个视觉容器**，而不是两个元素叠加：

```vue
<template>
  <!-- 一个容器包住弹窗和输入框，二者共享外框 -->
  <div class="composer" :class="{ 'composer--popup-open': popupVisible }">
    <Transition name="popup">
      <div v-if="popupVisible" class="trigger-popup">
        <!-- 列表项（无独立搜索框） -->
        <div class="popup-footer">
          <span><kbd>↑↓</kbd> 导航</span>
          <span><kbd>Enter</kbd> 选择</span>
          <span><kbd>Esc</kbd> 关闭</span>
        </div>
      </div>
    </Transition>
    <div class="input-box"><!-- 现有输入框内容，保持不变 --></div>
  </div>
</template>

<style scoped>
.composer {
  position: relative;
  background: var(--input-bg);       /* 与输入框现有背景一致 */
  border: 1px solid var(--input-border);
  border-radius: 16px;               /* 与输入框现有圆角一致 */
  transition: border-color 180ms ease-out;
}

/* 弹窗：不是独立卡片，是容器向上延伸的部分 */
.trigger-popup {
  position: absolute;
  left: -1px;                        /* 盖住容器左边框 */
  right: -1px;                       /* 盖住容器右边框 → 与输入框严格同宽 */
  bottom: calc(100% - 1px);          /* 与容器顶边 0 间距，边框相接 */
  background: inherit;               /* 与输入框同背景 */
  border: 1px solid var(--input-border);
  border-bottom: none;               /* 底边不画线，与输入框融为一体 */
  border-radius: 16px 16px 0 0;      /* 只保留上方圆角 */
  max-height: 320px;
  overflow-y: auto;
  /* 不用独立大阴影；如需阴影，与容器统一 box-shadow */
}

/* 弹窗打开时，容器顶部圆角交给弹窗，自己变直角，二者拼成一个整体 */
.composer--popup-open {
  border-radius: 0 0 16px 16px;
}

.popup-footer {
  display: flex;
  justify-content: flex-end;
  gap: 16px;
  padding: 8px 12px;
  border-top: 1px solid var(--input-border);
  font-size: 12px;
  color: var(--text-secondary);
}

.popup-enter-active, .popup-leave-active {
  transition: opacity 180ms ease-out, transform 180ms ease-out;
  transform-origin: bottom;
}
.popup-enter-from, .popup-leave-to {
  opacity: 0;
  transform: translateY(8px);
}
</style>
```

### 数值要求（全部从输入框现有样式取值，禁止新造色值）

- 宽度：弹窗与输入框严格同宽（用 `left:-1px; right:-1px` 对齐容器边框）；
- 间距：弹窗底边与输入框顶边 **0 间距**，共享边框，弹窗 `border-bottom: none`；
- 圆角：弹窗只保留上方两个圆角（与输入框圆角同值），弹窗打开时输入框上方圆角变直角，二者拼成一个完整圆角容器；
- 背景/描边/文字色：全部复用输入框现有 CSS 变量；
- 阴影：去掉弹窗独立的大阴影；如整体需要阴影，加在 `.composer` 容器上；
- 动画：从输入框方向向上展开，`transform-origin: bottom`，150~200ms ease-out；
- 底部快捷键栏：`↑↓ 导航`、`Enter 选择`、`Esc 关闭`，右对齐、12px、次要文字色。

## @ 引用列表：文件 / Skill / Agent 混排 + 类型徽标

参考 Codex CLI 的 @ 列表交互：

- 同一个结果列表中混合展示三类结果：**文件、Skill（技能）、Agent（智能体）**，按匹配度排序，不再分 Tab 或分区隐藏；
- 每行**末尾用类型徽标区分**：`File`、`Skill`、`Agent`（12px、次要色描边小胶囊）；
- 文件行格式：左侧文件名（等宽字体），中间灰色显示所在相对路径，右侧 `File` 徽标；
- Skill/Agent 行格式：名称 + 一句话描述 + 右侧类型徽标；
- 分组标题（如"智能体/技能"）保留可选，但类型徽标必须有。

## Bug：@ 文件搜索仍为空 —— 下沉一层排查根因

上轮修复未生效，本轮按以下顺序定位，**先出根因结论再动手改**：

1. 打开浏览器网络面板，在 @ 弹窗输入文件名，确认**前端是否真的发出了文件搜索请求**：
   - 若**没有发出请求** → 前端只接了智能体/技能数据源，文件数据源未接入，需补接；
   - 若请求发出但 **404/接口不存在** → 后端缺少文件搜索接口，需新建：`GET /api/files/search?q={关键词}&root={用户根目录}&limit=50`；
   - 若接口返回空 → 检查 root 参数是否为用户根目录、索引是否建立、目录读取权限；
2. 文件搜索默认根目录 = **当前用户根目录**（用户工作区目录），递归子目录，默认排除 `.git`、`node_modules` 等目录；
3. 三种空态分别提示，不允许一律显示"暂无可引用文件"：
   - 接口异常 → "文件搜索服务异常，请稍后重试"；
   - 索引为空 → "该目录下暂无可引用文件"；
   - 权限不足 → "无权限访问该目录"。
