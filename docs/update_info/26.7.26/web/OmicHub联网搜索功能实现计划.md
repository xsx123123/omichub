# OmicHub 联网搜索功能实现计划（参考 Cherry Studio）

## 背景与目标

**现状**：聊天输入框已有"联网搜索"开关（地球图标，悬停提示"关闭联网搜索"），但它只是
一个前端 UI 状态——AI 配置中心没有任何搜索服务商配置，对话链路也没有任何搜索调用，
开关打开后 AI 依然无法真正联网。

**目标**：参考 Cherry Studio 的"网络搜索"设计，分两件事落地：

1. **配置侧**：在 AI 配置中心 · 资源中心新增"联网搜索"子 Tab，实现多搜索服务商的统一
   管理（密钥配置、连通性检测、默认源设定）。
2. **能力侧**：把输入框的地球开关从纯前端状态接通为真实能力——模型回答前/回答中真实
   发起搜索，结果注入对话，并在回答下方展示可点击的引用来源。

## 现状问题 / 需求清单

1. 配置中心没有搜索服务商管理（对比 Cherry Studio：API 服务商 Tavily / Searxng / Exa /
   ExaMCP / Bocha / Zhipu / Querit + 本地搜索 Google / Bing / Baidu）。
2. 输入框"联网搜索"开关是纯前端状态，未接通任何后端逻辑。
3. AI 回答没有引用来源展示，用户无法验证时效性内容的出处。
4. 没有密钥连通性检测、没有"默认搜索源"概念，配错了只能在对话失败时才发现。

## 方案设计要点

### 配置模块（对标 Cherry Studio 双栏布局）

- **位置**：资源中心新增第 4 个子 Tab"联网搜索"，与 MCP 服务 / 技能 / 助手并列。
- **布局**：左侧服务商列表 + 右侧配置面板。
  - 左侧分两组：**API 服务商**（Tavily、Bocha、智谱 Zhipu、Exa、SearXNG 自建）与
    **本地搜索**（Google、Bing、Baidu，标注"免费 · 不稳定"）；当前默认源带绿色"默认"徽标。
  - 右侧：API 密钥（密码框 + 显隐切换 + **检测**按钮 + "点击这里获取密钥"外链）、
    API 地址（可编辑、带官方默认值）、右上角"设为默认"、启用开关。
- **数据模型**：

  ```json
  {
    "id": "tavily",
    "name": "Tavily",
    "type": "api | searxng | scrape",
    "apiKey": "<服务端加密存储>",
    "baseUrl": "https://api.tavily.com",
    "enabled": true,
    "isDefault": false,
    "params": { "maxResults": 5, "searchDepth": "basic" },
    "updatedAt": "..."
  }
  ```

- **密钥安全**：服务端加密存储（沿用项目里模型 Provider 密钥的既有加密方式）；接口只
  返回掩码（`sk-****1234`）；前端永不显示明文；日志脱敏。

### 搜索接入（对话链路）

两种模式，按模型能力自动选择：

- **模式 A · Function Calling（优先）**：模型支持 tools 时，注入 `web_search` 工具定义；
  模型发起 tool_call → 后端执行搜索 → 结果作为 tool 消息回注 → 继续流式生成。
- **模式 B · 预搜索注入（兜底）**：模型不支持 tools 时，发送前先用用户最后一条消息
  （必要时结合上下文改写 query）调搜索，把结果整理为带编号引用的 context 注入
  system 消息，再走正常对话。

统一返回结构（各服务商适配层归一化）：

```json
{ "title": "...", "url": "...", "snippet": "...", "publishedAt": "2026-07-26" }
```

### 对话 UI

- 开关接通真实状态；未配置任何可用搜索源时点击开关，弹出引导（"请先到 AI 配置中心 ·
  资源中心 · 联网搜索 配置服务商"）并附跳转，不静默失败。
- 触发搜索时，回答气泡前流式展示"🔍 正在联网搜索：{query}"状态条，完成后可展开查看
  命中结果列表。
- 回答正文的 `[1][2]` 编号与搜索结果一一对应；气泡底部渲染"来源"列表（标题 + 域名
  favicon + 点击新窗口打开）。
- 搜索超时（>10s）或全部失败时不阻塞对话：提示"联网搜索失败，已基于模型自身知识回答"，
  走无搜索链路。

### 阶段 3：增强项（可延后，独立交付）

- **SearXNG 自建源**：只需填实例地址无需密钥，作为隐私友好的自备选项。
- **本地免费抓取源**：Google / Bing / Baidu 结果页解析（服务端 cheerio 解析 + UA 轮换），
  默认不启用并标注"免费 · 不稳定"，被反爬时自动降级到默认 API 源。
- **搜索参数可调**：结果条数（1–20）、搜索深度（basic/advanced）、时间范围过滤
  （day/week/month/year），暴露在服务商配置面板。
- **按助手绑定默认源**：助手配置里可覆盖全局默认搜索源（如科研助手默认 Exa，
  通用助手默认 Tavily）。
- **Query 改写**：多轮对话下用轻量模型把"它多少钱"类指代问题改写为完整搜索 query，
  提升命中率。
- **用量统计**：各源调用次数 / 成功率 / 平均耗时，在"联网搜索"Tab 顶部加一行概览。

## 风险与回退

| 风险 | 应对 |
|---|---|
| 模型不支持 function calling | 模式 B 预搜索注入兜底，两模式在阶段二都要求验证 |
| 搜索延迟拖慢首字时间 | SSE 先发"正在联网搜索"状态事件；搜索超时上限 10s，超时自动降级 |
| API 密钥泄露 | 加密存储、接口掩码返回、日志脱敏、前端不回显明文 |
| 免费抓取源被反爬 | 标注"不稳定"、默认不启用、失败自动降级到默认 API 源 |
| 搜索结果污染上下文（超长） | 注入前截断 snippet（单条 ≤300 字符），总注入 ≤4000 字符 |
| 改动影响现有对话链路 | 开关默认关闭；搜索逻辑封装为独立中间层，关闭时零介入 |

**回退方案**：配置模块为独立 Tab、搜索执行为独立中间层，任一阶段出问题可整体关闭
开关回退到现有纯模型对话，不影响 MCP 服务与模型配置。
