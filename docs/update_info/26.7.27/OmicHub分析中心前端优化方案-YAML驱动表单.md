# OmicHub 分析中心前端优化方案（YAML 驱动表单）

> 对象：RNA-seq 差异表达分析等"分析中心"流程提交页。
> 关键前提：页面由**解析各流程 YAML 动态生成**，因此本方案的核心不是改某个页面，
> 而是 ① 升级通用渲染器 + ② 扩展 YAML 的 UI 提示 schema——所有流程页一次性受益，
> 单个流程只需补 UI 提示字段，不硬编码。

---

## 一、现状问题诊断（对照截图）

1. **信息架构缺失**：任务参数一区平铺 15+ 字段——项目元信息（项目名称/客户）、
   参考配置（基因组/物种/链特异性）、路径（原始/交付目录）、执行模式、
   8+ 个功能开关全部混排，用户无法建立"先填什么、后填什么"的心智模型。
2. **宽屏失控**：内容通栏拉伸，单列控件在 2K/4K 屏上拉满整行，标签列与控件之间
   大片空白；页面需滚动 3~4 屏才能到达提交按钮。
3. **功能开关区冗长**：每个 switch 独占一行（标签+开关+说明），8 个开关占近一屏；
   开关之间无分组（质控类/分析类/交付类）。
4. **样本表原始**：纯手填三列，无批量粘贴/CSV 导入/从数据管理选择；
   必填徽标是红底胶囊（像报错）；删除为裸文字链接；无行号与分组统计。
5. **差异比较组弱化**：定义对照/实验组是 DEG 分析的核心输入，却只是参数流中的
   一个虚线按钮，与样本表无联动（比较组的分组应可从样本表 group 列选取）。
6. **提交区割裂**：费用/余额行与"提交任务"按钮分离（按钮在卡片外左下角）；
   无提交前校验摘要（哪些必填未填）；提交中无 loading 态；不吸底，长表单下
   用户滚到底才能提交。
7. **细节不一致**："任务名称"只有 placeholder 无 label，与其他字段形态不一致；
   高级参数折叠行的说明文字甩在最右侧，关联性弱。

---

## 二、设计原则

1. **schema 驱动，不硬编码**：一切分组/布局/控件偏好都通过 YAML 的 `ui` 提示
   表达；渲染器对缺失提示有合理默认（向后兼容，旧 YAML 零改动可运行）。
2. **三段式心智模型**：任何流程提交页 = 基础配置（必填主链）→ 样本表 →
   提交栏。功能开关等"选装项"收进"分析模块"分组。
3. **宽屏收敛**：表单内容区 max-width 1080px；同组内短字段双列排布。
4. **提交前可见代价**：费用、必填校验状态、样本数统计在提交栏聚合并常驻可见。

---

## 三、YAML UI Schema 扩展设计（核心）

在现有流程 YAML 的每个参数定义上，增加**可选** `ui` 块（全部字段可缺省）：

```yaml
# flows/rna_seq.yaml（片段示例）
params:
  - key: project_name
    label: 项目名称
    type: string
    required: true
    default: OmicsHub_RNA_seq
    help: 为该 RNA-seq 项目命名
    ui:
      group: basic          # 分组 id，见下方 groups 定义；缺省归入 basic
      order: 10             # 组内排序，缺省按声明顺序
      span: 1               # 占列数（组内为 2 列网格）：1=半行 2=整行；默认短字段 1、长字段 2
      widget: input         # input|select|switch|path|textarea；缺省按 type 推断
      placeholder: 如 T细胞活化项目

  - key: raw_data_dir
    label: 原始数据目录
    type: string
    required: true
    help: 存放原始 FASTQ 文件的目录路径（RNAFlow 会根据 sample 列自动匹配 _R1.fq.gz/_R2.fq.gz）
    ui:
      group: data
      widget: path          # 路径型控件：等宽字体 + 目录选择器按钮 + 存在性校验图标
      span: 2

  - key: run_deg
    label: 运行差异表达分析 (DEG)
    type: boolean
    default: true
    help: 使用 DESeq2 进行差异表达分析
    ui:
      group: modules        # 功能开关统一进"分析模块"组
      subgroup: 差异与注释   # 模块组内的二级小标题，可选

# 分组定义（流程级，缺省时渲染器用默认三组）
groups:
  - { id: basic,   title: 基本信息,   desc: 项目标识与执行方式 }
  - { id: data,    title: 参考与数据, desc: 参考基因组、物种与输入输出路径 }
  - { id: modules, title: 分析模块,   desc: 选择本次运行的分析内容, collapsible: false }
  - { id: advanced, title: 高级参数,  desc: 一般无需修改, collapsible: true, collapsed: true }

# 样本表定义（已有，扩展 ui 提示）
sample_sheet:
  columns: [sample, sample_name, group]
  ui:
    import: [paste, csv, datacenter]   # 允许的批量导入方式
    group_column: group                 # 标记哪列是分组列（供差异比较组联动）
```

**渲染器默认规则（YAML 无 ui 提示时）**：
- 未声明 group → 按 `required` 归 basic / 其余归 modules（boolean 型）或 advanced；
- string 且 key 含 `dir|path` → widget=path；boolean → switch；enum → select；
- 单组字段 ≤2 个时该组自动取消分组标题，平铺即可。

## 四、页面结构与视觉 Spec

### 4.1 整体布局

```text
┌ 页头：流程名称 + 一句话说明 + 右侧「查看源码」 ─────────────┐
├ 内容区（max-width 1080px，居中，左右 24px padding）────────┤
│  ▎基本信息（分组标题 16px/600 + 4px 主题色竖条 + 12px 灰说明）│
│    任务名称*        │ 项目名称*        （双列网格，gap 16px） │
│    客户/课题组*     │ 执行模式*                            │
│  ▎参考与数据                                                  │
│    参考基因组版本*  │ 物种*                                  │
│    链特异性*        │ 原始数据目录*（path 控件，整行）         │
│    结果交付目录（path 控件，整行）                            │
│  ▎分析模块（开关网格，见 4.2）                                │
│  ▸ 高级参数（折叠，默认收起）                                 │
│  ▎样本表（独立卡片，见 4.3）                                  │
│  ▎差异比较组（独立卡片，与样本表联动，见 4.4）                │
├ 吸底提交栏（见 4.5）─────────────────────────────────────────┘
```

- 分组标题样式：16px/600 + 左侧 4px×18px 主题色竖条 + 同行右侧 12px 灰色说明；
  组间距 28px；不再使用大白卡套全表单，分组直接落在页面灰底上（与终端页
  优化后的层级一致）。
- 双列网格：span=1 字段两列排布（控件不再拉满整行）；<768px 退化为单列。
- 字段行结构统一：label（14px/500，必填红色 * 在 label 右侧）+ 控件 +
  help（12px 灰色，控件下方 4px）；label 一律在控件上方（弃用右侧对齐的
  窄标签列，消除标签与控件间的空白带）。

### 4.2 分析模块（开关区）

- 开关从"一行一个"改为**网格模块卡**：2~3 列网格，每卡 = 开关 + 名称（14px/500）
  + 一句说明（12px 灰），卡片 padding 12px 16px，边框 1px，圆角 8px；
- 开启态：卡片边框主题色 + 浅主题底（rgba 0.04），开关主题色；
- 有 subgroup 时按二级小标题分簇（如：质控 / 差异与注释 / 结构变异）；
- "仅运行 QC"这类互斥项：开启后其余模块卡置灰禁用并 tooltip 说明原因。

### 4.3 样本表

- 表头：列名 + 红色 `*`（弃用红底胶囊"必填"徽标）；行号列（40px）；
- 批量导入三入口（按钮组置于表格右上）：
  - **粘贴**：弹层内粘贴 Excel/TSV 文本，解析预览后写入；
  - **上传 CSV**：解析校验（列名映射、空值高亮）；
  - **从数据管理选择**：拉取用户已上传的样本表文件；
- 行内校验：sample 重复标红、group 为空标黄；表格底部统计
  "共 N 样本 · M 个分组（每组样本数）"；
- 删除改为行尾图标按钮（hover 红）；添加样本按钮虚线描边全宽。

### 4.4 差异比较组（仅 run_deg 开启时显示）

- 从参数流中移出，独立卡片置于样本表之后；
- 每组 = 对照组 select + 实验组 select，**选项取自样本表 group 列的去重值**
  （样本表改动即联动，无分组时提示"请先在样本表填写 group 列"）；
- 组间方向明示：`对照 ──vs──> 实验`，避免方向搞反（DEG 最常见错误）；
- 多组比较以卡片列表堆叠，可单独删除。

### 4.5 吸底提交栏

- 吸底固定（页面滚动时始终可见）：毛玻璃底 rgba(255,255,255,0.85) +
  backdrop-filter blur(8px) + 顶部 1px 分割线；
- 左：预估费用 + 当前余额 + 余额状态徽标（充足绿/不足红）；
- 中：必填校验状态（"还有 2 项必填未填写"红色，全部就绪时不显示）+
  样本统计摘要（N 样本 · M 分组）；
- 右：提交按钮（主按钮，高 40px，宽 140px），提交中 loading + 禁用；
- 提交失败：按钮恢复 + toast 给出后端返回的具体校验错误；
- 提交成功：跳转任务详情并 toast"任务已提交"。

## 五、提示词：分析中心渲染器与 RNA-seq 页面优化（粘给编码 Agent）

```text
你是一名资深前端工程师。项目为 OmicHub 多助手平台，前端 Vue3 + Naive UI。
分析中心页面由解析各流程 YAML 动态生成（先找到流程 YAML 解析器与表单渲染器
组件，以及 flows/rna_seq.yaml 的实际字段定义），理解现状后再修改。
禁止硬编码 RNA-seq 专属逻辑进渲染器；YAML 新增字段全部可选、向后兼容，
旧流程 YAML 不做任何修改时页面按默认规则正常渲染。

## 一、渲染器升级（通用，所有流程受益）
1. 支持参数级 ui 提示块：group / order / span(1|2) / widget(input|select|switch|
   path|textarea) / subgroup / placeholder，全部可缺省，默认规则：
   未声明 group 时 required 字段归 basic、boolean 归 modules、其余归 advanced；
   key 含 dir|path 的 string 默认 widget=path。
2. 支持流程级 groups 定义（id/title/desc/collapsible/collapsed），未定义时使用
   默认三组（基本信息/分析模块/高级参数）。
3. 分组渲染：标题 16px/600 + 左侧 4px 主题色竖条 + 右侧 12px 灰说明；
   组内双列网格（span=2 整行），<768px 单列；label 上置（14px/500，必填红色 *），
   help 12px 灰置于控件下 4px；组间距 28px；页面内容区 max-width 1080px。
4. 分析模块开关网格卡：2~3 列，卡 = switch + 名称 + 说明；开启态主题色描边 +
   浅底；subgroup 分簇小标题；支持互斥禁用（如仅运行 QC 开启时其余置灰 +
   tooltip）。
5. path 型控件：等宽字体 + 右侧"选择目录"按钮（复用现有文件/目录选择能力，
   无则先占位禁用态）。
6. 高级参数组：折叠面板默认收起，展开动画 200ms。

## 二、样本表组件重做（通用组件，供所有流程复用）
1. 表头列名 + 红色 *（移除红底胶囊徽标）；行号列 40px。
2. 批量导入：粘贴（弹层解析 Excel/TSV）/ 上传 CSV（列名映射 + 空值高亮）/
   从数据管理选择（按 yaml sample_sheet.ui.import 声明渲染按钮）。
3. 行内校验：sample 重复标红、必填空值标黄；底部统计"共 N 样本 · M 个分组"。
4. 删除为行尾图标按钮（hover 红）；添加样本为虚线描边全宽按钮。

## 三、差异比较组联动（RNA-seq 等有 comparisons 定义的流程）
1. 从参数流移出为独立卡片，置于样本表后，仅当对应开关（run_deg）开启时显示。
2. 对照组/实验组 select 的选项取自样本表 group 列去重值，样本表变更即联动；
   无分组时显示引导文案。
3. 组间渲染为 对照 ──vs──> 实验 的明确方向结构；多组堆叠可单独删除。

## 四、吸底提交栏
1. 吸底毛玻璃固定栏：左（预估费用/当前余额/余额徽标）｜中（必填校验提示 +
   样本统计）｜右（提交按钮 40px 主按钮，提交中 loading 禁用）。
2. 提交前前端必填校验，未通过时中间区红色列出缺项数量并自动滚动到第一个
   未填字段；失败 toast 带后端错误详情；成功跳转任务详情。
3. 费用/余额数据沿用现有接口，不改后端。

## 五、flows/rna_seq.yaml 补 UI 提示
按方案文档第三节的示例为各参数补 ui 块（groups 定义 + 参数 group/span/
widget/subgroup），纯增量，不改任何 key/type/default。

## 验收标准
- [ ] RNA-seq 页面呈现 基本信息/参考与数据/分析模块/高级参数 四分组，滚动 ≤1.5 屏
- [ ] 开关以网格卡呈现，仅运行 QC 的互斥禁用生效
- [ ] 样本表三种批量导入可用，行内校验与底部分组统计正确
- [ ] 差异比较组选项随样本表 group 列联动，方向明示
- [ ] 提交栏吸底，未填必填时提交被拦截并定位到首个缺项
- [ ] 不修改任何 YAML 时，另一个流程页（任选一个旧流程）按默认规则渲染无异常
- [ ] 1280/1920 宽度无布局破损
```

## 六、实施顺序与风险

**顺序**：① 渲染器分组/网格升级（收益最大）→ ② 吸底提交栏 → ③ 样本表组件 →
④ 比较组联动 → ⑤ RNA-seq YAML 补提示。前四步都是渲染器通用能力，
可逐个上线；⑤ 是纯配置。

| 风险 | 应对 |
|---|---|
| 渲染器改动影响其他流程页 | ui 提示全可选 + 默认规则兜底；验收时抽查一个未改 YAML 的旧流程 |
| 样本表批量导入解析边界（Excel 粘贴的合并单元格/空行） | 解析层 trim + 空行丢弃 + 列数不符整行标红，不给静默错误 |
| 比较组与样本表联动的时序（先填比较组后改样本） | 样本表 group 变更时校验已选比较组，失效选项标红提示重新选择 |
| 吸底栏遮挡表单底部内容 | 内容区底部 padding = 提交栏高度 + 16px |
