# OmicHub 任务界面样式优化实现计划（最近任务卡片 + 任务中心页）

> 版本：v2.0　日期：2026-07-27
> 范围：**Part 1** 首页/工作台「最近任务」卡片（选中态、进度列、列对齐）；
> **Part 2** 「任务中心」页整体优化（含 10000% 进度 bug、失败进度条、页面风格统一）
> 性质：**已有页面的样式优化 + 显示修复**，不是重新设计；不动数据逻辑与交互行为
> 实施顺序建议：**先做 Part 2**（含真 bug 修复，影响数据正确性），再做 Part 1（纯样式）

---

## 1. 背景与目标

「最近任务」卡片用于展示用户近期提交的分析任务（所属用户 / 任务名称 / 分析流程 /
提交时间 / 状态 / 进度 / 操作）。当前版本存在三处视觉问题，影响卡片选中时的观感和
表格的可读性。本次优化只做样式与单元格布局调整，目标是一次改对、可逐条对照验收。

## 2. 问题清单与修改 Spec

### 问题 1：卡片选中高亮与表格底色冲突

- **现状**：卡片选中态使用明显的浅蓝紫底色（约 #eef0fb 系），卡片内表格区域又铺了
  一层半透明白底，两种颜色叠加后显得脏、卡片与表格的边界不清晰。
- **修改 spec**：
  - 卡片选中态改为「左侧 3~4px 主题色竖条 + 1px 高亮描边（主题色 40% 透明度）
    + 极浅色底（不浅于 `#f7f8ff`）」，不再使用明显的蓝紫实底；
  - 表格容器背景改为不透明实色 `#ffffff`，表头行背景 `#f7f8fa`，与卡片底色形成
    清晰的明暗分层，**禁止半透明叠加**；
  - 未选中态卡片保持现有中性底色不变。
- **预期效果**：选中后卡片有明确的「选中感」（竖条 + 描边），但表格区域干净、边界分明。

### 问题 2：进度列「100%」折成两行

- **现状**：进度列中进度条 + 百分比文字排不下，「100」和「%」被挤成两行，行高被撑大。
- **修改 spec**：
  - 进度单元格改为 flex 布局且不换行：
    - 进度条：`flex: 1; min-width: 60px;`
    - 百分比文字：`white-space: nowrap; width: 44px; text-align: right;`
      并加 `font-variant-numeric: tabular-nums;` 保证数字宽度稳定；
  - 「进度」列设置 `min-width: 160px`，表格列宽分配时优先保证该列。
- **预期效果**：0%~100% 任意进度值都单行完整显示，行高一致。

### 问题 3：列对齐统一为居中（含方案评估结论）

- **评估结论**：**方向正确，建议全部居中。** 该表各列数据短且同构（用户名、短任务名、
  状态标签、进度条、图标按钮），统一居中后表头与数据上下对齐，视觉最整齐；这是
  数据表格中「短值同构列」的主流做法。唯一需要左对齐的场景是长文本列（如长任务名），
  当前不存在，无需保留例外。
- **修改 spec**：
  - 表格所有列（表头 `th` + 单元格 `td`）统一 `text-align: center`，覆盖
    所属用户、任务名称、分析流程、提交时间、状态、进度、操作七列；
  - 操作列图标按钮组用 `display: flex; justify-content: center; gap: 12px;`
    居中排列；
  - 若所用表格组件库支持 column 级 `align` 属性，优先用组件配置而非全局 CSS 覆盖，
    避免影响平台其他表格。
- **预期效果**：表头与数据垂直对位，整表视觉整齐。

## 3. 全局约束

- 在现有「最近任务」卡片组件基础上修改，**先读现有代码再动手**，禁止推倒重写；
- 不改路由、不改表格数据逻辑、轮询刷新逻辑和查看/重试/删除等交互行为；
- 不引入新依赖（确有必要先说明理由）；
- 风格与平台首页/工作台其他卡片保持一致（中性底 + 主题色点缀），不引入新色系；
- 响应式不破：选中切换、数据变化时不出现新增横向滚动。

## 4. 实施步骤

单阶段交付，三处修改位于同一组件（及其样式文件），一次提交即可：

1. 定位「最近任务」卡片组件与表格样式实现，确认表格组件库及列配置方式；
2. 按问题 1 调整卡片选中态与表格底色分层；
3. 按问题 2 改造进度单元格布局与列宽；
4. 按问题 3 统一列居中（优先组件配置）；
5. 对照验收 checklist 逐条自检。

# Part 2：「任务中心」页整体优化（2026-07-27 第二轮）

## P2.1 背景与目标

「任务中心」页用于管理和监控所有生信分析任务的执行状态（搜索、状态筛选、任务表格、
统计汇总）。当前页面存在两处**显示逻辑 bug** 和多处样式问题，且整体是纯灰白默认样式，
与平台首页的视觉风格（卡片质感、主题色、标题规范）脱节。本轮目标：先修 bug，
再把页面风格统一到平台整体基调。

## P2.2 问题清单与修改 Spec

### 问题 1【Bug】：进度显示「10000%」

- **现状**：进度列把百分比重复乘了 100，100% 显示为 10000%。
- **修改 spec**：定位进度格式化代码（常见于 `progress * 100` 而数据源已是百分数），
  修正为 0~100 的整数显示；百分比文字 `white-space: nowrap; width: 48px;`
  + `font-variant-numeric: tabular-nums;`。
- **预期效果**：进度显示为正常的 0~100% 数值。

### 问题 2【Bug】：失败任务进度条显示满格红色

- **现状**：失败任务进度条为满格红色（100%），与「失败」状态逻辑矛盾。
- **修改 spec**：失败任务显示实际进度值，进度条用灰色 `#d1d5db`；无实际进度数据时
  显示 0% 置灰条；「失败」语义由状态列标签承担，进度条不再用红色。
- **进度条颜色语义统一**：进行中 = 主题色、已完成 = 绿色、失败 = 灰色。
- **预期效果**：进度条只表达进度，不表达成败，全表颜色语义一致。

### 问题 3：流程列折行

- **现状**：流程名（如 kegg-enrichment）被放进灰色胶囊且折成两行。
- **修改 spec**：去掉灰色胶囊底，流程名用次要色普通文本单行显示，
  `white-space: nowrap`，超出省略号 + hover title 提示；流程列 `min-width: 140px`。
- **预期效果**：流程名单行完整显示，行高一致。

### 问题 4：页面风格与平台整体统一

- **现状**：纯灰白默认样式，无卡片质感，与平台首页风格脱节。
- **修改 spec**：
  - 页面标题「任务中心」与副标题的字号/字重/颜色对齐平台首页标题规范；
  - 任务列表容器改为平台统一卡片样式：白底 `#ffffff`、圆角 `12px`、
    1px 浅灰边框 `#e5e7eb` + 轻投影；
  - 表头行背景 `#f7f8fa`，行 hover 浅色反馈；行高由当前过松收紧至 56~64px；
  - 主按钮（刷新）用平台主题色实心或描边样式，去掉黑色粗描边。
- **预期效果**：页面质感与平台首页/工作台一致，一眼能看出是同一平台。

### 问题 5：统计区简陋

- **现状**：「共 10 个任务 / 4 已完成 / 6 失败」为裸文字 + 小圆点。
- **修改 spec**：改为三个统计 chip——浅灰底（`#f3f4f6`）圆角胶囊，内含彩色状态点
  + 加粗数字（tabular-nums）；与标题区左对齐排列。
- **预期效果**：统计信息整齐、易扫读。

### 问题 6：重复的「刷新」按钮

- **现状**：搜索栏右侧和统计区右侧各有一个刷新按钮。
- **修改 spec**：只保留搜索栏右侧的一个，删除统计区右侧的重复按钮。

### 问题 7：操作列按钮过重

- **现状**：4 个灰色方块按钮视觉重，禁用态与可用态区分不清。
- **修改 spec**：
  - 改为无边框纯图标按钮：icon 18px、颜色 `#6b7280`，hover 变主题色 +
    浅色圆形底 + tooltip 说明；
  - 删除按钮 hover 变红 `#ef4444`；
  - 禁用态 `opacity: 0.35` + not-allowed 光标；
  - 按钮间距 `gap: 8px`，整列垂直居中。
- **预期效果**：操作列轻量，可用/禁用态一眼可辨。

## P2.3 全局约束

## P2.6 风险与回退

- 问题 1 涉及格式化代码修改，需确认数据源进度的量纲（0~1 还是 0~100），
  避免改错方向；改前先在控制台打印原始值确认；
- 卡片/行高调整可能影响行内容垂直居中，改后检查状态标签、进度条、操作按钮的
  垂直对齐；
- 本轮所有改动集中在任务中心页，与 Part 1（最近任务卡片）无代码耦合，可独立交付；
  若线上出问题，按文件级回退即可，不影响其他页面。
