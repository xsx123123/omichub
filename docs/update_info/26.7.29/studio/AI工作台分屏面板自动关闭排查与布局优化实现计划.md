> 也可作为人工开发的需求文档。

## 一、背景与目标

| 项目 | 说明 |
| --- | --- |
| 产品 | 星尘 AI 工作台前端（Vue3 + Pinia + SSE 流式渲染；顶部"对话 / 分屏 / 代码"视图切换） |
| 问题⑦（Bug） | 用户手动打开的分屏/代码查看面板，在 AI 流式回复期间被自动关闭/切回对话视图 |
| 问题⑧（布局） | a) 代码面板底部终端默认高度太小，看不了几行输出；b) 右侧状态栏（结果产物/待办计划/沙盒状态）太宽，挤压主区域 |
| 目标 | 视图状态对用户"粘性"；终端默认可视行数明显增加且可拖拽记忆；状态栏收窄、主区域变宽 |

**总原则：问题⑦是 Bug 排查——先定位根因再动手；问题⑧是布局优化——落成具体数值。**
不改路由、不改 SSE 解析、不改消息数据结构。

## 二、问题⑦：分屏代码面板自动关闭（Bug）

### 2.1 症状与复现

**症状**：AI 工作台支持「对话 / 分屏 / 代码」视图切换，用户在「分屏」或「代码」
模式下可打开右侧代码面板查看工作区文件（如 vcf_filter.py）。但只要 AI 仍在流式
回复（SSE 持续推送 chunk），代码面板就会被自动关闭 / 视图被切回「对话」，
用户无法一边看 AI 输出一边对照代码。

**复现路径**：

1. 在 AI 工作台发起一个会生成代码的任务（如"帮我写一个 VCF 过滤脚本"）；
2. AI 流式回复期间，点击顶部「分屏」（或「代码」）打开右侧代码面板，
   点开工作区中的脚本文件查看；
3. 观察到：下一个或几个 SSE chunk 到达后，代码面板自动关闭 / 视图被切回「对话」；
4. **预期行为**：除非用户主动点击切换，视图模式与代码面板打开状态应保持不变。

### 2.2 疑似根因清单（按概率排序）

| # | 疑似根因 | 典型特征 | 验证方式 |
| --- | --- | --- | --- |
| 1 | 视图状态被流式更新覆盖：消息状态机（pending→streaming→done）的 watch / SSE 回调里把 viewMode 重置回 'chat' 或把面板 open 置 false | 每个 chunk 或状态流转时必现 | 全局搜索 viewMode / activeTab / panelOpen 的赋值点，在流式回调与 watch 中断点 |
| 2 | "跟随 AI"类自动逻辑强制切视图：流式期间自动滚动/切换视图，误伤用户手动打开的分屏 | 与"跟随 AI"开关状态相关 | 检查跟随逻辑触发条件；关闭"跟随 AI"后复现是否消失 |
| 3 | 组件卸载重建丢状态：流式期间 key 变化 / v-if 切换导致持有视图状态的父组件被销毁重建 | 面板状态存在组件内 ref 中 | 检查视图状态存放层级；观察组件是否被卸载（onUnmounted 日志） |
| 4 | SSE 事件携带视图指令：后端事件带 view / layout / panel 字段，前端无条件执行切换 | 特定事件类型到达时触发 | 打印流式事件原始内容，检查字段消费逻辑 |

> 注：#1 与 #2 最可能，且与本项目"吸底滚动跟随用户意图"（第三部分）是同一类
> 设计缺陷——**自动逻辑没有让位于用户手动操作**。

### 2.3 修复方案

**核心原则：用户手动操作优先，视图状态对用户粘性。**

1. 视图模式（chat / split / code）与代码面板 open 状态，只有用户显式点击
   「对话 / 分屏 / 代码」或关闭按钮才改变；SSE 流式事件、消息状态流转一律不得重置；
2. 用户手动切换视图后置"用户已接管视图"标记（与对话区 isUserScrolling 同思路），
   自动逻辑执行前先检查该标记；
3. 视图状态上移到 Pinia / 会话级状态，组件重建不丢状态；
4. 若产品确实需要"AI 生成新文件时自动打开代码面板"，只在对应工具事件到达时
   触发一次，且不得关闭用户已手动打开的面板；
5. 防回归：补测试——模拟流式期间手动打开分屏，断言视图不再被切回。

## 三、问题⑧：终端高度与状态栏宽度（布局优化）

### 3.1 终端面板默认高度

**现状（截图实证）**：代码面板底部的终端（终端 · BASH）展开后默认高度只占所在面板
约 1/5，仅剩 2~3 行可视，看输出需要频繁滚动。

**修改 spec**：

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 默认展开高度 | 约占容器 15~20% | 容器高度的 **40%**，且不小于 `280px`、不大于 `60%` |
| 高度调节 | 不可调 | 顶部边界加拖拽把手（hover 显示 `col-resize` 指示条），拖拽范围 `160px` ~ 容器高度 `70%` |
| 高度记忆 | 无 | 调整后写入 `localStorage`，下次打开自动恢复 |
| 动效 | — | 展开/折叠过渡 `200ms`；拖拽实时跟手；不影响终端滚动位置与连接状态 |

### 3.2 右侧状态栏宽度

**现状（截图实证）**：右侧栏（结果产物 / 待办计划 / 沙盒状态）宽度约 300px+，
中间对话区与代码区被明显挤压。

**修改 spec**：

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 栏宽 | 约 300px+ | 收窄至 **240~260px** 固定区间（按现有栅格取最近值） |
| 内容适配 | — | 待办计划条目文字自然换行不溢出；CPU/内存进度条正常显示；"工作区 / 会话 ID"等键值对不截断（超长值省略号 + title 提示） |
| 可选增强 | — | 左缘加拖拽把手支持 220~360px 微调并记忆；做不到就用固定 240~260px，不要两个都不做 |
| 释放空间 | — | 收窄释放的宽度让给中间对话/代码主区域 |

**约束**：只改工作台布局样式，不影响 AI 助手对话页与其他页面；
窗口宽度 ≥1280px 时布局不破损、无横向滚动条。

## 四、完整提示词（可直接投喂编码 Agent）

### 提示词一：排查「分屏代码面板自动关闭」Bug

```text
你是一名资深前端调试工程师。项目技术栈：Vue3 + Pinia + SSE 流式渲染（星尘 AI 工作台）。

## Bug 症状

AI 工作台支持「对话 / 分屏 / 代码」视图切换，用户在「分屏」或「代码」模式下可以
打开右侧代码面板查看工作区文件（如 vcf_filter.py）。但只要 AI 仍在流式回复
（SSE 持续推送 chunk），这个代码查看面板就会被自动关闭 / 自动切回对话视图，
用户无法一边看 AI 输出一边对照代码。

## 复现路径

1. 在 AI 工作台发起一个会生成代码的任务（如"帮我写一个 VCF 过滤脚本"）；
2. AI 流式回复期间，点击顶部「分屏」（或「代码」）打开右侧代码面板，
   点开工作区中的脚本文件查看；
3. 观察到：下一个或几个 SSE chunk 到达后，代码面板自动关闭 / 视图被切回「对话」；
   预期行为：除非用户主动点击切换，视图模式与代码面板打开状态应保持不变。

## 排查方向（先定位根因再动手，逐层验证）

1. 视图状态是否被流式更新覆盖
   - 检查视图模式（chat / split / code）与代码面板 open 状态存放在哪里
     （组件内 ref / Pinia store / 路由 query）；
   - 全局搜索 SSE 消息回调、消息状态机（pending → streaming → done）的
     watch / subscribe，确认是否有代码在流式期间把 viewMode 重置回 'chat'
     或把面板 open 置为 false。

2. "跟随 AI" 等自动行为是否强制切视图
   - 检查是否存在"跟随 AI 输出"之类的逻辑，在流式期间强制滚动/切换视图，
     误伤了用户手动打开的分屏状态；
   - 用户手动切换视图后，应置"用户已接管视图"标记，自动逻辑不得再改视图，
     与对话区"吸底滚动跟随用户意图"的策略对齐（用户手动操作优先）。

3. 组件是否被卸载重建
   - 检查消息列表/视图容器在流式期间是否有 key 变化、v-if 切换导致
     包含视图状态的父组件被销毁重建，状态随之丢失；
   - 确认面板 open 状态是否挂在会被重建的组件内部（应上移到 store 或
     会话级状态中，组件重建不丢状态）。

4. SSE 事件是否携带视图指令
   - 打印流式事件原始内容，确认后端事件里是否带 view / layout / panel 字段，
     前端是否对每个事件无条件执行了视图切换。

## 修复要求

- 视图模式与代码面板 open 状态对用户"粘性"：只有用户显式点击「对话 / 分屏 / 代码」
  或关闭按钮才改变；SSE 流式事件、消息状态流转一律不得重置；
- 若确实需要"AI 生成新文件时自动打开代码面板"的产品行为，也只在对应工具事件
  到达时触发一次，且不得关闭用户已手动打开的面板；
- 状态存放位置改为组件重建不丢失的层级（Pinia / 会话级），并补防回归：
  模拟流式期间手动打开分屏，断言视图不再被切回。

## 交付

- 根因说明（哪一层、哪段代码导致面板被关闭）；
- 最小化修复 diff 说明；
- 验证步骤：流式全程打开分屏查看代码，面板保持稳定不自动关闭。
```

### 提示词二：终端高度 + 右侧状态栏宽度优化

```text
你是一名资深前端工程师。项目为星尘 AI 工作台前端（Vue3 + 现有样式体系）。

任务：在现有 AI 工作台页面基础上做布局优化。先阅读现有代码（工作台布局组件、
终端面板组件、右侧状态栏组件及相关样式文件），理解当前实现后再修改。
禁止推倒重写，禁止改动路由、功能逻辑和无关组件。

## 需要修改的问题（逐条执行）

1. 终端面板默认高度太小
   现状：代码面板底部的终端（终端 · BASH）展开后默认高度只占所在面板很小的比例，
   看不了几行输出，用户需要频繁滚动。
   - 默认展开高度调整为所在容器高度的 40%（且不小于 280px、不大于 60%）；
   - 终端顶部边界加拖拽把手（鼠标 hover 显示 col-resize 指示条），
     支持用户上下拖拽调节高度，范围 160px ~ 容器高度的 70%；
   - 用户调整后的高度存入 localStorage，下次打开自动恢复；
   - 展开/折叠/拖拽过程平滑（过渡 200ms 或拖拽实时跟手），不影响终端内
     滚动位置与连接状态。

2. 右侧状态栏宽度太宽
   现状：右侧栏（结果产物 / 待办计划 / 沙盒状态）占用宽度偏大，挤压了中间
   对话区与代码区。
   - 宽度从现状收窄至 240~260px 固定区间（按现有栅格取最近值）；
   - 收窄后自查内容适配：待办计划条目文字自然换行不溢出，CPU/内存进度条、
     "工作区 / 会话 ID" 等键值对不截断（超长值可省略号 + title 提示）；
   - 如成本允许，右侧栏左缘加拖拽把手支持 220~360px 内微调并记忆，做不到
     就用固定 240~260px，不要两个都不做；
   - 收窄释放的宽度让给中间对话/代码主区域。

## 全局约束

- 只改工作台布局样式，不影响 AI 助手对话页与其他页面；
- 风格与平台现有视觉基调一致（浅色卡片、圆角、浅紫强调色）；
- 不同窗口宽度下（≥1280px）布局不破损，不出现横向滚动条。

## 验收标准（逐条自检）

- [ ] 终端默认展开即可视行数明显增加（默认高度 ≥ 容器 40%），可拖拽并记忆；
- [ ] 右侧状态栏收窄至 240~260px，内部内容无溢出、无截断；
- [ ] 中间对话区与代码区可用宽度明显变大；
- [ ] 终端连接、清空、折叠，状态栏各面板折叠等功能无回归。

完成后简述：每个问题对应的修改文件与关键属性改动。
```

## 五、验收 checklist（汇总）

- [ ] 流式全程打开分屏/代码面板查看文件，面板稳定不自动关闭、不切回对话视图；
- [ ] 只有用户显式点击才切换视图；"跟随 AI"开关状态不影响该结论；
- [ ] 新增防回归测试：流式期间手动打开分屏，断言视图保持；
- [ ] 终端默认高度 ≥ 容器 40%（≥280px），默认可视行数明显增加；
- [ ] 终端可拖拽调高/调低（160px ~ 70%），刷新后恢复用户设定高度；
- [ ] 右侧状态栏宽度 ∈ 240~260px，待办计划/进度条/键值对无溢出无截断；
- [ ] 中间对话区与代码区可用宽度明显变大，≥1280px 窗口下无横向滚动；
- [ ] 终端连接/清空/折叠、状态栏各面板折叠等功能零回归。

## 六、排期与风险

| 优先级 | 事项 | 建议工期 |
| --- | --- | --- |
| P0 | 分屏面板自动关闭根因定位 + 视图状态粘性修复 + 防回归测试 | 0.5 ~ 1 天 |
| P1 | 终端默认高度 + 拖拽把手 + localStorage 记忆 | 0.5 天 |
| P1 | 右侧状态栏收窄 + 内容适配（可选拖拽增强） | 0.5 天 |

**风险与回退**：

- 视图状态上移 Pinia 触碰面大 → 先在 store 新增独立 view 模块，组件内状态做
  代理转发，避免一次性改所有引用点；
- "用户已接管视图"标记可能影响既有"跟随 AI"体验 → 标记只在用户手动切换视图时
  置位，新会话/新任务开始时重置，不改变默认跟随行为；
- 终端拖拽与终端组件（如 xterm）resize 联动 → 拖拽结束调用终端 fit/resize，
  避免内容错位；拖拽库不引入新依赖，用原生鼠标事件实现；
- 状态栏收窄后待办计划长文本体验下降 → 换行 + 省略号 + title 兜底，不接受横向滚动。
