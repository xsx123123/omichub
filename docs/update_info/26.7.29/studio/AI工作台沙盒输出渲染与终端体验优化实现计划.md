# AI 工作台沙盒输出渲染与终端体验优化实现计划

> 来源：2026-07-29 截图反馈（沙盒执行结果块乱码 + 终端提示符/Tab 补全问题）。
> 适用对象：可直接投喂给 AI 编程助手（Cursor / Claude Code / kimi code 等）执行，
> 也可作为人工开发的需求文档。
> 关联文档：本文件为《AI 对话前端问题修复提示词与优化文档》第六部分的独立详版。

## 一、背景与目标

| 项目 | 说明 |
| --- | --- |
| 产品 | 星尘 AI 工作台（Vue3 前端 + 沙盒执行环境 + 内嵌终端） |
| 问题⑨ | Agent 在沙盒运行脚本的结果，在前端"输出"块中渲染乱码：换行被吞、空格塌陷、对齐全毁 |
| 问题⑩ | 内嵌终端：提示符显示字面量 `\w` 而非真实当前目录；Tab 键无法补全命令/文件名 |
| 影响范围 | 问题⑨影响所有沙盒执行结果的可读性；问题⑩影响终端日常可用性 |
| 目标 | 执行结果原样保真呈现；终端提示符显示真实目录、Tab 补全可用 |

**总原则**：问题⑨是纯前端渲染修复；问题⑩涉及终端启动链路（可能跨前后端/容器启动
命令），先定位再改。两者都不改 SSE 协议、不改沙盒执行逻辑本身。

## 二、问题⑨：沙盒执行结果渲染乱码

### 2.1 症状（截图实证）

Agent 运行 VCF 过滤脚本测试，实际输出约 20+ 行、带 `──────` 分隔线和空格对齐的
统计表格。前端"输出"块中：

- 折叠标签显示 **"输出 1 行"**——多行输出被识别为 1 行，说明换行符 `\n` 在渲染层
  被吞掉；
- 连续空格塌陷为单个空格，`总变异数:       10` 这类对齐列全部错位；
- `──────` 分隔线与文字连成一片，输出像一段普通段落，可读性极差。

### 2.2 根因判断（高置信度）

输出文本被当作**普通 HTML 段落**渲染：HTML 默认 `white-space: normal` 会把换行符
和连续空格全部折叠。叠加**比例字体**（非等宽），即使空格保留也无法对齐。

| # | 根因 | 验证方式 |
| --- | --- | --- |
| 1 | 输出容器未设 `white-space: pre / pre-wrap`，`\n` 与连续空格被 HTML 折叠 | 检查输出块 DOM 的 computed style |
| 2 | 输出未用等宽字体，列对齐依赖的等宽假设不成立 | 检查 font-family |
| 3 | （次要）行数统计按渲染后文本计算，"输出 1 行"是 #1 的衍生现象 | 修复 #1 后应自动变为正确行数 |

### 2.3 修复 spec

- 输出块容器：`white-space: pre-wrap; word-break: break-all;`
  （保留换行与空格，超长行软换行不撑破卡片）；
- 字体：等宽字体栈，如
  `font-family: ui-monospace, "SF Mono", "Cascadia Mono", Menlo, Consolas, monospace`，
  字号 12~13px，行高 1.5~1.6；
- 中文 + 等宽混排：确认中文字符宽度为英文字符 2 倍（full-width），
  对齐分隔线（`─` box-drawing 字符）需字体支持，缺字形时给 fallback；
- 深色输出块样式与代码块一致（背景、圆角、padding 沿用代码执行卡片规范，
  见第四部分深色描边过渡口径）；
- 行数统计按原始输出的 `\n` 计数，不按渲染结果计数；
- 超长输出（>500 行）保留现有折叠/截断逻辑，只改渲染不改数据。

## 三、问题⑩：终端提示符 `\w` 未解析 + Tab 补全失效

### 3.1 症状（截图实证）

- 提示符显示 `studio@omicbox:\w$`——`\w` 是 bash PS1 的"当前工作目录"转义符，
  被原样打印说明它**没被 bash 解析**，而是作为字面字符进入了 PS1；
  真实目录（`pwd` 验证为 `/workspace/scripts`）完全不显示；
- 按 Tab 无法补全文件名/命令。

### 3.2 疑似根因清单（按概率排序）

| # | 疑似根因 | 典型特征 | 验证方式 |
| --- | --- | --- | --- |
| 1 | PS1 在多层 shell / 启动命令传递中被双重转义：如 `bash -c "PS1='...\w...' bash"`，外层 shell 先吃掉一层转义，内层拿到字面 `\w` | `\w` 原样显示，其他转义符（\u \h）却正常——截图中 `studio@omicbox` 显示正常、唯独 `\w` 是字面量，提示 PS1 可能是分段拼接/部分被转义 | 在终端里执行 `echo $PS1`，看实际值是 `\w` 还是已被转义 |
| 2 | shell 以非交互模式启动（如 `sh`、或 `bash` 无 `-i`），readline 未启用 → Tab 不补全；同时非交互模式可能读取不同的 PS1 来源 | Tab 完全无反应，`echo $0` 显示 sh 或 `$-` 不含 `i` | 终端执行 `echo $0`、`echo $-`、`bind -v \| head` 确认 readline |
| 3 | 前端终端组件（如 xterm.js）拦截了 Tab 键用于焦点切换，未透传给 PTY | Tab 触发的是浏览器焦点移动而非补全 | 在 xterm 的 onKey / attachCustomKeyEventHandler 里查 Tab 处理 |
| 4 | PTY 未分配（命令走普通 pipe 而非伪终端），shell 退化为非交互 | 终端无控制字符回显、无颜色 | 检查后端 spawn 命令是否分配 pty（如 `script -qc` / node-pty / docker exec -t） |

### 3.3 修复 spec

**提示符（根因 #1）**：

- 定位 PS1 的设置位置（容器镜像 bashrc / 后端启动命令 / 前端连接参数），
  修正转义层级：推荐在容器内 `/etc/bash.bashrc` 或 `~/.bashrc` 里用**单引号**
  固定 `PS1='studio@omicbox:\w\$ '`，启动命令不再内联 PS1，杜绝多层转义；
- 修复后提示符应显示真实目录，如 `studio@omicbox:/workspace/scripts$`
  （或 `~/scripts`，取决于 \w vs \W 的选择，建议保留 `\w` 全路径）；
- 目录变化（cd）后提示符同步更新。

**Tab 补全（根因 #2/#3/#4）**：

- 确认 shell 以**交互式 bash + 分配 PTY** 启动（如 `bash -i` 或登录 shell，
  后端 spawn 必须分配伪终端）；
- 若前端 xterm.js 有自定义按键处理，确认 Tab（`keyCode 9`）透传给 PTY，
  不被 `preventDefault` 后用于焦点切换；
- 修复后：Tab 补全文件名/目录名/命令，连续按两次 Tab 列出候选；
- 顺手确认：`bash-completion` 在容器内可用则补全更智能，没有则 bash 内建补全
  也应可用，二者至少保证其一。

### 提示词一：修复沙盒执行结果渲染乱码

```text
你是一名资深前端工程师。项目为星尘 AI 工作台前端（Vue3）。

## Bug 症状

Agent 在沙盒中运行脚本后，执行结果在前端"输出"块中渲染乱码：
```

### 提示词二：修复终端提示符 `\w` 与 Tab 补全

```text
你是一名资深全栈调试工程师。项目为星尘 AI 工作台（Vue3 前端 + 沙盒容器 +
内嵌终端，疑似 xterm.js + 后端 PTY）。

## Bug 症状

1. 终端提示符显示为 studio@omicbox:\w$ —— \w 是 bash PS1 的当前目录转义符，
   被原样打印说明未被 bash 解析；真实目录（如 /workspace/scripts）不显示；
2. 按 Tab 键无法补全文件名/命令。

## 排查方向（先定位根因再动手）

1. PS1 转义链路：在终端执行 echo $PS1 看实际值。怀疑 PS1 在多层 shell/启动命令
   传递中被双重转义（如 bash -c 内联 PS1 时外层吃掉一层转义）。注意截图中
   \u@\h 部分（studio@omicbox）显示正常、唯独 \w 是字面量，提示 PS1 可能是
   分段拼接或部分被转义，请完整还原 PS1 从设置到生效的每一层传递。
2. shell 启动方式：执行 echo $0、echo $-，确认是否为交互式 bash（$- 含 i）；
   若启动的是 sh 或非交互 bash，readline 不工作 → Tab 不补全。
3. PTY 分配：检查后端 spawn 终端的命令是否分配了伪终端（node-pty /
   docker exec -t / script -qc 等）；普通 pipe 会让 shell 退化为非交互。
4. 前端按键拦截：检查终端组件（xterm.js）的 onKey / attachCustomKeyEventHandler，
   确认 Tab（keyCode 9）被透传给 PTY，未被 preventDefault 后用于焦点切换。

## 修复要求

1. 提示符：PS1 改在容器内 ~/.bashrc 或 /etc/bash.bashrc 用单引号固定
   （如 PS1='studio@omicbox:\w\$ '），启动命令不再内联 PS1，杜绝多层转义；
   修复后提示符显示真实当前目录，cd 后同步更新；
2. Tab 补全：确认以交互式 bash + 分配 PTY 启动；前端 Tab 键透传；
   修复后 Tab 可补全文件名/目录/命令，双击 Tab 列出候选；
   容器内有 bash-completion 则启用，没有则保证 bash 内建补全可用；
3. 不破坏现有终端连接、清屏、滚动、ANSI 颜色渲染。

## 交付

- 每个症状各自的根因说明（哪一层、为什么）；
- 最小化修复 diff 说明；
- 验证步骤：提示符显示真实目录且 cd 后更新；Tab 补全可用。
```

- [ ] 沙盒执行结果按原始换行/空格原样呈现，对齐表格列对齐正确；
- [ ] 行数统计显示真实行数（不再出现多行输出标"输出 1 行"）；
- [ ] 输出块等宽字体、中文全宽、`─` 分隔线不缺字形；
- [ ] 超长行软换行不撑破卡片，超长输出折叠逻辑不变；
- [ ] 终端提示符显示真实当前目录（如 `studio@omicbox:/workspace/scripts$`），
      `cd` 后同步更新；
- [ ] Tab 补全文件名/目录/命令可用，双击 Tab 列出候选；
- [ ] 终端连接、清屏、ANSI 颜色、滚动无回归。

## 六、排期与风险

| 优先级 | 事项 | 建议工期 |
| --- | --- | --- |
| P0 | 输出块 pre-wrap + 等宽字体 + 行数统计修复 | 0.5 天 |
| P0 | PS1 转义链路修复（bashrc 单引号固定） | 0.5 天（含容器镜像更新） |
| P1 | 交互式 bash + PTY 确认、Tab 透传修复 | 0.5 ~ 1 天 |

**风险与回退**：

- 修改容器 bashrc 需更新镜像 → 镜像未更新前可先用启动命令兜底导出正确 PS1
  作为过渡方案，但正式修复必须在镜像内；
- pre-wrap 导致超长行撑高输出块 → 已有 >500 行折叠逻辑兜底，单行超长靠
  word-break: break-all 软换行；
- Tab 透传后浏览器焦点切换习惯变化 → 终端聚焦时 Tab 归终端，失焦时归浏览器，
  符合所有主流 Web IDE 约定。
