

# 多 Agent 单细胞分析智能系统设计方案

## 1. 项目概述

本项目旨在构建一个面向单细胞 RNA 测序（scRNA-seq）数据分析的多 Agent 智能协作系统。系统以用户整理的单细胞分析全流程笔记为核心知识资产，通过结构化的知识库管理与多 Agent 协同编排，实现从原始数据质控到生物学解释的全流程自动化/半自动化分析。

### 1.1 核心目标

- **知识资产化**：将个人积累的单细胞分析经验转化为可检索、可验证、可进化的结构化知识库
- **流程标准化**：通过专家审核机制确保分析流程的科学性与可重复性
- **智能协作化**：多 Agent 分工协作，模拟真实实验室中的"分析团队"工作模式
- **决策透明化**：每个分析步骤提供置信度评估与决策依据，支持人机协同

## 3. 知识库构建方案

### 3.1 知识来源

| 来源 | 内容 | 处理方式 | 优先级 |
|------|------|----------|--------|
| 个人笔记 | 单细胞分析全流程经验 | 结构化解析 → 决策图谱 | P0（最高）|
| 经典文献 | 已发表的方法学论文 | 摘要提取 → 方法卡片 | P1 |
| 在线教程 | Scanpy/Seurat 官方文档 | 关键步骤提取 | P1 |
| 联网搜索 | 最新方法/参数建议 | 实时检索，结果缓存 | P2 |
| 模型知识 | GPT-4/Claude 内置知识 | 兜底推理，需验证 | P3 |

### 3.2 笔记结构化转换流程

```
原始笔记（Markdown）
    │
    ▼
┌─────────────────┐
│ 1. 章节解析      │  → 识别分析阶段（质控→降维→聚类→注释→...）
│ 2. 步骤提取      │  → 提取每个阶段的具体操作、参数、判断标准
│ 3. 条件标注      │  → 标注"如果...则..."的决策逻辑
│ 4. 依赖建模      │  → 建立步骤间的输入输出关系
│ 5. 置信度标注    │  → 专家标注每个流程的可靠性等级
└─────────────────┘
    │
    ▼
结构化知识图谱（JSON/YAML + 向量嵌入）
```

### 3.3 知识库双轨存储

#### A. 向量检索库（语义匹配）
- **用途**：用户提问的语义理解与相关流程召回
- **技术**：文本分块 → Embedding（如 text-embedding-3-large）→ 向量数据库（如 ChromaDB/Milvus）
- **更新**：新增笔记时自动重新嵌入

#### B. 决策图谱库（流程编排）
- **用途**：Agent 执行分析时的步骤导航与参数选择
- **结构**：有向无环图（DAG），节点 = 分析步骤，边 = 条件依赖
- **示例节点**：
  ```json
  {
    "node_id": "QC_doublet_removal",
    "name": "双细胞去除",
    "category": "质控",
    "methods": ["Scrublet", "DoubletFinder", "ScDblFinder"],
    "selection_criteria": {
      "default": "ScDblFinder",
      "if_large_dataset": "DoubletFinder",
      "if_known_cell_types": "Scrublet"
    },
    "parameters": {
      "expected_doublet_rate": "0.05-0.1 * (n_cells / 1000)"
    },
    "expert_confidence": 0.92,
    "last_reviewed": "2026-07-15",
    "reviewer": "单细胞分析专家"
  }
  ```

## 4. Agent 角色定义

### 4.1 主控 Agent（Orchestrator）

**职责**：
- 接收用户请求，识别分析意图（如"我要做细胞亚群鉴定"、"帮我看看这批数据的质量"）
- 将复杂任务拆解为子任务序列
- 调度各子 Agent 并行或串行执行
- 整合子 Agent 结果，生成最终报告
- 评估整体置信度，决定是否触发人工复核

**核心能力**：
- 意图分类：数据质控 / 探索性分析 / 差异分析 / 轨迹推断 / 细胞通讯 / ...
- 任务依赖解析：识别哪些步骤可以并行，哪些必须串行
- 异常熔断：当某个 Agent 返回低置信度结果时，暂停流程并告警

### 4.2 知识检索 Agent（Knowledge Retriever）

**职责**：
- 根据当前分析步骤，从知识库中检索最相关的分析流程
- 执行分层检索策略（见第 5 节）
- 对检索结果进行相关性排序与去重
- 当知识库无匹配时，触发联网搜索或模型推理

**检索策略**：
1. **精确匹配**：决策图谱中的节点 ID 匹配
2. **语义匹配**：向量库中的相似度 Top-K 召回
3. **上下文增强**：结合当前数据特征（物种、样本数、测序平台）过滤

### 4.3 分析执行 Agent（Pipeline Executor）

**职责**：
- 根据检索到的分析流程，生成可执行代码（Python/R）
- 调用单细胞分析工具（Scanpy、Seurat、Monocle 等）
- 执行具体计算任务（PCA、UMAP、聚类、差异基因分析等）
- 捕获执行日志与中间结果

**类型细分**（可选扩展）：
- **质控 Agent**：负责细胞过滤、基因过滤、双细胞检测
- **降维 Agent**：负责 PCA、UMAP、t-SNE 等降维可视化
- **聚类 Agent**：负责聚类算法选择与参数优化
- **注释 Agent**：负责 marker 基因匹配与细胞类型注释
- **高级分析 Agent**：负责轨迹推断、细胞通讯、空间转录组分析

### 4.4 验证 Agent（Validator）

**职责**：
- 对每个分析步骤的结果进行科学性验证
- 检查是否符合知识库中的标准（如"线粒体基因比例应 < 10%"）
- 识别异常结果（如聚类数过多/过少、marker 基因表达异常）
- 生成验证报告，标注通过/警告/失败

**验证维度**：
- **技术验证**：代码是否运行成功、输出格式是否正确
- **生物学验证**：结果是否符合已知生物学规律
- **统计验证**：p 值、效应量、批次效应等指标是否合理

### 4.5 专家反馈 Agent（Expert Feedback）

**职责**：
- 当系统遇到知识库未覆盖的新场景时，记录问题并请求专家输入
- 将专家反馈结构化后入库
- 定期（如每周）生成"知识库更新建议报告"
- 追踪知识库中流程的"保质期"，提醒专家复核过时内容

## 5. 分层检索策略（核心机制）

当用户提问或 Agent 需要决策时，按以下优先级逐级检索：

### 5.1 第一层：结构化知识库（本地专家知识）

**触发条件**：所有分析请求

**检索方式**：
- 在决策图谱中匹配当前分析阶段与数据特征
- 向量语义检索相关笔记段落
- 返回：已审核的标准操作流程（SOP）+ 参数建议 + 注意事项

**成功标准**：
- 匹配度 > 0.85（语义相似度）
- 数据特征兼容（如物种、测序平台匹配）
- 知识未过期（last_reviewed < 6 个月）

**输出**：
- 推荐分析流程（含具体步骤、参数、代码模板）
- 置信度评分（基于专家审核等级 + 数据匹配度）
- 引用来源（笔记章节 / 文献 DOI）

### 5.2 第二层：联网搜索（实时知识补充）

**触发条件**：
- 第一层检索失败（无匹配或匹配度 < 0.85）
- 用户明确要求"最新方法"
- 验证 Agent 发现结果与知识库预期不符

**检索策略**：
- 自动生成搜索 query（如"scRNA-seq batch correction 2026 best practice"）
- 优先检索：bioRxiv、Nature Methods、Cell、Genome Biology 等权威来源
- 结果过滤：仅保留近 2 年文献，优先高被引/高影响因子

**结果处理**：
- 提取方法摘要、参数建议、代码链接
- 标记为"未审核"，不直接入库
- 提交给专家反馈 Agent，等待审核后入库

### 5.3 第三层：模型内部知识（通用推理兜底）

**触发条件**：
- 前两层均失败
- 需要通用生物学推理（如"这个基因的功能是什么"）
- 需要代码生成但无特定模板

**使用原则**：
- 明确标注"基于模型内部知识，未经验证"
- 置信度自动降级（最高 0.6）
- 必须触发人工复核标记
- 结果不入库，仅作为临时建议

### 5.4 检索决策流程图

```
用户提问 / 分析需求
    │
    ▼
┌─────────────────┐
│ 第一层：本地知识库 │
│ 专家审核流程      │
└─────────────────┘
    │
    ├─ 匹配成功（置信度 ≥ 0.85）→ 使用知识库流程，标记高置信度
    │
    └─ 匹配失败 ─────────────────────────┐
                                          ▼
                              ┌─────────────────┐
                              │ 第二层：联网搜索  │
                              │ 实时补充最新方法  │
                              └─────────────────┘
                                  │
                                  ├─ 检索成功 → 使用搜索结果，标记"待审核"
                                  │
                                  └─ 检索失败 ─────────────┐
                                                           ▼
                                               ┌─────────────────┐
                                               │ 第三层：模型知识  │
                                               │ 通用推理兜底      │
                                               └─────────────────┘
                                                   │
                                                   └─ 生成建议，标记"低置信度，需人工复核"
```

## 6. 多 Agent 协作流程示例

### 场景：用户上传小鼠脑组织 scRNA-seq 数据，请求"帮我鉴定细胞亚群"

#### Step 1：主控 Agent 任务拆解

```
用户请求："帮我鉴定细胞亚群"
    │
    ▼
主控 Agent 拆解：
  1. 数据质控（质控 Agent）
  2. 降维与可视化（降维 Agent）
  3. 聚类分析（聚类 Agent）
  4. 细胞类型注释（注释 Agent）
  5. 结果验证（验证 Agent）
```

#### Step 2：知识检索 Agent 并行检索

各子 Agent 同时向知识检索 Agent 请求对应阶段的知识：

| 子 Agent | 检索 Query | 预期返回 |
|----------|-----------|----------|
| 质控 Agent | "小鼠脑组织 scRNA-seq 质控标准" | 线粒体阈值、最小基因数、双细胞检测方法 |
| 降维 Agent | "脑组织数据降维最佳实践" | PCA 组件数、UMAP 参数、批次效应校正 |
| 聚类 Agent | "脑组织细胞聚类分辨率" | 推荐分辨率、Leiden/Louvain 选择 |
| 注释 Agent | "小鼠脑细胞类型 marker 基因" | 已知 marker 列表、注释层级 |

#### Step 3：分析执行 Agent 执行计算

各子 Agent 按依赖关系执行：

```
质控 Agent ──► 降维 Agent ──► 聚类 Agent ──► 注释 Agent
    │              │              │              │
    └──────────────┴──────────────┴──────────────┘
                           │
                           ▼
                    验证 Agent（串行验证每一步）
```

#### Step 4：验证 Agent 结果校验

- 质控：线粒体比例 < 10%？双细胞率 < 8%？→ 通过
- 降维：UMAP 是否显示明显批次效应？→ 警告（建议 Harmony 校正）
- 聚类：Silhouette score > 0.5？→ 通过
- 注释：已知 marker 表达是否符合预期？→ 通过（但发现一个新亚群，无匹配 marker）

#### Step 5：主控 Agent 整合与决策

```
整合结果：
  - 已鉴定 12 个主要细胞类群
  - 其中 11 个与已知脑组织类型匹配（高置信度）
  - 1 个新亚群（低置信度，可能为双细胞或新类型）

决策：
  - 高置信度结果：直接呈现给用户
  - 低置信度结果：标记"建议人工复核"，提供备选解释
  - 触发专家反馈：记录新亚群特征，请求专家审核
```

## 7. 创新点提炼（比赛定位）

### 7.1 核心创新："自进化专家知识库 + 多 Agent 置信度协同"

| 创新维度 | 传统方案 | 本方案 |
|----------|----------|--------|
| 知识来源 | 静态文档 / 通用预训练 | 个人专家经验 → 结构化知识库 → 持续进化 |
| 检索策略 | 单次向量检索 | 分层三级检索（本地→联网→模型），逐级降级 |
| Agent 协作 | 单 Agent 串行或简单路由 | 多 Agent 并行协作 + 验证 Agent 交叉校验 |
| 结果可信度 | 黑盒输出 | 每步置信度评分 + 不确定性量化 + 人机协同触发 |
| 知识更新 | 手动维护 | 自动检测冲突 → 专家审核 → 结构化入库 |

### 7.2 差异化亮点

1. **领域深度绑定**：不是通用 RAG，而是深度绑定单细胞分析领域的"分析决策图谱"
2. **专家审核闭环**：知识库中的每条流程都有"保质期"和"审核记录"，过期自动告警
3. **验证 Agent 机制**：像实验室中的"第二人复核"，防止单 Agent 的幻觉或参数误设
4. **失败可追溯**：当分析结果异常时，可回溯到具体步骤、具体知识库条目、具体参数

### 7.3 技术壁垒

- **笔记→决策图谱的自动解析**：需要领域特定的 NLP 解析器，将非结构化笔记转化为可执行 DAG
- **置信度量化模型**：基于数据特征、知识库匹配度、历史成功率的多维置信度评估
- **Agent 间通信协议**：定义标准的结果格式、错误码、置信度传递机制

## 9. 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 笔记结构化解析不准确 | 知识库质量差 | 先人工标注 20% 样本训练解析器，逐步自动化 |
| 多 Agent 通信复杂 | 调试困难 | 定义严格的输入输出 Schema，使用消息队列解耦 |
| 联网搜索结果质量不稳定 | 引入错误知识 | 限制来源白名单，结果需验证 Agent 过滤 |
| 模型幻觉导致错误分析 | 科学结论不可靠 | 强制验证 Agent 校验，高风险步骤必须人工确认 |
| 比赛时间不足 | 无法完成全部功能 | 优先实现核心链路（质控→聚类→注释），高级分析作为扩展 |

| 组件 | 推荐方案 | 备选方案 |
|------|----------|----------|
