# 协作室（AgentTeams 多助手）页面视觉优化实现计划

> **任务类型**：已有页面视觉/样式优化（不是重新设计）
> **优化对象**：协作室页面（左侧 Case 列表栏 + 右侧会话/空状态区 + 底部输入框）
> **参考基准**：星尘 AI 首页（`HomeView.vue`）+ `fontend.md`（OmicHub 前端设计系统与实现规范）+ AgentTeams 架构图与 AgentTeams 客户端聊天页面
> **铁律**：在现有协作室页面基础上修改，禁止推倒重写，禁止改动路由、创建 Case 逻辑和无关组件。
>
> **第二轮更新（2026-08-13）**：用户补充了 AgentTeams 平台架构图（用户入口 → Worker 团队多智能体 → 观测/评估/调优）、管理平台架构图（Team Pool + RBAC + 业务团队按需接入）和 AgentTeams 客户端真实聊天页面截图（Matrix/Element 风格 IM：左侧房间列表 + 右侧聊天时间线，Manager 管家智能体主导对话）。据此追加 **Part 2（§8～§11）**：协作室页面的交互模型从"Case 列表 + 空状态"进一步对齐 AgentTeams 的"房间制 IM + Manager 管家 + 人工监督审批"模型。Part 1（§1～§7）的视觉 spec 仍然有效，Part 2 在其之上补充交互模型与信息架构层面的优化，并新增阶段 P5。

## 1. 背景与目标

协作室页面是 AgentTeams 多助手协作的入口，但目前呈现"灰白工具感"，与平台首页（星尘 AI）的品牌体验断裂：

- 首页有紫色星尘 Hero、品牌问候、`KimiChatInput` 大卡片输入区、快捷操作胶囊、最近会话卡片列表；
- 协作室页面是裸列表栏 + 整屏空白卡片 + 朴素输入框，没有复用任何平台共享模式。

**目标**：让协作室页面在不增加装饰负担的前提下，复用平台已有的页头、卡片、输入区、空状态和品牌令牌，达到与首页一致的"平静、清晰、可靠、可控"质感（规范 §1）。注意规范 §2.3/§5.6：**星空与玻璃材质只用于认证页与首页 Hero，工作台页面保持克制**——所以本次优化不照搬首页的紫色渐变 Hero，而是统一令牌、组件与品牌主色。

## 3. 优化方案（逐条 spec）

### 3.1 左侧栏头部与筛选（对应问题 1、2）

- 标题"协作室"升级为区块标题级：`18px / 28px / 600`，字距 `-0.01em`，颜色 `var(--neutral-text-1)`；左侧栏头部按 `标题左 + 操作右` 两区布局，刷新按钮使用圆形弱化图标按钮 + Tooltip（"刷新列表"），禁止图标裸放。
- "+ 新房间"按钮改为 `NButton type="primary"`，颜色走 `--arco-primary`（`#4C6FFF`），与全平台主按钮一致；一个视觉区域只保留这一个主要动作。
- 状态筛选改用规范 §5.1 的胶囊分段切换器 `.omichub-segmented-toggle`：`1px var(--neutral-border)` 边框、`999px` 圆角、`--neutral-fill-2` 轨道、`11px` 加粗标签，选中态 `--arco-primary` 背景 + `--text-on-primary` 文字；五个状态项容器 `flex-wrap: nowrap` + 横向滚动（`overflow-x: auto`），禁止"失败 0"单独折行；计数数字与状态文字用 `4px` 间距，数字使用 `var(--neutral-text-3)`（选中态反白）。
- 每个筛选按钮提供 `aria-pressed`，支持键盘与 `focus-visible`（`2px solid var(--arco-primary)` + `3px` 外偏移）。

### 3.2 左侧栏空状态（对应问题 3）

- 换用 `NEmpty`，图标去掉 × 语义（使用中性空盒/收件箱图标，或 `NEmpty` 默认插画），`size="small"`。
- 文案分两级：主文案"还没有协作房间"（`13px / var(--neutral-text-2)`），说明文案"在下方输入需求，回车即可创建第一个协作 Case"（`12px / var(--neutral-text-3)`）。
- 空状态下提供下一步操作：文字按钮"了解协作 Case 的工作方式"（如有帮助文档入口）或引导高亮右侧输入区，不留死路（规范 §5.4）。

### 3.3 右侧空状态主区域（对应问题 4、5）

- 保留"中间引导 + 底部输入区"的双段结构，但把右侧空状态做成与首页一致的内容居中列：最大宽度 `720px`，`margin-inline: auto`，垂直居中偏上（`padding-top: 48px` 即 `--space-5xl` 起，遵守 §3.4 间距阶梯），避免"整屏一张空卡片"。
- 引导区增加品牌锚点（克制版）：星尘图标/Logo 使用 `48px` 尺寸、品牌色 `--arco-primary` 系（不引入首页的紫色渐变背景和星空装饰）；标题"协作室"或"多助手协作"使用 Display 级 `28px / 36px / 600 / -0.02em`，颜色 `var(--neutral-text-1)`。
- 引导文案分层重写：
  - 主说明（`14px / 22px / var(--neutral-text-2)`）："描述你的分析问题，回车即可创建协作 Case，多个助手将分工协作完成；也可以从左侧选择已有 Case 进入房间。"
  - 次级提示（`12px / 18px / var(--neutral-text-3)`）："流程型分析（真实计算）请在 AI 工作台发起，需人工审批。"
- 增加快捷操作胶囊组（复用首页模式，规范 §1 高频路径优先）：3~4 个快捷入口，如"创建一个数据质控协作 Case"、"查看进行中的 Case"、"了解 AgentTeams 工作方式"；胶囊使用 `1px var(--neutral-border)` 边框 + `--neutral-card` 底 + `999px` 圆角 + `13px` 文字，hover 用 `--neutral-hover`；点击即填充输入框或执行对应动作。
- 右侧容器材质与左栏统一：右侧不再单独套一张"大卡片"，直接落在页面背景 `--neutral-bg` 上，引导区与输入区按内容列组织；若保留卡片包裹，则圆角 `12px`、边框 `var(--neutral-border)`、内边距 `24px`、阴影 `--shadow-card`，与左栏卡片规格一致（规范 §3.4、§4.2）。

### 3.4 底部输入区（对应问题 6）

- **复用 `KimiChatInput`**（规范 §3.3.5 强制项）：协作室页面输入框与 AI 助手/AI 工作台使用同一个输入组件；页面根容器补齐 `--chat-input-bg: var(--neutral-card)` 与 `--chat-input-border: var(--neutral-border)` 两个变量后消费组件默认样式，禁止页面级另写背景色与阴影。
- 输入卡片宽度与引导内容列对齐（`max-width: 720px`，`margin-inline: auto`），不再贴边拉伸。
- 占位文案保留"输入需求创建协作房间，@ 引用工作区文件"；`@` 触发逻辑不变。
- 底部提示行（附件图标 + "Enter 创建协作 Case · Shift+Enter 换行"）与首页输入卡片工具行样式对齐：图标按钮圆形弱化 + Tooltip；发送按钮使用 `--arco-primary`，空内容时 `disabled`（规范 §18.3）。

### 3.5 页面结构与响应式（对应问题 7、8）

- 页面级标题/副标题/操作若需要在壳层体现，复用 `PageHeader`（规范 §4.1/§12）；若协作室保持"沉浸式分栏"无页头设计，则左侧栏头部按 §3.1 的对齐规则执行，不再自定义第三套页头。
- 左右分栏：左栏宽度建议 `280px~320px`（`flex-shrink: 0`），右栏 `flex: 1; min-width: 0`；两栏间距 `16px`，落在统一 `--page-padding: 32px` 内。
- 响应式（规范 §7.1）：`1024px` 以下左栏收纳为可折叠抽屉或顶部下拉（进入 Case 后默认收起）；`768px` 以下页面内边距降至 `16px`；`640px` 以下快捷胶囊组允许换行、输入卡片占满宽度；任何断点下不出现横向滚动（筛选胶囊容器自身滚动除外）。
- 深色模式：全部颜色走语义令牌，左栏卡片用 `--neutral-card`，页面底 `--neutral-bg`，不新增硬编码色值；如协作室未来接入深色五级 Surface，普通卡片 `--surface-card`、输入区 `--chat-input-bg`，本次改动不得阻断该路径（规范 §3.3）。
- 动效：hover/选中过渡 `140ms~220ms`，只动画 `transform/opacity`；`prefers-reduced-motion: reduce` 下取消位移（规范 §6）。

# Part 2：对齐 AgentTeams 架构与客户端交互模型（第二轮，2026-08-13）

## 8. AgentTeams 架构与客户端页面解读

### 8.1 运行时架构（图 1）

用户入口（AgentTeams 客户端 / IM 钉钉等 / API 直接访问）→ **Worker 团队（多智能体）**：Team Leader 接受并分解任务、跟踪进展，Worker-A/B 执行任务、上下游协同 → **Human 监督 / 干预 / 修正**（人在回路）；底层由 LLM、MCP Server 支撑，左侧接 Worker 资产与 AI 资产管理，底部接观测/评估/调优（AgentLoop）。右侧能力面：多 Agent 统一纳管编排、Skill/MCP/模型/模板资产注册管理、企业级治理（鉴权/计量/审计/安全）、IM 原生集成、全链路可观测。

### 8.2 管理平台架构（图 2）

平台管理员配置 Team 池 → AgentTeams 管理平台（Team Pool 按角色分组：研发/运维/数据/安全 Team + RBAC 权限 / 配额管理 / 资源隔离）→ 业务团队按需接入（权限隔离、用量独立计费）。

### 8.3 客户端聊天页面（图 3，真实产品截图）

AgentTeams 客户端是 **Matrix/Element 风格的房间制 IM**：

- **左侧栏**：Home + `Unreads / People / Rooms` 分组 tabs；房间列表项 = 圆形头像（首字母徽标）+ 房间名 + 在线状态点（如 `Manager: default`、系统日志房间 `matrix-local.agentteams.io:180…`）。
- **右侧**：房间标题栏（房间名 + 视频/语音/线程/信息/成员图标）+ **消息时间线**（Manager 长欢迎语、回复引用条、`(edited)` 标记、用户与 Manager 消息按发送者分布）+ 底部输入框（表情 / 附件 / 更多）。
- **Manager 是"管家 / AI 指挥官"**：首轮对话主动做 onboarding——让用户给 Manager 起名、选沟通风格（正式专业 / 亲切友好 / 极简高效）、定行为准则（谨慎模式先请示 vs 自主模式直接执行）、确认语言。

### 8.4 对协作室页面的推导

协作室页面是 AgentTeams 能力在 OmicHub 内的入口，信息架构应当对齐房间制 IM 模型，而不是停留在"Case 列表 + 空白卡片"：

| AgentTeams 模型 | 协作室页面对应物 | 现状差距 |
|---|---|---|
| 房间列表（头像 + 名称 + 状态点 + 分组 tabs） | 左侧 Case 列表 | 列表项只有一行标题，无头像、无消息预览、无未读、状态表达弱 |
| 消息时间线（Manager/Worker 对话） | 右侧选中 Case 后的会话区 | Part 1 只覆盖了空状态，未规定选中后的聊天区形态 |
| Human 监督 / 干预 / 修正 | 左栏"待审批"状态 | 只有筛选计数，房间内没有审批操作界面 |
| Team Leader 分解任务、跟踪进展 | 协作过程展示 | 消息流中没有任务分解/进度的结构化表达 |
| Manager 管家 onboarding | 首次创建引导 | 空状态引导是抽象"Case"话术，没有管家心智 |
