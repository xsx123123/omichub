# 协作室（AgentTeams）房间头部与消息流修正——前端优化提示词与实现计划

> 依据：真实运行房间截图（"rna-seq 数据分析"，received 状态）+ 《OmicHub 前端设计系统与实现规范》
> 日期：2026-08-18
> 前置：本文档是《协作室页面视觉优化实现计划》第五轮的独立版，可单独粘贴给编码 Agent 使用；四轮前置优化（视觉基础、AgentTeams 交互模型对齐、规范审核、输入区工具行）的上下文见原文档。

## 1. 背景与目标

协作室页面此前四轮优化基于空状态截图与 AgentTeams 客户端设计稿。本轮截图首次呈现**真实运行中的房间**：头部含标题、发起人、创建/更新时间与步骤条，消息流中已有 ask_user 澄清问答与 Manager 分析方案长文。真实状态暴露出一批空状态阶段不可见的缺陷。

本轮目标：**修正真实状态渲染缺陷 + 对照设计规范收尾**，不引入新功能、不改业务逻辑。

## 3. 优化方案（逐条 spec）

### 3.1 消息列表遮挡修复（对应问题 1）

- 根因方向（编码 Agent 先定位再改）：消息滚动容器未为 sticky/fixed 房间头部预留偏移——优先检查滚动容器 `padding-top` / `scroll-padding-top` 是否等于头部实际高度，以及进入房间时"滚动到底部/定位到未读"逻辑是否在头部渲染完成前执行。
- 修复要求：进入房间后首条消息完整可见；加载更多历史后视口锚定不跳动；头部高度变化（窄屏换行）时偏移同步更新（`ResizeObserver` 或 CSS 变量驱动，不写死 px）。
- 预期效果：任意断点下消息流无内容被头部遮挡。

### 3.2 发起人身份展示（对应问题 2）

- "发起人"字段改显示用户显示名（后端有昵称/用户名字段则用，没有则先用"我"或邮箱前缀并标注 TODO）；头像沿用左栏房间头像体系。
- UUID 不再直接展示；确需保留时以 Tooltip 承载完整值，正文永不出现完整 UUID（§5.4）。
- 预期效果：用户一眼识别房间归属人。

### 3.3 步骤条与 Case 状态语义统一（对应问题 3）

- 单一事实源：步骤条激活步骤必须由 Case 状态映射派生，不允许步骤条与状态标签各自取数。received 状态下步骤条应为"未开始"形态（全部步骤未激活，或第 1 步显示为"待开始"的弱态，不用主色激活态冒充进行中）。
- "已接收"状态标签与步骤条合并表达：状态标签 `NTag` 保留为当前真实状态（文本 + 语义色双表达），步骤条只展示流程进度；二者同源。
- 预期效果：同一头部不再出现"已接收"与"计划进行中"并存的矛盾。

### 3.4 左栏筛选胶囊溢出（对应问题 4）

- 方案 A（首选）：胶囊容器允许横向滚动（`overflow-x: auto`，隐藏滚动条但保持可滚），每枚胶囊 `flex-shrink: 0`，计数永不被截断。
- 方案 B（备选）：窄栏下计数与文字分行，或切换为 `NSelect` 下拉（仅当胶囊 > 4 枚时）。
- 无论哪个方案：当前激活胶囊仍有完整选中态（§5.2），hover 有 `--neutral-hover` 底色，键盘焦点环完整。
- 预期效果：5 枚胶囊与各自计数在 280px 侧栏内全部可读。

### 3.5 时间显示统一规则（对应问题 5、6）

- 全页面统一规则（写入协作室页面级工具函数或复用现有时间工具，不引入新日期库，dayjs + zh-cn）：
  - 当天：`HH:mm`；
  - 当年：`MM/DD HH:mm`；
  - 跨年：`YYYY/MM/DD`；
  - 列表/气泡 hover Tooltip 显示完整时间 `YYYY年M月D日 HH:mm:ss`。
- 左栏相对时间（"2 天前"）保留——这是 IM 惯例，但 hover Tooltip 补完整时间。
- 头部元信息收敛为一行：`发起人 {显示名} · 创建于 {当年格式}`；"更新于"仅在确实晚于创建时间时显示，同值不重复展示。
- 预期效果：全页时间表达一致、无秒级时间戳噪音。

### 3.6 ask_user 澄清回复折叠（对应问题 7）

- 对齐 §18.4.2：澄清完成（已回答）后，整条问答折叠为工具卡样式——单行显示"询问工具 | 已收集信息"+ 状态标签 + 旋转箭头，点击展开可回看问答明细，不重新展示可点选项。
- 展开态限高（参考 §18.4.1：`max-height: 220px; overflow-y: auto`），问题/回答分行展示（问题 `var(--neutral-text-2)`、回答 `var(--neutral-text-1)`），不再渲染为整段蓝色用户气泡。
- 历史重载：折叠卡必须能从落库数据 hydrate 重建（§18.4.3），旧消息若缺字段按"无载荷"降级为纯文本，不崩。
- 预期效果：澄清完成后消息流恢复整洁，问答细节可回看。

### 3.7 气泡与卡片宽度核查（对应问题 8、9）

- 实测用户气泡当前 `max-width`，超过 720px 则收敛到 `max-width: 720px`（§18.1）；代码块/表格允许占满气泡宽度。
- Manager 长文与内联状态卡遵守 §18.1.1：`width: 100%; max-width: 1120px; margin: 0 0 var(--space-md,12px); box-sizing: border-box`，标题与说明同行左对齐（gap 连接，禁止 `space-between`）。
- 预期效果：消息流左右边界整齐，上下卡片边缘对齐。

### 3.8 输入区与图标按钮收尾（对应问题 10）

- 输入区 `autosize` 最小行数收紧为 1~2 行（对齐 AI 助手页 KimiChatInput 默认形态），不改动共享组件交互逻辑。
- 工具行全部图标按钮（附件、引用工作区文件、发送）补齐 `NTooltip` + `aria-label`（§5.1）；发送按钮禁用态保留现有语义。
- 预期效果：图标按钮悬停均有文字说明，键盘与读屏可达。

## 7. 风险与回退

| 风险 | 说明 | 应对 |
|---|---|---|
| 遮挡修复误改滚动锚定逻辑 | "自动滚底 / 上翻暂停"行为是既有已定交互 | 修复只动偏移计算，不动滚底策略；验收含"上翻时不自动跳底"回归 |
| 步骤条改数据源波及审批流 | 步骤条若与审批操作共用状态，改动可能影响审批推进 | 只做"读取侧"映射收敛，不改状态推进写路径；验收含一次完整 计划→审批→执行 走查 |
| 澄清回复折叠影响未回答态 | 未回答的 ask_user 卡片必须保持可交互向导形态 | spec 已限定"已回答态"才折叠；验收含未回答态回归 |
| 时间格式统一漏改分支 | 消息、头部、列表三处各自实现会漏 | 收敛为单一格式化函数，三处消费同一函数；diff 中不应出现第二处格式化逻辑 |
