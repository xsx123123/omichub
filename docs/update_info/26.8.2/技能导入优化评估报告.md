> 目标读者：编码 Agent（kimi code / Claude Code / CODEX）

## 一、评估结论（Verdict）

**总体方向：对，可以放心推进。** 四个想法逐项结论如下：

| # | 方案 | 结论 | 依据 |
|---|---|---|---|
| 1 | 废弃 Modal，改为配置中心标准页面 | ✅ 方向正确 | 主流扩展/插件市场（VS Code Extensions 视图等）全部是页面级承载，无一使用 Modal；市场类界面需要长列表浏览、搜索、滚动，Modal 的空间与滚动限制是先天缺陷；改页面后顺带获得路由直达能力 |
| 2 | 动静分离：市场（浏览）与导入（操作）两个顶级 Tab | ✅ 方向正确 | 与 VS Code「浏览 vs @installed」、各类插件管理器「Browse / Installed / Updates」的分区逻辑同构：浏览是高频被动行为，导入是低频主动操作，混在一个弹窗里四个入口层级不对等 |
| 3 | 市场增加搜索 + 按来源（平台内置/阿里云）筛选 | ✅ 方向正确 | VS Code 扩展搜索框的 `@builtin`、`@category` 过滤器就是这个模式，你的来源筛选胶囊完全同构 [^5^] |
| 4 | 平台内置技能用 `./data/skill/skill.yaml` 配置化 | ⚠️ 方向正确，但有一个关键设计陷阱要避开 | 业界约定：**SKILL.md 的 YAML frontmatter 是技能元数据的唯一事实源**（Agent Skills 开放规范，name/description 必填，其余可选）[ ^27^][^28^]；Claude Code 的 `marketplace.json` 只存"清单指针"（名称、来源路径、版本），不重复抄写每个 SKILL.md 里的 description [^24^][^39^]。如果把名称/描述/版本同时写进 skill.yaml 和 SKILL.md，就制造了双事实源，两边迟早漂移 |

**第 4 点的正确姿势**（详见第六章）：

- **skill.yaml 做"注册清单"（registry manifest）**：只存路径、来源、启用状态、排序、pin 版本、安装时间等**管理类**信息；
- **name / description 等展示元数据仍在加载时从 SKILL.md frontmatter 读取**，不在 skill.yaml 里复写；
- **版本号由注册清单/治理层持有**，不写进 SKILL.md——Agent Skills 开放规范里 version 不是标准必填字段，官方建议恰恰是"让 registry 拥有版本号与分发规则" [^32^]；
- 若担心市场列表加载时逐个读 SKILL.md 太慢，可以让系统生成一个**安装/构建时自动生成的索引缓存**，并提供校验与重新同步入口，而不是手工维护两份元数据。

这样你的两个诉求都能满足：**预置内置技能** = 在 skill.yaml 登记条目；**后续手动扩充** = 加技能目录 + 追加一条注册项（甚至可以做到纯目录自动发现，skill.yaml 只覆盖需要管理的条目）。

## 二、业界约定依据（评估锚点）

1. **SKILL.md frontmatter 是唯一事实源**：Agent Skills 开放规范规定 `name`、`description` 为必填字段（name ≤64 字符、kebab-case、必须与父目录同名；description ≤1024 字符、说明"做什么 + 何时用"），其余字段可选，运行时会忽略不认识的字段 [^27^][^28^][^22^]。VS Code Copilot、Cursor、Codex 等 26+ 平台均采用该格式 [^28^][^29^]。
2. **"放进目录即注册"的自动发现约定**：Hermes、Claude Code 等运行时都是扫描技能目录自动加载，**不需要注册步骤** [^31^]；Claude Code 插件市场里，"在既有插件的 `skills/<name>/SKILL.md` 加一个目录，插件就会自动收录它" [^26^]。
3. **marketplace.json 是指针型清单**：Claude Code 市场清单只记录插件名、来源路径、版本、作者等分发信息，技能的名称与触发描述仍以各自 SKILL.md frontmatter 为准；且版本只写在 `plugin.json` 一处，"第二份拷贝只会漂移" [^24^][^26^][^39^]。
4. **版本号归属 registry**：开放规范没有要求顶层 version 字段；可移植的版本实践是 Git tag / `metadata.version` / **由 registry 或插件包持有版本号与分发规则** [^32^]。Claude Code 也是靠 `plugin.json` 的 version 变化来向已安装用户推送更新 [^26^]。
5. **市场 UI 页面化 + 过滤器**：VS Code 扩展视图为页面级 UI，搜索框支持 `@builtin`、`@installed`、`@category:*` 等过滤器并可组合 [^5^]。
6. **版本治理已有成熟范式**：skills CLI 的 `.skill-lock.json` 锁版本 + check/update/回滚，已在《阿里云Skills接入与Skill治理实现计划》Part 4 落地为本平台的 `skill_version` 快照方案，本文的 skill.yaml 与之衔接而不重叠。

## 四、Part 1：页面结构与导航重构

> 原则：这是**对现有"资源中心 → 技能"模块的结构优化**，不是重新设计。先读现有代码（市场弹窗组件、技能入库接口、预览校验逻辑），复用现有组件与样式体系，禁止推倒重写，不改路由表之外的无关逻辑。

### 4.1 布局骨架（严格对齐 fontend.md §4.3 配置中心配方）

```vue
<div class="admin-config-center">
  <PageHeader title="技能管理" subtitle="浏览技能市场，或从 GitHub / 本地 / JSON 导入技能">
    <template #actions>
      <NButton secondary :loading="refreshing" @click="loadSkills">刷新列表</NButton>
    </template>
  </PageHeader>
  <NTabs v-model:value="activeTab" type="line" animated class="admin-config-tabs">
    <NTabPane name="market" tab="技能市场"><SkillMarketSection /></NTabPane>
    <NTabPane name="import" tab="导入技能"><SkillImportSection /></NTabPane>
  </NTabs>
</div>
```

实现规则（逐条对应 fontend.md）：

1. 根容器用 `.admin-config-center`（`width: min(100%, 1440px)` + 居中），页面底色 `--neutral-bg`；**不要**自造 `max-width` 容器。
2. 两个子区块（SkillMarketSection / SkillImportSection）使用 `.admin-config-section`，`width: 100%`、`min-width: 0`，与顶层标签页共享同一条内容边界，切换 Tab 时内容区不得突然收窄（§4.3 规则 3）。
3. 顶级 `NTabs type="line"` 沿用应用主题激活态/焦点态/深色模式颜色，禁止局部硬编码覆盖（§4.3 规则 2）。
4. 页面级刷新放 `PageHeader #actions`，按钮带 `:loading`，刷新后 `useMessage()` 反馈；禁止 `$router.go(0)` / `location.reload()`（§5.1）。
5. 保留 Modal 作为**降级回退**（如从助手配置页打开的小型选择器场景）——本次改造只替换主入口，弹窗组件保留但标注 deprecated，确认无引用后再删。
6. 路由：新页面挂到资源中心现有路由下（如 `/admin/resources/skills`），`meta.title = '技能管理'`；Tab 状态同步到 `query`（`?tab=market|import`），刷新/分享链接可直达对应 Tab。

## 五、Part 2：技能市场页设计规范

这是用户浏览和搜索的核心区域，全部样式消费语义令牌（fontend.md §3），不硬编码浅色模式色值。

### 5.1 工具条（搜索 + 筛选）

- 工具条置于列表上方、`--neutral-card` 表面、内边距 `16px 24px`、圆角 `12px`。
- **搜索框**：`NInput` + `clearable`，placeholder「搜索技能名称或描述」，前端对当前列表做名称/描述/分类的本地过滤；若后续条目量大（>200），改走后端查询并加防抖，避免每次击键发请求。
- **来源筛选胶囊**：复用全局 `.omichub-segmented-toggle`（§5.1）：`1px --neutral-border` 边框、`999px` 圆角、`--neutral-fill-2` 轨道、`11px` 加粗标签，选中态 `--arco-primary` 背景 + `--text-on-primary` 文字；容器 `role="group"` + `aria-label`，按钮带 `aria-pressed`，支持 hover / focus-visible / 键盘 / `prefers-reduced-motion`。选项：`全部` / `平台内置` / `阿里云官方`（阿里云条目带「官方」badge，对齐治理文档路径 B）。
- 窄屏（<640px）工具条允许换行，胶囊组不裁切标签（§5.1 分段器规则）。

### 5.2 卡片网格

- 网格布局：`repeat(auto-fill, minmax(320px, 1fr))`，间距 `20px`；≥1200px 三列、768–1200px 两列、<768px 单列（§7.1）。
- 卡片复用 `NCard` / `.omichub-card` 外观：表面 `--neutral-card`、边框 `--neutral-border`、阴影 `--shadow-card`，默认内边距 `24px`（§3.3）。
- **卡片标题 16px / 24px / 500**（§3.3 字阶），版本与分类用 `NTag` 表达，描述用 `--neutral-text-2` 小正文（13px / 20px），超过两行省略 + Tooltip（§5.4 长文本规则）。
- hover 反馈：位移 **≤2px**（`translateY(-2px)`）+ 阴影切到 `--shadow-card-hover`，过渡 `220ms var(--motion-spring)`，只动 transform/opacity（§6.1）。
- 操作按钮：每卡一个主要动作——未安装显示 `NButton type="primary"`「安装」；已安装显示 `secondary`「重新安装」+ 可选「检查更新」（红点对齐治理文档 §5.2）；点击后按钮切 `:loading`，完成后 `useMessage()` 成功/失败反馈（§5.1）。
- 来源标识：卡片右上角来源 tag（`平台内置` / `阿里云官方` / `GitHub` / `本地`），颜色来自语义令牌，不只靠颜色——必须有文字（§7.2 规则 2）。

### 5.3 加载与空状态（§5.4）

- 首次加载：`NSkeleton` 骨架屏，贴近卡片结构（标题条 + 两行描述条 + 按钮块），不用整页 NSpin。
- 局部刷新：工具条区域或刷新按钮 `:loading`，不清空已有卡片。
- 搜索无结果：`NEmpty` + 引导文案「未找到相关技能，换个关键词试试」；阿里云源同步失败：分组内显示「官方源暂不可用」+ 重试，**不影响平台内置条目**（对齐治理文档风险表）。
- 部分失败用 `Promise.allSettled`，展示成功部分 + 失败提示（§15.4）。

## 六、Part 3：导入技能页设计规范

把三个导入通道平铺展开，用分段切换器收敛。

### 6.1 分段控制器

页面顶部使用 `.omichub-segmented-toggle` 切换 `本地 ZIP` / `GitHub 导入` / `JSON 粘贴`（规格同 §5.1 上文）。注意：分段器只用于同层级偏好切换，导入提交按钮仍是独立主按钮（§5.1 分段器用途约束）。

### 6.2 三个导入通道

- **本地 ZIP**：废弃单按钮，改拖拽上传区（§17.1）：虚线边框 `--neutral-border`、上传图标 + 说明文案（「拖拽 ZIP 技能包到此处，或点击选择；内含 SKILL.md 与可选 scripts/ references/ assets/，≤6MB」）；`dragover` 时边框高亮为 `--arco-primary`；客户端先校验扩展名 + MIME + 大小，不合规直接 `useMessage().error()` 拦截，不发请求。
- **GitHub 导入**：`NForm` + `NFormItem` + 校验规则（非空、URL 格式、github.com 域名白名单），`blur` 触发校验，错误文案放在字段附近（§5.3）；辅助文案说明支持仓库主页 / tree 分支子目录 / 直指 SKILL.md 的链接。
- **JSON 粘贴**：等宽字体代码输入框（`'JetBrains Mono', Menlo, Consolas, monospace`，§19.1），`NInput type="textarea"` + `autosize`，placeholder 给出最小 JSON 示例；「解析并预览」为主按钮。
- **操作保护**：三个通道提交前都必须 `FormInst.validate()` / 客户端预检，通过后走**现有预览校验流程**入库——本优化不改后端入库逻辑，只改承载与交互（§5.3 表单契约）。
- 表单区置于宽大的 `--neutral-card` 表面、内边距 `24px`；窄屏表单降单列（§5.3）。

## 七、Part 4：平台内置技能 `skill.yaml` 配置化

### 7.1 评估

你的设想：「平台内置技能通过 `./data/skill/skill.yaml` 配置，把 SKILL.md 的作用、版本等信息写进 skill.yaml，后面可以手动扩充」。

- **「配置化预置 + 手动扩充」本身完全成立**：这正是 Claude Code `marketplace.json` 的指针清单模式 [^24^][^39^]，也和 Hermes/Claude Code「目录自动发现」约定兼容 [^31^][^26^]。
- **必须避开的陷阱**：把 name/description/版本**复写**进 skill.yaml。业界反例已有实录——有平台在市场安装链路里用清单里的 id/title 重新生成 SKILL.md frontmatter，导致 name 被覆盖、描述错乱，技能列表与按名查找全部出错 [^36^]。SKILL.md frontmatter 是规范定义的事实源 [^27^][^28^]，任何第二份元数据拷贝都会漂移（Claude Code 社区的原话："a second copy just drifts" [^26^]）。

### 7.2 推荐 Schema（注册清单，只管管理信息）

```yaml
# ./data/skill/skill.yaml —— 平台技能注册清单（registry manifest）
# 规则：本文件只存"管理信息"；技能的名称/描述/触发条件/版本在加载时从各条目
# path 指向的 SKILL.md frontmatter 读取，本文件不得复写。
version: 1
skills:
  - id: data-cleaning              # 必须与目录名及 SKILL.md 的 name 一致
    source: builtin                # builtin | aliyun-official | github | local | json
    path: builtin/data-cleaning    # 相对 ./data/skill 的目录
    enabled: true                  # 停用不删档
    order: 10                      # 市场/列表排序
    pinned_version: "1.0.0"        # 可选：生产 pin 版本（对齐治理文档 Part 4）
    installed_at: "2026-08-01T10:00:00+08:00"
    note: "赛题演示必备"            # 可选：管理备注，不进入 Agent 上下文
```

加载规则：

1. 启动时读 skill.yaml → 逐条校验（`id` 合法 kebab-case、`path` 存在、目录内 SKILL.md 可解析、SKILL.md 的 `name` 与 `id` 一致 [^22^]）→ 从 SKILL.md frontmatter 读取 name/description/version 组装列表。**单条校验失败只标记该条目为 invalid 并告警，不阻断其他条目**（对齐平台"部分失败"哲学 §15.4）。
2. **手动扩充的两条路径**：① 在 skill.yaml 追加条目（显式注册）；② 直接把技能目录丢进 `./data/skill/` 未注册目录，系统扫描后在市场显示「未注册 · 点击启用」——兼容"放进目录即注册"的主流约定 [^31^][^26^]，降低扩充门槛。
3. **列表性能**：技能数量 <100 时启动逐个读 SKILL.md 开销可忽略；规模变大后再加构建/安装时自动生成的 `skill-index.json` 缓存（含各 SKILL.md 内容 hash，hash 变化自动重建），**缓存是产物不是事实源**，并提供「重新同步」管理入口。
4. **版本归属**：版本号以治理文档的 `skill_version` 快照表 + skill.yaml 的 `pinned_version` 为准，SKILL.md frontmatter 里不写版本（规范未要求顶层 version，建议 registry 持有 [^32^]）；若上游 SKILL.md 自带 `metadata.version`，仅作展示参考。
5. **冲突与覆盖**：同 `id` 下，用户手动导入视为对内置技能的"覆盖安装"——生效用户版本，内置版本保留在快照表中可一键恢复（衔接治理文档 Part 4 回滚链路）；不允许两个不同来源的条目共用同一 `id` 同时 enabled。
6. **热更新**：`./data/skill/` 目录与 skill.yaml 加 watch，变更后重建内存注册表；进行中的 Agent 会话仍 pin 旧版本（对齐治理文档 §5.2 第 4 条），新会话用新版本。
7. **安全**：skill.yaml 只描述注册信息，不注入 Agent 上下文；frontmatter 解析使用标准 YAML 解析器并拒绝非法 frontmatter 的技能（未闭合/非法标量的 frontmatter 会导致技能被静默跳过，已有上游实录 [^38^]），导入预览时就要报出具体行号。

### 7.3 与既有文档的边界

- 市场源（阿里云官方源同步）、版本快照与回滚：已在《阿里云Skills接入与Skill治理实现计划.md》定义，**不在本文重复实现**；skill.yaml 的 `source`/`pinned_version` 字段就是为衔接那套治理而设。
- 本文新增的只有一件事：**把"平台内置技能"从代码硬编码/数据库种子，改为 `./data/skill/skill.yaml` + 目录的声明式注册**。

## 八、分阶段实施与编码 Agent 提示词

### 阶段 1：弹窗改页面 + 导航重构（0.5–1 天）

```text
你是一名资深前端工程师。项目技术栈：Vue 3 + TypeScript + Naive UI（另有 Arco Design Vue 并行），
```

### 阶段 3：平台内置技能 skill.yaml 配置化（1–1.5 天，后端为主）

```text
你是一名资深全栈工程师。项目技能模块已有：四种导入方式 + 预览校验入库，以及 skill_version
不可变快照（版本控制与回滚，见既有治理实现）。

任务：将"平台内置技能"从硬编码/数据库种子改为声明式注册：./data/skill/skill.yaml +
技能目录。先阅读现有技能加载、入库与市场列表代码，禁止改动 Agent 调用技能的运行时语义。

## 功能需求
1. 新增 ./data/skill/skill.yaml 注册清单，schema：version、skills[]（id、source、path、
   enabled、order、pinned_version?、installed_at、note?）。本文件只存管理信息；
   技能的 name/description/version 一律在加载时从各条目 path 下 SKILL.md 的 frontmatter
   读取，清单中不得复写。
2. 加载流程：启动读 skill.yaml → 逐条校验（id 为合法 kebab-case、path 存在、SKILL.md
   可解析且其 name 与 id 一致）→ 组装列表；单条失败标记 invalid 并告警，不阻断其他条目。
3. 目录自动发现：./data/skill/ 下未注册的技能目录在市场显示"未注册 · 点击启用"，
   启用即向 skill.yaml 追加条目。
4. 同 id 覆盖语义：用户手动导入同 id 技能视为覆盖安装，生效用户版本，内置版本存入
   skill_version 快照可一键恢复；不允许两个不同来源条目同 id 同时 enabled。
5. 热更新：watch ./data/skill/ 与 skill.yaml，变更重建内存注册表；进行中会话 pin 旧版本，
   新会话用新版本（复用既有会话 pin 逻辑）。
6. frontmatter 解析用标准 YAML 解析器；非法 frontmatter 的技能在导入预览与加载校验时
   报出具体行号，不静默跳过。
7. 迁移：现有内置技能（数据清洗、差异表达分析、人/小鼠单细胞注释、植物单细胞注释等）
   一次性迁移为 skill.yaml 条目 + 目录落盘，提供迁移脚本。

## 验收标准
- [ ] 删除 skill.yaml 某条目后该技能从市场消失；目录新增未注册技能出现"点击启用"
- [ ] 单条非法配置不影响其他技能加载
- [ ] 覆盖安装后内置版本可回滚恢复
- [ ] 修改 SKILL.md 的 description 后（不重启服务）市场列表按 frontmatter 更新
- [ ] 进行中 Agent 会话不受技能变更影响
```

## 九、风险与回退

| 风险 | 应对 |
|---|---|
| 弹窗改页面后遗漏其他入口仍引用旧 Modal | 阶段 1 保留旧组件 deprecated，全局搜索引用确认清零后再删 |
| skill.yaml 与 SKILL.md 元数据被后人改成双份复写 | Schema 评审 + 代码评审拦截；加载器只认 frontmatter，清单里的同名字段直接忽略并告警 |
| 目录 watch 在部分部署环境（只读文件系统/容器）不可用 | 降级为启动时加载 + 管理页"重新同步"手动入口 |
| 目录自动发现把半成品技能暴露给 Agent | 未注册目录只在市场显示、需人工启用后才进入 Agent 匹配集 |
| 搜索改本地过滤后条目量变大性能下降 | >200 条目时切后端查询 + 防抖；网格渲染量大时用虚拟滚动（§21.2） |
| 卡片网格在超宽屏过度拉伸 | 已由 .admin-config-center 的 1440px 上限兜住；网格列宽 minmax 下限 320px |
