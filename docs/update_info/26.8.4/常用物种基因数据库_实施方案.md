# 常用物种基因数据库 · 详细实现逻辑

> **目标**：把当前"参考基因组数据库"页面（`/database`，目前纯前端 mock）升级为真实的**常用物种基因数据库**——按物种/版本管理基因信息、序列信息、基因注释、GO、KEGG，并提供一套可搜索的 API（既供页面使用，也可被平台内 AI 助手/分析工具程序化调用）。
> **前置阅读**：`refdata/README.md`（已有的后端搭建蓝图，569 行，含模块分层/FTS5 索引/10 个端点设计）。本文档在其基础上扩展 **GO/KEGG 条目级入库、序列 API、统一搜索、构建管线、多物种接入**，与蓝图冲突处以本文档为准。
> **读者**：执行实现的 AI/开发者。第 1~3 章建立共识，第 4~8 章是可直接照做的详案。

---

## 1. 需求拆解

| 需求 | 落地形态 |
|---|---|
| 常用物种数据库 | YAML 注册的物种 → 版本两级模型（物种卡片 → 版本），首批：拟南芥 TAIR10、生菜 v8/v11、水稻 IRGSP-1.0、番茄 SL4.0/ITAG4.1 |
| 基因信息 | 基因 ID/名称/染色体/坐标/链向/长度/外显子数/转录本，入库可查询 |
| 序列信息 | 基因组 FASTA（faidx 随机访问）+ CDS/蛋白 FASTA，提供基因序列与区间序列 API，**序列不入库** |
| 基因注释 | 功能描述文本，进 FTS5 全文索引，可搜索 |
| GO 信息 | GO term 字典 + gene↔GO 关联表，支持"基因查 GO"与"GO 反查基因" |
| KEGG 信息 | KO 字典 + pathway 字典 + gene↔KO/pathway 关联表，双向查询 |
| 搜索 API | REST API：基因搜索、统一搜索（基因/GO/KEGG 三类聚合）、跨基因组搜索、序列获取、批量注释 |
| 嵌入当前页面 | 前端两个视图把 mock 换成 API 调用；页面搜索框改为服务端搜索；卡片 FA/GFF/GO/KEGG 状态改为真实审计结果 |

## 3. 总体架构

```
┌─ 前端（现有 UI，换数据源）──────────────────────────────┐
│ ReferenceGenomesView / DetailView                        │
│   └── frontend/src/api/referenceGenomes.ts（新建）        │
└──────────────┬──────────────────────────────────────────┘
               │ /api/v1/reference-genomes/**
┌──────────────▼──────────────────────────────────────────┐
│ src/omichub/reference_genomes/（新建，对齐 tools/ 分层）   │
│  api.py      路由 + 鉴权（Depends(get_current_user)）     │
│  service.py  查询逻辑（SQLite / faidx / YAML）            │
│  schema.py   Pydantic 模型（alias 输出 camelCase）        │
│  config.py   YAML 加载器（mtime 热重载，缺失回退空配置）   │
│  indexer.py  离线构建：GFF3/GO/KEGG/注释 → SQLite         │
│  sequence.py faidx 纯 Python 读取器（不引入新依赖）        │
└──────┬───────────────┬────────────────┬─────────────────┘
       │               │                │
  YAML 注册表      每版本一个          原始文件（只读）
  refdata/        gene_index.db       /data/omichub/omichub_data/
  reference_      （genes FTS5 +      reference/<species>/
  genomes.yaml     GO/KEGG/映射表）    （fa/gff/go/kegg/cds/pep）
```

**核心决策**：

1. **元数据 YAML 驱动、热重载**（沿用蓝图）：物种/版本/文件路径/统计信息全部在 `refdata/reference_genomes.yaml` 声明，改配置即生效；文件就绪状态由 service 实时审计（`os.path.exists`），不再用 mock 的静态 `buildStatus`。
2. **基因级数据用每版本一个 SQLite**（沿用蓝图并扩表）：`gene_index.db` 与该版本数据文件同目录；查询毫秒级、零运维、可随数据目录整体迁移。**不进 PostgreSQL**（yaml 里预留的 `use_database` 开关保持 false）。
3. **序列不入库**：基因组序列走 `.fai` 索引随机访问（纯 Python 实现，不装 pysam）；CDS/蛋白直接读对应 FASTA。
4. **构建与运行分离**：`indexer.py` 离线/异步构建（先 CLI，后 Celery），运行态 API 只读。
5. **搜索全部服务端化**：页面搜索框、基因 Tab、GO/KEGG Tab 全部走 API；同时 API 即平台的"数据库搜索接口"，OpenAPI 自动出文档（FastAPI `/docs`），供 AI 助手和外部脚本使用。

## 4. 数据模型设计

### 4.1 YAML 注册表（`refdata/reference_genomes.yaml` 扩展）

物种 → 版本两级，与前端 mock 的 `SpeciesDatabase → GenomeVersion` 对齐：

```yaml
species:
  - id: arabidopsis
    common_name: 拟南芥
    latin_name: Arabidopsis thaliana
    taxonomy_id: "3702"
    emoji: 🌿
    description: 模式植物拟南芥 TAIR10 注释库
    versions:
      - id: tair10
        version_name: TAIR10
        assembly_name: TAIR10
        is_default: true
        tags: [模式植物, 稳定版]
        data_dir: /data/omichub/omichub_data/reference/TAIR10
        stats: { chromosomes: 5, total_genes: 27655, genome_size: "135 Mb" }
        files:
          fasta:   { path: TAIR10_chr_all.fas,        type: genomic }   # 构建时解压 .gz
          gff3:    { path: TAIR10_GFF3_genes.gff }
          cds:     { path: TAIR10_cds.fas }
          protein: { path: TAIR10_pep.fas }
          go:      { path: gene_association.tair.gz,  format: gaf }
          go_obo:  { path: go-basic.obo }             # 可共享，见 6.4
          kegg_ko: { path: ath_ko.list,               format: kegg_list }
          kegg_pathway: { path: ath_pathway.list,     format: kegg_list }
        gene_index: gene_index.db                      # 相对 data_dir，构建产物
        id_mapping: []                                 # [{to: lettuce-v11, path: ...}]
```

- `files` 每项的 `format` 告诉 indexer 用哪个解析器（§6）；缺项 = 该物种没有此文件 → 卡片对应标签灰显（就绪状态由 service 审计得出：`ready/missing`，`building` 由构建任务写入 meta）。
- 生菜等只有注释总表的物种用 `annotation_overview: { path: ..., format: lettuce_overview }`，解析器从单表抽出基因/注释/GO/KEGG。

### 4.2 每版本 SQLite（`gene_index.db`）表结构

在蓝图的单 FTS 表基础上扩展为 6 张表（FTS5 全文 + 关联表）：

```sql
-- 1) 基因主表（FTS5）：gene_id/gene_name/annotation 可全文搜，其余仅存储
CREATE VIRTUAL TABLE genes USING fts5(
    gene_id, gene_name, chromosome,
    start UNINDEXED, end UNINDEXED, strand UNINDEXED, length UNINDEXED,
    annotation, exons UNINDEXED,
    tokenize = "unicode61 remove_diacritics 2"
);

-- 2) 转录本（详情页 Transcripts Tab）
CREATE TABLE transcripts(
    transcript_id TEXT PRIMARY KEY,
    gene_id TEXT NOT NULL,
    chrom TEXT, start INT, end INT,
    cds_id TEXT, pep_id TEXT,
    exon_count INT
);
CREATE INDEX idx_tr_gene ON transcripts(gene_id);

-- 3) GO：term 字典 + 关联（双向查询）
CREATE TABLE go_terms(
    go_id TEXT PRIMARY KEY,      -- GO:0003700
    name TEXT,                   -- DNA-binding transcription factor activity
    aspect TEXT,                 -- F/P/C
    definition TEXT
);
CREATE TABLE go_annotations(
    gene_id TEXT NOT NULL, go_id TEXT NOT NULL,
    evidence TEXT,
    PRIMARY KEY(gene_id, go_id)
);
CREATE INDEX idx_go_term ON go_annotations(go_id);

-- 4) KEGG：KO 字典 + pathway 字典 + 关联
CREATE TABLE kegg_kos(ko_id TEXT PRIMARY KEY, name TEXT, definition TEXT);
CREATE TABLE kegg_pathways(pathway_id TEXT PRIMARY KEY, name TEXT);
CREATE TABLE kegg_annotations(
    gene_id TEXT NOT NULL, ko_id TEXT, pathway_id TEXT,
    PRIMARY KEY(gene_id, ko_id, pathway_id)
);
CREATE INDEX idx_kegg_ko ON kegg_annotations(ko_id);
CREATE INDEX idx_kegg_pw ON kegg_annotations(pathway_id);

-- 5) 版本映射（替代/等价于 TSV，入库后双向可查）
CREATE TABLE id_mapping(
    source_id TEXT NOT NULL, target_id TEXT NOT NULL,
    target_genome TEXT NOT NULL,
    PRIMARY KEY(source_id, target_genome)
);
CREATE INDEX idx_map_target ON id_mapping(target_id);

-- 6) 构建元信息（API 汇报真实 buildStatus 用）
CREATE TABLE meta(key TEXT PRIMARY KEY, value TEXT);
-- 例：built_at=..., source_gff3_md5=..., build_status=ready, gene_count=27655
```

**查询逻辑要点**：

- `gene_id` 搜索用 `LIKE '%q%'`（FTS5 的 unicode61 分词会把 `AT1G01010` 的点/数字切碎，ID 类查询 LIKE 更稳）；`gene_name`/`annotation` 用 FTS5 `MATCH`（前缀 `q*`），失败回退 LIKE。
- "GO 反查基因"：`SELECT gene_id FROM go_annotations WHERE go_id=?` 或 join `go_terms.name LIKE`；KEGG 同理。
- 统一搜索（§5.6）= 三类查询并行执行（asyncio.to_thread），各取 top N 聚合返回。

### 4.3 序列的存储与读取

- **基因组序列**：FASTA 必须解压为普通文本（`gunzip`，构建步骤之一），`samtools faidx` 或 indexer 内置逻辑生成 `.fai`。`sequence.py` 实现纯 Python faidx 读取器（~60 行：解析 `.fai` 的 `name/length/offset/linebases/linewidth`，按坐标 seek 读取，支持反向互补）——**不引入 pysam/pyfaidx 依赖**。
- **CDS/蛋白序列**：TAIR10 这类已按转录本拆好的 FASTA，构建时把 `>id` 与文件偏移记入 `transcripts`（或单独 `seq_kv` 表存全序列，TAIR10 约 3.5 万条、几十 MB，可接受）；生菜等无此文件的物种返回 `available: false`。
- 基因 genomic 序列 = `chrom:start-end` + 链向修正（负链反向互补）。

## 5. API 设计

前缀 `/api/v1/reference-genomes`，全部 `Depends(get_current_user)`；OpenAPI 文档自动见 `/docs`。在蓝图 10 个端点基础上扩展（★ 为新增）：

### 5.1 物种/版本（替换卡片数据源）

```
GET /species                          → 物种卡片列表（含各版本、files 审计状态 ready/missing/building、stats）
GET /species/{species_id}             → 物种详情 + 全部版本
GET /versions/{version_id}            → 版本详情（染色体数组、基因类型统计、文件清单）
```

响应字段与前端 mock 类型一一对应（snake_case 定义、alias 输出 camelCase，照蓝图 §五）。

### 5.2 基因搜索（核心）

```
GET /versions/{version_id}/genes?field=gene_id|gene_name|annotation|go|kegg
    &q=MYB&chromosome=Chr1&page=1&page_size=20
```

- `field=go`：`q` 为 GO ID（精确）或 term 名（模糊）→ 反查基因列表；
- `field=kegg`：`q` 为 KO/pathway ID 或名 → 反查基因列表；
- 响应 `{total, items[Gene...]}`，Gene 含 `hasGo/hasKegg/hasSequence` 布尔位供前端标灰。

### 5.3 基因详情（基因抽屉数据源）

```
GET /versions/{version_id}/genes/{gene_id}
```

一次返回聚合结构（前端抽屉五个 Tab 各取一段，避免五个请求）：

```json
{ "data": {
    "gene": { "geneId": "AT1G01010", "geneName": "NAC001", "chromosome": "Chr1",
              "start": 3631, "end": 5899, "strand": "+", "length": 2269,
              "annotation": "NAC domain protein", "exons": 3 },
    "transcripts": [{ "transcriptId": "AT1G01010.1", "exonCount": 3,
                      "exonRanges": [[3631, 3995]] }],
    "go": [{ "goId": "GO:0003700", "name": "...", "aspect": "F", "evidence": "ISS" }],
    "kegg": { "kos": [{ "koId": "K01126", "name": "..." }],
              "pathways": [{ "pathwayId": "ath04075", "name": "..." }] },
    "sequenceAvailable": { "genomic": true, "cds": true, "protein": true }
} }
```

### 5.4 序列 API ★

```
GET /versions/{version_id}/genes/{gene_id}/sequence?type=genomic|cds|protein&format=fasta|json
GET /versions/{version_id}/sequence?chrom=Chr1&start=1000&end=2000&strand=-&format=fasta|json
```

- `format=fasta` 返回 `text/plain` FASTA；`json` 返回 `{header, sequence, length}`；
- 无对应文件的物种 → `404 {reason: "sequence file not registered"}`；
- 区间上限 1 Mb（防滥用），超限 400。

### 5.5 GO/KEGG 检索 ★

```
GET /versions/{version_id}/go?q=kinase&aspect=F&page=1      → term 列表（含每个 term 的基因数）
GET /versions/{version_id}/kegg/kos?q=                      → KO 列表
GET /versions/{version_id}/kegg/pathways?q=                 → pathway 列表（含基因数）
GET /versions/{version_id}/go/{go_id}/genes                 → 该 term 下基因（分页）
GET /versions/{version_id}/kegg/pathways/{pw_id}/genes      → 同上
```

前端 GO/KEGG Tab 用前三个做浏览，点条目用基因搜索/反查接口联动。

### 5.6 统一搜索（页面搜索框 + 对外搜索接口）★

```
GET /versions/{version_id}/search?q=MYB&limit=10
GET /search?q=MYB&species=arabidopsis&limit=10     ← 跨版本/跨物种（页面顶部搜索框）
```

响应聚合三类：

```json
{ "data": {
    "genes":    [{ "geneId": "...", "geneName": "...", "versionId": "tair10", "speciesId": "arabidopsis" }],
    "goTerms":  [{ "goId": "...", "name": "...", "geneCount": 12 }],
    "kegg":     [{ "id": "...", "kind": "ko|pathway", "name": "...", "geneCount": 8 }],
    "species":  [{ "speciesId": "arabidopsis", "commonName": "拟南芥", "match": "common_name" }]
} }
```

页面搜索框命中物种/版本 → 跳卡片；命中基因/GO/KEGG → 跳对应版本详情页并带上定位参数。

### 5.7 批量注释（供 AI 助手/分析工具）★

```
POST /versions/{version_id}/genes/batch
{ "gene_ids": ["AT1G01010", ...] }   # ≤500
→ 每基因返回 annotation + go 数 + kegg 数（不含全量列表，控制体积）
```

### 5.8 版本映射 / 管理（沿用蓝图）

`POST /versions/{version_id}/map-ids`、`POST /versions/{version_id}/set-default`、`POST /reload`（管理员）。

### 5.9 构建管理 ★（P2）

```
POST /versions/{version_id}/build    → 触发 Celery 构建任务（管理员）
GET  /versions/{version_id}/build    → 构建状态/进度（卡片"构建中"的真实来源）
```

## 6. 数据接入与构建管线（indexer.py）

### 6.1 构建命令

```bash
python -m omichub.reference_genomes.indexer build --version tair10          # 单版本全量
python -m omichub.reference_genomes.indexer build --version tair10 --only go
python -m omichub.reference_genomes.indexer audit                            # 全物种文件审计（卡片状态）
```

流程：读 yaml → 按 `files.*.format` 分派解析器 → 写入该版本 `gene_index.db`（先写临时文件再原子替换）→ 写 `meta` 表（built_at / build_status / 各项 ready 状态）。失败只影响该版本，绝不让 API 挂掉（service 读不到 db 时该版本标记 `building/missing`，其余正常）。

### 6.2 解析器清单（每种 format 一个函数，全部纯 Python）

| format | 输入 | 产出表 | 说明 |
|---|---|---|---|
| `gff3` | TAIR10 GFF3 等 | genes、transcripts | 蓝图 §6.1 代码基础上：gene 行取 ID/Name/Note；mRNA/exon 回溯 Parent 链 |
| `gaf` | gene_association.tair.gz（gzip） | go_annotations | GAF 15 列：DB Object ID→gene_id、GO ID、Evidence Code |
| `obo` | go-basic.obo | go_terms | 解析 `[Term]` 段的 id/name/namespace/def |
| `kegg_list` | ath_ko.list / ath_pathway.list | kegg_annotations | 两列 `gene\tko/pathway` |
| `kegg_brite` | ath_brite.txt | kegg_pathways、kegg_kos 名称 | 层级文本，提取 id↔name |
| `fasta_kv` | cds/pep FASTA | transcripts.cds_id/pep_id（+可选 seq_kv） | 只登记 id，序列留文件中 |
| `genomic_fasta` | fas.gz | （解压 + .fai） | `gunzip` 后自建 `.fai`（纯 Python：扫描每行字节偏移） |
| `lettuce_overview` | annotation_overview.tsv | genes、go_annotations、kegg_annotations | 生菜单表多列抽出（列名以实际文件头为准，实现时先 `head` 核实） |
| `itag_annot` | ITAG4.1 blast2go annot | go_annotations + annotation | 番茄 |
| `id_map_tsv` | 两列 TSV | id_mapping | 蓝图 §3.3 |

### 6.3 构建状态真实化

卡片 FA/GFF/GO/KEGG 标签 = `meta` 表对应键 + 文件审计：`ready`（索引已建且文件在）/ `missing`（yaml 未声明或文件缺）/ `building`（构建任务进行中，Celery 任务写 meta）。**替代 mock 的静态 buildStatus**，番茄"构建中"从此是真实状态。

### 6.4 共享资源

`go-basic.obo`、KEGG 层级文件是跨物种通用的：放 `/data/omichub/omichub_data/reference/_shared/`，yaml 里用绝对路径引用，避免每物种重复存。

### 6.5 Celery 化（P2）

照 `src/omichub/tools/jbrowse/tasks.py` 的模式加 `reference_genome_build` 任务：队列复用现有 worker；任务内调 indexer 同一函数；进度写 meta + 任务表，前端卡片轮询 §5.9。

## 10. 验收标准

1. `GET /species` 返回 ≥4 物种，卡片 FA/GFF/GO/KEGG 状态与磁盘/索引真实一致。
2. `GET /versions/tair10/genes?q=MYB&field=annotation` 毫秒级返回；`field=go&q=kinase` 能反查基因。
3. `GET /versions/tair10/genes/AT1G01010` 一次返回基因+转录本+GO+KEGG 聚合。
4. `GET .../sequence?type=genomic` 返回与 `samtools faidx` 一致的序列；负链反向互补正确；无序列文件的物种返回结构化 404。
5. 全局搜索 `GET /search?q=` 同时命中物种/基因/GO/KEGG 四类并正确跳转。
6. 批量注释 500 个 ID 一次往返；OpenAPI `/docs` 可见全部端点。
7. 前端整站无 mock import；构建中的版本卡片显示真实进度；yaml 改动热重载生效。

## 11. 风险与注意事项

1. **FTS5 分词陷阱**：基因 ID 含点号/数字（AT1G01010.1），`MATCH` 会被分词切碎——ID 查询一律 LIKE，全文只用于 name/annotation；实现时两种都写并各配测试。
2. **生菜总表列名未核实**：`lettuce_overview` 解析器动手前先 `head -5` 真实文件核对列名与分隔符，不要凭猜。
3. **gzip FASTA 不能 faidx**：构建必须先解压；磁盘多占一份（TAIR10 ~120MB，可接受），yaml 指向解压后路径。
4. **SQLite 并发**：API 只读连接（`mode=ro`），构建走临时文件 + 原子替换，避免读到半个库。
5. **不引入新依赖**：GFF3/GAF/obo/fai 全部纯 Python 解析（蓝图已定调），容器镜像不用改。
6. **体积控制**：详情聚合接口的 GO/KEGG 列表截断（如各 ≤100 条）+ 批量接口 ≤500 ID；区间序列 ≤1Mb。
7. **配置热重载一致性**：service 每次请求取 config_manager 最新配置；`gene_index.db` 路径相对 data_dir 解析，避免 yaml 改了路径还连旧库。
8. **权限**：查询类登录即可；set-default/reload/build/注册限管理员（照蓝图 §4.9/4.10）。
