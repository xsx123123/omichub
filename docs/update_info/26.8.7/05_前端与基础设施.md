# 05 前端与基础设施

## 前端入口与切换机制(事实)

- 模式 1:`/ai` → `AIChatView.vue` → `AgentWorkspace.vue`(`frontend/src/router/index.ts:110-114`),发送走 `useAgentChatStream` 的 SSE `POST /api/v1/chat/stream`。
- 模式 2:`/studio/:sessionId?` → `StudioView.vue`(`router/index.ts:122-126`),与模式 1 **共用同一个 agentHub store**,靠 `session.mode === 'studio'` + 单独拉取的 `studioSessionIds` 集合区分(`agentHub.ts:147-148`)。路由命中 `default_mode=studio` 的 Agent 时经 `studioRedirect` 自动跳转(`agentHub.ts:129-138`)。
- 模式 3:`TasksView?tab=agent-teams` 列表 → `/agent-teams/cases/:caseId` → `AgentTeamsCaseView.vue`(`router/index.ts:116-120`);或由聊天流内 `agentteams_case` SSE 事件卡片跳转。store `agentTeams.ts` 仅 15 行。
- 三种模式**没有 store 级隔离**;路由守卫统一(`router/index.ts:413-463`),三种模式都只要求登录,AgentTeams 无额外模块门禁(路由可直接访问)。

## 中严重度

### M1. Studio 代码重跑流组件卸载不中断

- 位置:`frontend/src/components/studio/StudioCodeCard.vue:162` 只解构 `{ isRunning, run }`,`abort` 未取出;`onUnmounted`(:310-313)不 abort。切换会话/离开 Studio 时后端沙盒继续执行。
- 修复:`onUnmounted(() => abort())`。

### M2. 切换会话/模式时静默中断正在生成的回复

- 位置:`agentHub.ts:968-969` — `selectSession` 切换即 `stopStreaming()`,无"回复生成中,确认离开?"拦截;后端 token 已消耗,部分内容丢失。
- 修复:切换前若 `isStreaming` 弹确认;或允许后台续流(store 本就是全局单例)。

### M3. chat/studio 模式判定依赖两套数据源,存在不一致窗口

- 位置:`agentHub.ts:147-148` 注释自述:"后端 ChatSessionDTO 无 mode 字段,前端绕道获取"——`/chat/sessions` 与 `/studio/sessions` 两次请求拼出 `studioSessionIds`。若其中一次失败(`fetchStudioSessionIds` 静默 catch,:656),Studio 会话在 /ai 列表无角标、点击不跳转。
- 修复:后端 `ChatSessionDTO` 直接返回 `mode` 字段(模型里本来就有,`models/chat.py:50`),去掉双数据源。

### M4. 指标缓冲写库失败静默丢弃(见共性问题 C7)

### M5. API Key 加密密钥单点、不可轮换(既有审查 F-1/F-2 未修)

- 加密已落地:`ai_provider_repository.py:111,136` 用 `encrypt_value`(Fernet)。但主密钥仍是单一固定配置值,无轮换/版本标记。
- 修复:引入 key_version + 双密钥过渡轮换机制。

## 低严重度

- **L1** 路由守卫以 `localStorage.access_token` 存在性判断登录(`router/index.ts:415`),token 过期未清除时仍视为"已登录",进入页面后 401 才跳登录;`setupChecked`(:7)模块级缓存依赖手动 `resetSetupCheck()`。
- **L2** 临时会话识别依赖 ID 前缀约定(`agentHub.ts:643,1000,1016`),凡 `id.startsWith('sess-')` 即视为未落库临时会话,后端真实 session_id 若以 `sess-` 开头会被误判。建议显式标志位。
- **L3** 模式切换重复请求:`StudioView.vue:332-333` + `AgentWorkspace` 各自挂载时拉 agents/models/sessions,无 TTL 缓存。
- **L4** 鉴权覆盖方式是"全局中间件兜底 + 端点自觉":`middleware/auth.py:56-122` 全局 JWT + 白名单使无 `CurrentUserId` 的端点实际也要求登录——抽查后**未发现漏鉴权端点**(studio internal 有 HMAC 控制令牌)。风险在于新增路由误配白名单前缀即裸奔,建议对白名单加注释级契约或测试快照。
