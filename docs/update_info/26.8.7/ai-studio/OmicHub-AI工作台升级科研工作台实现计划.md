# OmicHub AI 工作台升级「科研智能实验工作台」实现计划

> 版本：v1.0（2026-08-07）
> 范围：AI 工作台页面整体 UI 架构与视觉语言升级（展示层重构 + 后续状态数据接入）
> 前置：本计划基于用户优化方案的评估修订版，评估结论见第三节

---

## 一、背景与目标

AI 工作台是 OmicHub 面向生物信息学、多组学分析场景的核心页面。当前问题：

- 整体过于类似 ChatGPT 聊天页，Agent 能力不突出
- 工具调用以 `ask_user MCP: studio` 形式直出，像开发者日志
- 用户无法感知 AI 正在执行科研任务，缺少分析流程、任务状态、结果管理感

**目标**：升级为 "Scientific AI Research Workspace"——用户不是在聊天，而是在与多个科研 Agent 协作完成分析任务。保持现有功能逻辑，仅优化 UI 架构、视觉语言与交互体验。

## 二、方案评估结论（2026-08-07 会话）

用户方案整体方向正确，与业界主流约定一致：

| 方案要点 | 业界锚点 |
|---|---|
| 聊天页 → 任务/Agent 工作台 | AI 产品从"聊天回复"转向"执行系统"的普遍趋势（Copilot 专用 Agent、Anaxa 研究工作台） |
| 工具调用改为事件卡 + 技术详情折叠 | DeepSeek Reasonix 工具详略三级设置、OpenClaw 默认折叠工具调用 |
| 弱化模型名、突出 Agent 身份 | GitHub Copilot（Explore/Task/Plan Agent）、Claude Code、Codex 的 Agent 叙事 |
| 左侧任务中心 + 右侧结果面板 | PromptBio QAgent 任务一等公民、Anaxa ResearchQuest 阶段状态机 |
| 具体 hex/圆角/动效数值 | 符合可执行 spec 要求 |

**评估中修正的 3 个细节（已并入本计划）：**

1. **分层实施**：方案混合了"纯展示层改动"与"依赖后端任务状态数据的改动"。拆为两个阶段，阶段一只做展示层，状态用前端可推断信息；阶段二再接真实任务状态流，避免"假状态"。
2. **Pipeline 不硬编码**：Workflow Pipeline 与 Agent Planning 合并为"计划即管线"——由计划步骤数组驱动渲染，不为 RNA-seq 或任何组学写死流程节点。
3. **三处冲突修正**：
   - 删除"粒子聚合形成 Agent 卡片"动效（与"避免复杂动画"自相矛盾），保留节点点亮、结果区入场微动效；
   - 文案统一为"中文主标题 + 英文小标签"，不大面积使用英文标题（平台现有界面为全中文）；
   - 输入区按钮改名必须保留"旧功能 → 新入口"映射表，不得丢失附件/文件/联网/终端/工具/深度思考的真实功能。

## 三、信息架构总览

```
┌─────────────┬──────────────────────────┬─────────────┐
│ 分析任务中心  │      Agent 执行流          │ 研究结果面板  │
│ (原会话列表)  │  · 任务理解卡             │ (原结果产物)  │
│  任务卡片×N  │  · Agent 身份(主)/模型(副) │  产物分组列表 │
│  状态指示灯   │  · 计划时间线(计划即管线)   │  预览/下载/打开│
│             │  · Agent 事件卡(工具调用)   │  新产物动效   │
│             │  · 对话内容                │             │
│             ├──────────────────────────┤  沙盒状态     │
│             │  Scientific Task Composer │  (保留)      │
│             │  (输入区, 功能映射不变)     │             │
└─────────────┴──────────────────────────┴─────────────┘
```

技术栈锚点：Vue3 + Pinia + SSE 流式渲染（与平台现有工作台一致）。

## 四、阶段一：展示层重构（本期执行）

**原则**：不改路由、不改 SSE 消息流逻辑、不改工具调用数据结构；所有状态由前端从现有消息流推断；无数据一律回退到现有样式，禁止空白卡片。

### 4.1 改动清单

| # | 区域 | 现状 | 改为 |
|---|---|---|---|
| 1 | 左栏 | 聊天会话标题列表 | 「分析任务」任务卡片：类型图标+任务名+Agent+时间+状态灯（🟢/🔵/🟡） |
| 2 | 中栏顶部 | 模型名为主标识 | Agent 名主标题 + "Powered by 模型名" 12px 灰色副标题 |
| 3 | 中栏 | 用户消息→AI 回复→工具调用 | 任务理解卡 → 计划时间线 → 事件卡 → 回复正文 |
| 4 | 工具调用 | `ask_user MCP: studio` 直出 | Agent 事件卡：图标+中文标题+状态徽标+耗时，技术详情折叠 |
| 5 | 右栏 | 「结果产物 / 暂无产物」 | 「研究结果」：类型分组图标 + 预览/下载/打开 + 新产物入场动画 |
| 6 | 输入区 | 「向智能助手描述分析任务」 | placeholder「告诉星尘你的研究目标…」+ 4 个示例快捷词；六按钮科研语义化重绘（功能不变） |
| 7 | 视觉 | — | 配色/圆角/阴影/动效统一规范（见 4.3） |

### 4.2 工具名 → 科研语言映射表（初版，可持续扩充）

| 工具/调用 | 事件卡标题 |
|---|---|
| read_file / 读取文件 | 读取数据文件 |
| write_file / 写文件 | 生成分析结果 |
| shell / 终端执行 | 执行分析命令 |
| mcp: studio（沙盒） | 沙盒分析环境 |
| ask_user | 向用户确认信息 |
| web_search | 检索文献与资料 |
| 未覆盖工具 | 回退显示原始名称 |

### 4.3 视觉规范

- 背景 `#F8FAFC`；主蓝 `#2563EB`；AI 紫 `#8B5CF6`（Agent 身份、进行中态）；生物绿 `#10B981`（成功/完成态）；正文 `#0F172A`
- 卡片圆角 12–16px，柔和阴影（shadow-sm/md），轻玻璃效果仅用于悬浮操作条
- 动画 300–800ms，仅 transform/opacity，尊重 `prefers-reduced-motion`
- 避免：游戏化、赛博朋克、粒子动效、普通聊天气泡样式
- 文案：中文为主，英文仅作小标签（如状态徽标旁 "Running"）

### 4.4 阶段一提示词

> 直接粘贴给编码 Agent（kimi code / Claude Code / CODEX）：

```
请在现有 OmicHub AI 工作台页面（Vue3 + Pinia，三栏布局：左侧工作台会话列表 / 中间对话与工具调用区 / 右侧结果产物与沙盒状态面板）基础上做 UI 架构与视觉语言升级。这是展示层重构，不是重新设计：先读现有代码再动手，禁止改动路由、SSE 消息流逻辑、工具调用数据结构和无关组件。

【目标】把页面从"类 ChatGPT 聊天页"升级为"科研智能实验工作台"：左侧 = 分析任务中心，中间 = Agent 执行流，右侧 = 研究结果面板。

一、左侧：会话列表 → 分析任务中心
- 区域标题改为「分析任务」；会话条目重绘为任务卡片：任务类型图标（按标题关键词推断，🧬转录组/🔬单细胞/📊通用）+ 任务名 + Agent 名 + 时间 + 状态指示灯（🟢已完成 / 🔵执行中 / 🟡等待输入）。
- 状态本期用现有消息流可推断的信息做前端推断（是否有运行中工具调用、最后一条是否待用户回复），数据结构预留 status 字段，不写死。
- 无元数据的旧会话回退为现有"标题+时间"样式，不得空白或报错。

二、中间：对话流 → Agent 执行流
1. 任务理解卡：用户发送任务后、Agent 首条回复前插入「任务理解」卡片（任务/领域/目标/状态四行）；数据来自 Agent 回复的结构化段落解析，解析失败则不渲染，绝不显示空卡。
2. Agent 身份层级：消息头像旁主标题显示 Agent 名（如「转录组分析专家」），模型名降级为 12px 灰色副标题 "Powered by qwen3.7-plus"。顶栏模型选择器保留，仅作设置入口。
3. 分析计划时间线：Agent 输出的计划步骤渲染为竖向时间线（✓已完成 / ●进行中 / ○待执行），由步骤数组驱动，禁止硬编码任何具体组学流程节点。

三、工具调用 → Agent 事件卡
- 不再直接展示 "ask_user MCP: studio" 这类原始调用名。
- 每张工具卡：类型图标 + 科研语言标题（工具名→中文描述映射表，如 read_file→读取数据文件、mcp studio→沙盒分析环境）+ 状态徽标（执行中/成功/失败）+ 耗时。
- 原始工具名、MCP 来源、参数与返回摘要折叠进「查看技术详情」展开区，默认收起；映射表未覆盖的工具回退显示原名。

四、右侧：结果产物 → 研究结果面板
- 标题改为「研究结果」；产物按类型分组图标（📄表格 / 📈图表 / 📑报告），每项提供 预览 / 下载 / 打开（复用现有文件操作逻辑）。
- 新产物入场动画：opacity 0→1 + translateY 8px→0，400ms ease-out，尊重 prefers-reduced-motion。

五、底部输入区
- placeholder 改为「告诉星尘你的研究目标…」，下方一排示例快捷词（分析这个 RNA-seq 数据 / 注释单细胞亚群 / 预测蛋白功能 / 比较两个物种基因差异），点击填入输入框。
- 现有按钮（附件/文件/联网/终端/工具/深度思考）功能逻辑不变，仅重绘图标与 tooltip 为科研语义：Data(附件) / Sequence(文件) / Agent(智能体) / Analysis(工具) / Workflow(终端) / Reasoning(深度思考)。先列出"旧功能→新入口"对照表再改，逐个确认映射，不得丢功能。

六、视觉规范（全页统一）
- 背景 #F8FAFC；主蓝 #2563EB；AI 紫 #8B5CF6（Agent 身份与进行中态）；生物绿 #10B981（成功/完成态）；正文 #0F172A。
- 卡片圆角 12-16px，柔和阴影，轻玻璃效果仅用于悬浮操作条。
- 所有状态动画 300-800ms，只用 transform/opacity，尊重 prefers-reduced-motion；不做粒子、赛博朋克效果。
- 文案以中文为主，英文仅作小标签；与平台首页及星尘 AI 品牌视觉保持一致。

【验收】
1. 旧会话正常打开、发消息、SSE 流式渲染无回归。
2. 工具调用全部以事件卡呈现，技术详情可展开收起。
3. 无元数据会话回退正常，无空白卡片。
4. prefers-reduced-motion 下动画全部禁用。
5. 输入区六个按钮功能逐一验证与改版前一致。
```

## 五、阶段二：任务状态与管线数据接入（后续迭代）

**前提**：后端提供结构化任务状态（task_id / status / plan_steps[] / artifacts[]）。阶段一已预留 `status` 字段与回退逻辑，本阶段为数据替换，不再动信息架构。

### 5.1 改动清单

| # | 内容 | 说明 |
|---|---|---|
| 1 | 任务状态真实化 | 左栏状态灯从"前端推断"切换为后端 status（Running/Waiting/Completed/Failed） |
| 2 | 计划即管线 | 后端下发 plan_steps（含每步 status），前端时间线直接渲染；完成阶段一"推断→真实"的切换 |
| 3 | 任务理解卡结构化 | 后端在任务创建时返回 task_meta（领域/目标/输入数据），替代前端解析 |
| 4 | 产物联动 | 结果面板与 artifacts[] 绑定，新产物事件触发入场动画与高亮 |

### 5.2 阶段二提示词（骨架，执行前按后端实际接口补全）

```
在阶段一完成的工作台 UI 基础上，将任务状态从"前端推断"切换为后端真实状态：
1. 左栏任务卡状态灯接入后端 task status 字段（Running/Waiting/Completed/Failed），保留阶段一的推断逻辑作为接口异常时的回退。
2. 中间计划时间线接入后端 plan_steps 数组（每步含 name/status），前端不再自行推断步骤进度；接口未返回 plan_steps 时回退为阶段一行为。
3. 任务理解卡改为读取任务创建时返回的 task_meta（领域/目标/输入数据），不再从回复文本解析。
4. 右侧研究结果面板绑定 artifacts[]，新产物事件触发入场动画与短暂高亮（1.5s）。
约束：不改动阶段一已定稿的信息架构与视觉规范；所有后端字段缺失时必须有回退，禁止空白或报错。
验收：断网/接口异常场景下页面行为与阶段一一致；正常场景下状态与后端一致。
```

## 六、风险与回退

| 风险 | 等级 | 对策 |
|---|---|---|
| 阶段一状态推断不准（如"等待输入"误判） | 中 | 推断逻辑保守化：不确定时一律不显示状态灯；阶段二接真实状态后彻底解决 |
| 任务理解卡解析失败率高 | 中 | 解析失败不渲染该卡（已写入提示词）；阶段二改结构化下发后解决 |
| 输入区按钮改名后用户找不到原功能 | 低 | tooltip 保留原功能说明（如 "Reasoning · 深度思考"）；对照表逐一验证 |
| 视觉规范与平台其他页面不一致 | 低 | 提示词已带"与平台首页及星尘 AI 品牌视觉保持一致"约束；验收时对照首页截图 |
| 会话列表重构引入渲染回归 | 中 | 验收 Checklist 第 1、10 项兜底；回退方案：git 还原左栏组件，其余改动不受影响（改动按区域解耦） |

## 七、实施顺序建议

1. **阶段一**（本文档 4.4 提示词，单次或按"左栏→中栏→右栏+输入区"拆两轮执行）
2. 阶段一验收通过后，视后端排期启动**阶段二**
3. 阶段二执行前，需先与后端确认 task status / plan_steps / artifacts 接口字段，再补全 5.2 提示词骨架
